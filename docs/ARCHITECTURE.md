# ARCHITECTURE｜当前系统结构

> 当前结构摘要，按需再进入源码。设计缘由和故障取舍见 [归档索引](archive/INDEX.md)；长期约束见 [LESSONS](LESSONS.md)。

## 系统边界

SoloChat 是单机 Android 聊天应用。`:core` 是纯 Kotlin/JVM 领域与协议层，不依赖 Android；`:app` 提供 Compose、Room、网络适配、设置和应用生命周期。依赖方向只能是 `app → core`。API Key 和网页密码保存在本机加密存储；没有 SoloChat 云端服务。

- `core`: 会话/消息模型、模型协议解析、提示词与上下文规划、调用编排接口、事件播放计划、价格快照、备份数据协议。
- `app`: Room/DataStore/SecretStore、OpenAI 兼容客户端、调用适配、会话控制器、导航与 UI、内嵌日志和测试网关、备份/更新功能。
- Room 当前版本为 10；迁移定义在 `app/.../data/db/Migrations.kt`，schema 导出在 `app/schemas/`。

## 一轮生成与播出

1. `ChatScreen` 订阅应用级 `SessionRegistry` 中该会话唯一的 `SessionController`。
2. 控制器接收 AUTO/MANUAL 输入；AUTO 防抖后认领并保存推送消息，MANUAL 输入保存为尚未推送的消息。
3. `AgentTurnRunner` 经 `ContextPlanner` 取得当前有效模型、人设、记忆、已推送消息和已出口事件，交由 `PromptBuilder` 构建请求；一次调用返回事件脚本。
4. 事件先以 PENDING 落库并完成调用记账，然后播放器逐条播出。每条播出结束写入事件交付状态和助手上下文消息，再刷新 UI。
5. Room 时间轴查询按来源与稳定游标分页；`ChatProjector` 将可见记录投影为界面项目。当前会话及全局搜索共用完整库候选查询，再经相同映射与时间轴可见性规则过滤，按会话与来源键保留分页结果，不重载聊天窗口。全局候选联结当前会话/人物元数据，含归档会话，人物缺失时标为待确认；每批正文按候选 ID 有界读取。

生成和播出解耦。会话控制器由应用按会话唯一持有；离开页面不停止当前回合。同一会话的发送、模式/模型/人物配置操作须共用串行化边界。

## 历史读取与定位

| 路径 | 查询与窗口 | 与运行中会话的关系 |
|---|---|---|
| 聊天时间轴 | 最近 80 条，可向前分页 | 由 SessionController 持有，按出口事件刷新 |
| 当前会话/全局搜索 | 完整库候选，每页最多 40 条 | 独立只读结果，不改变已加载聊天窗口 |
| 点击搜索结果 | 来源类型+ID 精确查目标，前后各 20 条；两侧按页扩展 | HistoryContextState 独立持有，不获取 SessionRegistry，不逐页接到最新 |
| 定位页返回最新 | 读取该会话最近 80 条可见记录 | 仍是只读历史，不自动进入聊天或推送代发 |

定位沿用时间轴可见性，目标已删除或不再可见时提示并保留返回搜索/最新的路径。数据库变化只检查最新位置及目标有效性，不替换正在阅读的前后文；新内容提示由用户点击后加载。搜索层留在组合中，返回时保留查询、已加载结果与滚动位置；当前聊天的输入草稿仍由原输入区持有。

主要入口为 `core/.../model/TimelineContext.kt`、`StoragePort.timelineContext`、`RoomStore`、`ui/chat/HistoryContextState.kt` 与 `HistoryContextScreen.kt`。纯 Kotlin 来源键不直接用作 Compose 列表 key，UI 转成可保存在 Android Bundle 中的来源字符串。

## 首页与人物会话列表

`ui/conversations/ConversationPreview` 从 `timelinePage(limit=1)` 的最近可见记录派生文本、来源键、活动时间及用户代发状态，复用 `historySearchHit` 解码，预览折叠换行而不改原文。人物行取未归档会话的最新活动，包含零会话人物及原有“待确认人物”组；会话置顶优先，其余按可见活动排序，管理用 `updatedAt` 不参与活动顺序。没有额外汇总表或 Room 迁移。

页面观察 persona/conversation/message/event 的 Room 失效通知，合并后后台顺序读取，collectLatest 与代次阻止旧结果覆盖新状态；awaitClose 移除观察器，首页和人物列表分别保留滚动状态。列表读取不获取 `SessionRegistry` 或触发推送。首页“+”经人物选择面板新建明确归属会话，人物页“+”直接新建；底部操作面板复用改名/删除并通过既有 pinned 字段置顶。用户已取消更换人物，当前缺失归属不自动修复。

NavHost 生命周期内持有 `ConversationListSnapshot` 展示快照；聊天返回时立即复用人物、会话和预览，避免首次刷新前闪空首页。选中人物保留必要显示状态，初次读取完成后才判断真正失效的分组；快照不替代 Room，不持有控制器或新增持久化。

## 可见性与中断

事件状态按 PENDING → PLAYING → DELIVERED 推进。播出中断时当前条可标记 INTERRUPTED，尚未播出的条取消。只有 DELIVERED 与 INTERRUPTED 属于 spoken，可进入聊天时间轴和后续模型上下文；PENDING/PLAYING/CANCELED 不代表角色已经说出。助手事件播出后另写为消息供模型上下文使用，时间轴避免重复显示副本。

## 上下文、记忆与记账

- 用户消息仅在明确推送后进入模型上下文；手动代发保持未推送状态。
- system 稳定前缀由安全规则、人设、协议和静态风格组成；每轮变动信息位于动态区。已应用的上下文修订以版本指针启用，聊天显示仍保留原历史。
- `call_record` 保存逐字段用量及开始时价格快照。复杂时段在调用开始求值，各输入档的当时价格放入 ModelPrice.frozenTiers；收尾和统计只用返回输入量从该快照选档，绝不查今天的价格表。旧字段缺失默认空阶梯，旧费用口径保持兼容。未知值不补造为零，费用为估算口径。
- 人物记忆归属人物卡；会话必须明确绑定有效人物 ID，缺失时阻止生成，不静默改归属。普通会话不提供更换人物入口；恢复修复只作用于仍暂停且原人物归属缺失的备份副本。

## 持久化与备份

Room v11 在 v10 基础上只追加表情收藏、消息用途/事件快照、调用图片类型清单及 P4 合成测试归属表；v10 历史行不重写。原图以内容摘要存放在应用私有文件目录，缩略图和发送变体放在可重建缓存。图片只支持静态 JPEG/PNG/WebP，导入限制 32 MiB 与 4000 万像素。一次明确提交最多 4 图，稳定 submission ID 原子保存消息/附件与对应草稿清理；表情单独成为空正文用户消息，使用既有会话控制器和 AUTO/MANUAL 批次边界。

视觉能力沿用当前聊天模型，可靠官方声明优先、手动确认兜底。请求准备冻结图文、模型与价格；原件身份和发送变体分离，当前变体为最大边 2048 的 JPEG/PNG。新图优先，近期未压缩历史在图片数/体积/像素预算内附入；其余明确保留未附原图标记。压缩只处理文字与可靠图片标记，附件感知指纹保留旧无图摘要兼容；含图缺接口总输入用量时保持未知，不从 Base64 估算。

新备份入口写 ZIP v4，严格读取 v1～v4；旧写入路径遇到表情资料时拒绝遗漏。v4 媒体闭包包含消息附件与用户/人物表情关系所需原件，并传递消息用途、收藏状态及类型化调用图片来源。Room 一致快照导出原件闭包，文件按摘要流式校验；恢复先校验原图并提升到私有目录，再单事务发布副本/引用/暂停标记。确认后的 importId 与源 ZIP 保存在私有续接记录，重建先查已提交结果，未提交才重建暂存；清理失败与恢复失败分别处理。详细契约见 [备份专题](reference/07-backup-format.md)。当前 P4-A 仍有待复核与未运行路径，见 HANDOFF。

提供商、模型稳定 ID、用途选择与思考能力保存在 DataStore 的 v2 非秘密文档；升级通过冻结计划、Room 追加关联、最后发布 READY 完成。旧偏好在迁移前保留为源，READY 后正式聊天/压缩只从 v2 解析，不回退旧接口组。会话选择写入 Room v10 的 `conversation_model_binding`；`call_record` 首写与非秘密 `call_config_snapshot` 同事务完成。未确认或失效选择阻止调用，不静默改用旧模型。

新增 provider/model 使用带类型前缀的 UUID，删除后重建不复用身份；升级保留原身份和槽位。新增提供商发布时重新分配独立 Key 槽位，不信任草稿 keyId，未填写/清空保持缺失。连接测试和获取模型仅使用明确待保存的 Key，或同一已持久化提供商的可信槽位，不按新草稿探读历史凭据。

提供商只保存密钥槽位 ID，Key 留在 SecretStore 加密文件；备份不含 Key。替换既有 Key 时先写新槽位，再由 READY v2 文档发布新槽位 ID；失败保留旧槽位，系统不清理未引用槽位。配置编辑与调用准备共用应用级 `configMutex`，会话绑定和预检再串行于会话锁。一次请求使用同一 PreparedAgentCall 的地址、Key、模型 ID、思考参数、价格规则和非秘密快照；聊天预检在认领待发消息前完成，配置变化不改在途请求。压缩独立使用 COMPRESSION 选择、思考固定 OFF；多段压缩冻结连接与价格规则，各次调用按实际开始时间冻结对应时段价格。统计明细按 callId 读取历史思考快照，旧调用缺快照时标为未记录，不从当前配置补历史。

旧偏好和 Key 槽位只作为可恢复升级源保留；不再维护第二套长期运行配置。升级错误由启动门禁显示并允许重试，未 READY 时聊天、设置和压缩不可进入。备份导入继续按 v1/v2 兼容规则重映射到副本，模型关联变为待确认，副本保持暂停；明确选择本机人物与模型并通过调用预检后才解除暂停。

设置首页分为“聊天”（模型选择、回复节奏、聊天行为）与“服务配置”（提供商与模型、模型价格）；旧“当前接口”和“接口与模型”入口移除。A-8/9 草稿在 A-10 后持久化到 READY v2；保存失败保留草稿并提示，取消不写入。Key 草稿只在内存，模型目录和连通测试复用现有 OpenAI 兼容客户端并显式使用所选提供商草稿地址/Key。

接口新建模板限 DeepSeek 官方、阿里云百炼、自定义，仅预填地址；不生成模型或价格、不重分类既有组。独立价格页直接展示模型项，表管理入口可新建/切换/导入/导出；简单表 v1、复杂规则表 v2 均可读。`PriceTableTransfer` 在 core 校验版本、币种、单位、显式单价与已有价格约束；导入生成新表 ID，只追加当前组草稿，页面保存后才发布。SAF 文件读写在 app 层，交换文件不包含组 ID/地址/Key。参考资料由独立的 ReferencePrices 提供，只读分渠道展示日期、来源与适用条件；可表达条目须明确复制，R4 支持多时段/星期/日期例外与输入阶梯，复制后仍须明确配置启用；日历需核对确认。旧 initialCatalog 与 assets 保留兼容，价格解析器不读取新参考资料，已有旧表保留兼容；不变更 Room 或历史账目。格式见 [价格表专题](reference/price-table-format.md)。

Room 负责会话、事件、消息、人物、记忆、调用、上下文修订及备份导入来源。v8→v9 只追加绑定和调用配置快照表，旧业务行不重写；备份通过版本化 ZIP 导出并以副本方式事务导入。密钥、日志和临时凭据不随备份。详细格式与恢复语义见 [备份专题](reference/07-backup-format.md)。

## 运行时服务

应用内 Ktor 服务目前用于日志网页和测试网关；它不等于正式 LAN 聊天网页。测试命令只有在复用同一个 SessionRegistry/控制器入口时才与 UI 等价。更新功能手动查询公开发行信息、下载固定 APK 并在安装前检查包身份；系统确认界面返回不证明已安装。

## P4 当前实施边界

2026-10-27 用户确认全局用户收藏与人物独立收藏双库；共享 P3 MediaAsset，独立收藏身份/生命周期。用户添加只写全局收藏，点击表情才创建真实消息并进入既有 AUTO/MANUAL；AI 不能浏览用户库，只能对本轮已推送的表情来源提出可校验收藏/维护操作。人物库逐字段锁/版本与移出代次在存储事务中校验。助手表情将使用独立事件载荷、发送时快照及按 eventId 的幂等出口事务，历史不依赖当前收藏元数据。

P4-A 首轮已实现 Room v11/ZIP v4、基础收藏关系、用户表情发送、基础恢复及专用测试入口。AI 收藏维护与 AI 表情事件播放仍未接入（P4-B/C 未放行）；人物库 UI、接口运行和设备行为也尚未验收。具体实现与边界见 [P4 任务书](reference/p4-implementation.md) 及 [HANDOFF](HANDOFF.md)。
