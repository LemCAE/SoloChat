# 日志与调试接口

## 文件日志

出问题时**先看日志**，别猜。三个入口：会话列表右上角菜单 → 日志、设置 → 应用 → 排查与日志 → 文件日志、出错卡片的「看日志」。

日志记录每次请求的**完整提示词、模型原始输出、解析结果、播出时间线**，按 tag 与级别过滤，
长内容可展开、可复制全部。版本号显示在标题栏。

日志同时保留内存显示与应用私有目录中的轮转文件，文件总量最多约 8 MiB，可跨重启导出。
“清空”只清内存显示，不删除文件；关闭“记完整正文”只影响后续正文记录，不清除已有内容。

### 在电脑上看（日志网页）

手机上翻日志很麻烦，所以可以把日志开成一个网页：

设置 → 应用 → 排查与日志 → 日志网页 → **开启日志网页**并保存，然后把显示的地址复制到电脑浏览器。

| 模式 | 监听 | 需要密码 | 怎么访问 |
|---|---|---|---|
| 默认 | `127.0.0.1` | 否 | 手机自带浏览器打开；或电脑上 `adb forward tcp:8787 tcp:8787` 后访问 |
| 允许局域网 | `0.0.0.0` | **必须设** | 电脑浏览器打开 `http://<手机IP>:8787/?t=<密码>` |

> ⚠️ 日志里有你与对方的**完整对话内容**。所以默认只监听本机、默认关闭；
> 要开局域网就**必须**设访问密码，否则保存会被拒绝。用完就关掉。

也可以直接用命令行拉：

```powershell
curl "http://127.0.0.1:8787/api/logs?t=<密码>"
curl "http://127.0.0.1:8787/api/health"          # 探活
```

当前没有“常驻服务”的设置入口，息屏或进入后台后的连接持续性未获保证；使用日志网页时先保持 App 在前台。

### 与界面同步的调试接口

设置中启用日志网页后，可以直接向已有会话发送命令。接口与聊天页复用应用级 `SessionController`：手动模式仍需“发送→推送”，自动模式仍走防抖；插话、模式切换、播出和落盘也走同一条路径。手机可随时打开目标会话观察，返回首页或打开其他会话不会取消生成/播出。此保证限于进程存活期间，不承诺系统杀进程后自动续播。

本机可通过 `adb forward tcp:8787 tcp:8787` 访问；局域网访问沿用日志网页密码。开发测试只用独立 TEST- 人物及会话，示例不会创建、删除或清空资料：

```powershell
# 查询 id 可用原有 /api/conversations，也可从日志查看；必须明确目标。
pwsh tools/ui-command.ps1 -ConversationId <会话id>
pwsh tools/ui-command.ps1 -ConversationId <会话id> -Action send -Text "测试收到请回复收到" -RequestId test-send-1
pwsh tools/ui-command.ps1 -ConversationId <会话id> -Action push -RequestId test-push-1
# 直接改变会话模式，再发起一次模型开场；相同模式不会重复调用。
pwsh tools/ui-command.ps1 -ConversationId <会话id> -Action mode -Mode scene -RequestId test-mode-1
```

`GET /api/ui/state?id=…` 返回同一控制器的模式、阶段、历史、待推送数、正在播出的正文与错误。`POST /api/ui/command` JSON 字段为 `conversationId`、`requestId`、`action`，附 `text` 或 `mode`；`send` 还可用 `pieces: [{"kind":"say","text":"…"},{"kind":"act","text":"…"}]` 组合面对面输入。响应表示命令已交给控制器，完成情况需再读 state；不会阻塞等待模型和整场播出。同一进程最近 128 个 `(conversationId, requestId)` 重试不重复执行，改动内容须换编号；重启后不保留这份去重记录。导入副本仍须先在手机确认恢复发送。

聊天输入 `/scene`、`/chat`，或 `/system 进入面对面模式` / `/system 切换到聊天模式` 会直接切换并让对方开场。普通 `/system …` 仍只记录事实供下一轮读取，不立即调用模型。测试人物模板在 `tools/TEST-UI-persona.json`；先导入或填入独立人物卡，再选给测试会话，不应用于日常人物。

### 旧执行器测试接口

下述 `/api/send` 直接运行执行器，**不包含 UI 的代发、防抖与真实播出**，仅保留给协议/提示词排查；验证交互请优先使用上面的 `/api/ui/command`，不要把两条写入路径同时用于同一会话。



同一个端口上还有几个接口，可以直接发消息并看待回的**原始输出**。排查"为什么回这个"
时比截图快得多：

```powershell
# 发一条并等这一轮跑完（默认新建专用测试会话，不删除已有资料）
curl -X POST "http://127.0.0.1:8787/api/send" -d "在干嘛" `
     -H "Content-Type: text/plain; charset=utf-8"

# 接着上一个会话继续发（?id= 从上面返回的 conversationId 拿）
curl -X POST "http://127.0.0.1:8787/api/send?id=<会话id>" -d "假期要没了"

# 看历史（和界面同一套投影，所以能用来判断"是引擎顺序错还是界面渲染错"）
curl "http://127.0.0.1:8787/api/history?id=<会话id>&limit=30"

# 看**消息表**（装配上下文读的就是它，不是上面那个投影）
curl "http://127.0.0.1:8787/api/messages?id=<会话id>&limit=100"

# 列出会话
curl "http://127.0.0.1:8787/api/conversations"
```

`/api/send` 的返回里同时有：**模型原始输出**、解析出的事件（含顺序与 `gap_hint`）、
实际会发出的气泡、以及这一轮的 token 与成本。这样"输入 X → 输出 Y"在一个响应里就完整了。

> **`/api/history` 与 `/api/messages` 为什么都要有。**
> 前者是"界面上该看到什么"（事件 + 消息的投影），后者是"模型能看到什么"（消息表）。
> 两者会分叉，而且分叉时**前者看起来完全正常** —— 曾经有一个 bug 就是这样：
> 助手说的话在时间轴上一条不少，但消息表里根本没有它们，于是模型看不到自己说过什么，
> 会把自己上一轮答过的内容重新答一遍（用户原话："它又重新回答了一遍我在睡觉"）。
> 排查这类问题只能看 `/api/messages`，以及日志里那行 `历史构成: 对方 N 条 / 我 M 条`
> —— **`我` 是 0 就说明模型这一轮看不到自己的任何发言。**

> 这些接口返回的是对话内容，所以和 `/api/logs` **共用同一道密码**。
> 只监听本机时不需要密码。


## 实机检查范围

2026-10-23 H2 后，`/api/ui/state` 的 `items` 表示手机控制器当前已加载的历史窗口，默认最近 80 条；上翻加载会扩大窗口，返回最新收回一页。不要将它当完整数据库历史，也不要将旧 `/api/history` 的截取路径当作分页界面的等价验收。

界面、键盘、滚动等问题使用本次连接的设备检查；对话交互仅操作独立 TEST- 人物与会话。状态读取不调用模型，send/push/mode 可能产生模型用量，须按实际需要与授权执行。截图、录屏的可用性以当前设备为准，不沿用旧设备限制。历史播出排查方法见 [交接文档](../LESSONS.md#5-真机取证这台机器上能做什么不能做什么)。
