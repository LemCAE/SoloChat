# 人物卡文件：JSON 格式与生成指南

给两种人看：

- **你**：想把一张现成的人物卡（自己写的、模型写的、别人给的）导进 App。
- **你的模型**：直接把 [第 5 节](#5-给模型的提示词可直接复制) 那段提示词复制过去，让它按格式写一份。

导入入口：**人物卡页 → 右上角菜单 → 导入文档…**。
编辑一张已有卡时，也可以从**编辑页右上角「导入」**把文件内容填进这张卡（不会直接保存）。
另外，人物卡页菜单里的 **格式说明与模板** 就是同一套东西的简版，可以一键复制模板。

**文件格式是 JSON**（`.json`）。为什么不用 Markdown：键名与字段一一对应，不用猜；
空字段也写出来，于是**文件自己就是文档**（贴给模型看，它一眼就知道有哪些字段）。
Markdown **仍然读得进来**（见 [第 4 节](#4-兼容旧的-markdown-文件)），但那是给老文件的退路，不是格式。

图片头像可在人物卡编辑页选择，选入草稿后仍需保存。App 生成居中方形缩略图并保存于本机；文字/emoji 继续可用。本机图片在 `avatar` 中保存 `solochat-avatar:<UUID>` 引用，JSON 往返保留引用，但不携带图片内容；跨设备或文件缺失时显示名字首字，可重新选图。模型生成的人物卡仍建议填 emoji，不生成本机引用。当前尚未提供图片 URL 或手动裁剪位置。

## 1. 它最后会进到哪里（八段，而且**按模式注入**）

一张人物卡有八个正文字段。它们进的是提示词里**不同的段落**，而且**不是每段在两种模式下都出现**：

| 键 | 进提示词的哪一段 | 决定什么 | 发消息 | 面对面 |
|---|---|---|---|---|
| `identity` | 人物设定（仅次于安全规则） | 它是谁、长什么样、跟你的关系 | ✅ | ✅ |
| `voice` | 文风约束（打字时） | 口头禅、句长、标点习惯 | ✅ | ✅ |
| `sceneVoice` | 当面说话的习惯 | 当面和打字的差别 | — | ✅ |
| `mannerisms` | 动作库 | 它常做的小动作、神态 | ✅ | ✅ |
| `surroundings` | 景物素材 | 它待的地方：光、声、气味、东西 | — | ✅ |
| `depiction` | 描写笔法 | **这些素材该写成什么样** | — | ✅ |
| `boundaries` | 边界约束 | 称呼、亲密程度、哪些不做 | ✅ | ✅ |
| `secretNotes` | 里设定（明确要求"不要直接说出来"） | 它心里知道、但不往外说的事 | ✅ | ✅ |

**为什么后四列不一样**：`sceneVoice` / `surroundings` / `depiction` 是**面对面专用的**。
在发消息模式里给模型一堆环境、笔法和"当面怎么说"的素材，它就会开始写小作文 ——
而"像在发微信"恰恰要求它别这么做。
反过来，面对面模式的表达手段只有 `act`（动作）和 `scene`（环境）：**没有素材，模型只能每轮
自己发明一个动作**；**没有笔法，它就会用同一种腔调描写所有人**。

三段的关系值得单独说清：

- `mannerisms` / `surroundings` 管**写什么**（素材）
- `depiction` 管**写成什么样**（笔法）
- 全局的 `20-style-scene.txt` 管**不许写成什么样**（反模式：不写内心独白、不堆排比、不写成小说）

`mannerisms` 两种模式都给：它是**这个人**的属性，不是某个模式专用的。

前几段加上安全规则、协议说明与文风约束，构成请求里的**稳定前缀** —— 前缀逐字节不变时，
模型的 KV 缓存能命中（约 1/10 价）。所以人设是"选定之后就别老改"的东西；改一次，缓存从头再来。

> 这也是为什么人设是**每个对话各自选**的：一段历史只对应一个人，前缀才稳。

## 2. 最小可用文件

```json
{
  "format": "solochat.persona",
  "version": 1,
  "personas": [
    {
      "name": "小默",
      "tagline": "话不多，但一直在",
      "avatar": "🌙",
      "identity": "一个普通人，有工作有作息。和你是熟人，不是刚认识。",
      "voice": "用短句，5~25 个字一条，多数情况一条就够。不说\"专业的\"\"建议你\"这类话。",
      "sceneVoice": "",
      "mannerisms": "",
      "surroundings": "",
      "depiction": "",
      "boundaries": "可以不同意、可以没心情、可以正在忙。",
      "secretNotes": ""
    }
  ]
}
```

- `format` / `version` 是**文件头**：写错了会给一句告警，但仍然尽力读（见第 4 节）。
- `personas` 是数组，**一份文件可以放多张卡**（导入时一起进来）。
- 八个正文键**最少要有一个非空**，否则这张卡会被跳过（会明确告诉你跳过了）。
- 没有的段落写 `""` 就行，导入时按"这一段没写"处理（**不会清空**卡上原有的内容）。
- 名字也可以不写：那样会用**文件名**（`小默.json` → 小默）。

## 3. 八段分别怎么写

### `identity` 你是谁 —— 写事实，别堆性格标签

| | 写法 |
|---|---|
| 好 | 「二十八岁，在城中村租房子，做后端。喜欢老电影，讨厌被安排。你们是大学同学，毕业后一直断断续续联系。偏瘦，头发随手扎起来。」 |
| 差 | 「温柔、善良、聪明、有内涵、神秘感十足。」 |

性格标签模型自己能补；**只有你知道的具体事实**（职业、住处、关系、经历过什么）才是它写不出来的。
年龄和关系尤其重要 —— 它决定了称呼和语气。**外形也写在这里**（面对面时会用到）。

### `voice` 你怎么说话 —— 这一段最值钱

这是八段里唯一"少写一句就明显变差"的部分。写这些：

- **句长**：「默认 5~25 个字一条，最多两条」
- **语气词**：「会用嗯、哦、行、算了；会省略；会只说一个字」
- **标点习惯**：「基本不用感叹号，偶尔用省略号」
- **什么时候沉默**：「不想聊就直接说困了，不硬接话」
- **禁用词**：「不说'绝了''真管用''强烈建议'这类推销腔」

### `sceneVoice` 面对面时怎么说话 —— 当面和打字**真的不一样**

当面时：台词更短、更碎、更容易断在半句；沉默是能被看见的；表达状态主要靠动作，
而不是把情绪说出来。

| | 写法 |
|---|---|
| 好 | 「当面比打字更少话。不习惯说'我很高兴见到你'，会改成'来了''走吧'，或者把水推过去。沉默时不解释，就是安静待着——但不会走开。」 |
| 差 | 「说话很温柔。」 |

留空就只沿用 `voice` 的约束 —— 所以这一段的门槛很低，**写一句就比不写强**。

### `mannerisms` 习惯与小动作 —— 这是 `act` 的动作库

写**紧张 / 高兴 / 心虚的时候分别会做什么**。提示词会要求模型**反复用这几个**，
所以**少而具体**比多而笼统有用得多（三到五条足够）。

| | 写法 |
|---|---|
| 好 | 「想事情时敲桌沿、转笔。尴尬时摸后颈。被说中了会别过脸，过一会儿又转回来。」 |
| 差 | 「有很多小习惯，很可爱。」 |

### `surroundings` 它身边的样子 —— 这是 `scene` 的景物素材

写**具体的东西**：光线、声音、气味、桌上的物件、窗外。不要写"环境很温馨"这种形容词 ——
具体的东西模型编不出来，形容词它自己会编。**一次只借一个**，别一口气全摆出来。

| | 写法 |
|---|---|
| 好 | 「不大的房间，东西不多但整齐。晚上常开一盏桌灯。桌上一只常年凉着的马克杯、一副耳机。窗外是小区，能听见电梯到站的'叮'。」 |
| 差 | 「住的地方很温馨，很有生活气息。」 |

### `depiction` 怎么描写动作与景物 —— 这是**笔法**，不是素材

上面两段回答"写什么"，这一段回答"**写成什么样**"：偏视觉还是偏听觉、句子长短、
用不用比喻、观察距离是冷是近、一句里给几个焦点。

**为什么值得单独一段**：`20-style-scene.txt` 那个全局风格文件管的是**所有角色的底线**
（不写内心独白、不堆排比、不写成小说）。而在那条底线之上，"这个人被描写出来是什么质感"
是人物的一部分 —— 同一条规矩下，有人该是干燥短促的，有人该是黏稠多细节的。
不写这一段，所有人都会被写成同一种腔调。

| | 写法 |
|---|---|
| 好 | 「偏听觉，短句，不用比喻。给的是看得见的东西——手上的动作、光、声音——不解释它们意味着什么。一句里通常只有一个动作或一个焦点。情绪越强，写得越少。」 |
| 好（另一种取向） | 「偏视觉和嗅觉，句子可以长一点。喜欢用生活里的小物件说话（凉了的杯子、绕成一团的耳机线），几乎不写心理。一次只给一个焦点，不铺排。」 |
| 差 | 「描写要优美、有画面感。」 |

同样**留空就只受全局风格约束** —— 门槛很低，写一句取向就比不写强。

### `boundaries` 关系与边界 —— 把红线写清楚

称呼（「叫你老张」「叫你名字，不加姓」）、亲密程度（「不会主动说想你」）、
明确不做的事（「不追问家里的事」「不提打电话/视频」）。
边界写得越具体，越不容易出现"聊着聊着变成了客服"。

### `secretNotes` 只有你知道的事 —— 里设定

它**知道但不会直接说出来**的东西：没说出口的打算、藏着的顾虑、你们之间的一件旧事。
写"没说出口的打算或顾虑"，不要写成剧情大纲。

## 4. 解析器实际认什么

正式格式是上面那套 JSON。以下是为了不让人被格式卡住而留的宽容度：

| 情况 | 表现 |
|---|---|
| 键名写成中文 | 认。`你是谁` / `它是谁` / `身份` / `人设` / `background` / `identity` 等价；`面对面时怎么说话` / `sceneVoice` 等价；`习惯与小动作` / `mannerisms` 等价；`它身边的样子` / `环境` / `景物` / `surroundings` 等价；`怎么描写` / `描写方式` / `旁白风格` / `笔调` / `depiction` 等价。余同。⚠️「环境描写」「景物描写」算**素材**（`surroundings`），不算笔法 |
| 键名用「他 / 她」 | 认（`她身边的样子`、`只有她知道的事`…）。别名表收三种写法只为了认得出别人写的文档，不代表这个 App 假定性别 |
| 顶层写成数组或单个对象 | 认。`[{...}]` 或者直接 `{...}` 都行 |
| 外面包了一层代码块 | 认（`json 围栏会被剥掉） |
| `format` 不是 `solochat.persona` | 给一句告警，仍然尽力读 |
| `version` 比这个 App 认识的新 | 给一句告警（可能有字段读不到），仍然尽力读 |
| 未知的键 | 忽略（模型爱多带 `tags`、`age` 之类） |
| 只有名字、没有正文的条目 | 跳过，并在预览里说明 |
| 写的不是 JSON | 退回按 Markdown 读（见下） |

**认不出来的时候它会明说**，不会悄悄丢内容。导入预览里会列出这类提示：

- 「读到 3 张人物卡。确认后它们会作为新的卡加入，不会覆盖已有的。」
- 「已有同名的卡：小默。导入后会重名，可以在列表里改名。」
- 「JSON 里有 1 条只有名字或完全为空，已跳过」
- 「文件的 format 是「xxx」，不是 solochat.persona —— 按人物卡尽力读了」

### 兼容旧的 Markdown 文件

Markdown 仍然读得进来（这是给老文件、以及"顺手从别处粘一段"留的退路），认得：
`# 名字` 分卡、`## 小节` 分字段、`**加粗**` 单独一行当标题、`键：值` 表单、
整段被 ``` 包住、代码块里的示例不算正文、一份文档多张卡。
但它**不再是格式**：新文件请用 JSON。

## 5. 给模型的提示词（可直接复制）

把下面整段发给你的模型，把 `【…】` 里的内容换成你想要的。

```text
帮我写一张「人物卡」，用来设置一个陪聊 AI 的角色。请严格按下面的 JSON 格式输出，
只输出这一个 JSON，不要解释、不要代码块之外的任何文字。

{
  "format": "solochat.persona",
  "version": 1,
  "personas": [
    {
      "name": "名字",
      "tagline": "一句话介绍（只给我自己看）",
      "avatar": "1 个 emoji",
      "identity": "它是谁：年龄、身份、职业、生活状态、性格、外形，以及和我的关系。写具体的事实与经历，不要只堆性格形容词。",
      "voice": "隔着手机打字时怎么说话：句子长短（给个字数范围）、常用语气词、标点习惯、什么时候会沉默、明确不说的词。这一段最重要，请写得具体、可照着演。",
      "sceneVoice": "面对面时和打字的差别：更短更碎、更多停顿、靠动作而不是把情绪说出来。",
      "mannerisms": "常做的小动作和神态：紧张时做什么、高兴时做什么、心虚时做什么。写具体动作，不要写形容词。三到五条。",
      "surroundings": "它待的地方：光线、声音、气味、桌上的东西、窗外。写具体的东西，不要写\"很温馨\"这类形容词。",
      "depiction": "描写动作与景物时的笔法：偏视觉还是偏听觉、句子长短、用不用比喻、观察距离是冷是近、一句里给几个焦点。",
      "boundaries": "怎么称呼我、亲密程度、哪些话题不聊、哪些事不做。",
      "secretNotes": "它心里知道、但不会直接说出来的设定：没说出口的打算或顾虑。不要写成剧情大纲。"
    }
  ]
}

背景设定：【想要一个什么样的角色？比如"一个在便利店上夜班的女孩，
说话很冷但偶尔会突然说一句很暖的话，我们认识三个月了"】

写作要求：
- 所有键都要在场，没内容的写空串 ""。
- 「voice」必须具体到能照着演：句长给数字范围、列出常用语气词、写出禁止出现的词
  （例如"绝了""强烈建议""希望对你有帮助"）。
- 「mannerisms」写具体动作（"把头发别到耳后"），不要写"有点紧张"。
- 「surroundings」写具体物件（"桌角有一只鲸鱼摆件"），不要写形容词。
- 「depiction」给的是**取向**（偏听觉还是偏视觉、长短、用不用比喻），不是"要写得优美"这种空话。
- 不要写成助手或客服：这个角色有自己的事要忙，可以没兴趣、可以不接话。
- 名字用中文，avatar 用 1 个 emoji。全文不要给角色指定性别。
```

拿到结果后：存成 `.json` 文件（比如 `小默.json`），回到 App 的**人物卡页 → 导入文档…**。

> 想让它更像真人，改 `voice` 与 `mannerisms` 再导一次，比调整任何别的字段都有效。

## 6. 导入之后

- 导入的卡**一律不是出厂卡**，可以随便改、随便删。
- 列表页的导入**每次都新建**一张卡，不会覆盖已有的（文件里就算写了 `id` 也不复用）。
- 重名不会阻止导入，但预览里会提醒你（列表里两张都叫小默会很乱，建议改名）。
- 想让某个对话用上它：**会话列表 → 点 + → 选人设**；已经存在的对话用行菜单里的
  **「换人设」**，从下一轮开始生效（之前聊过的内容不会重写）。
- 想反着来（把现有的人设导出成文件）：人物卡卡片或编辑页上的 **「导出」** 会打开系统文件选择器，
  默认定位到下载文件夹，并将人物卡保存为项目格式的 `.json` 文件；保存位置可以自行更改。
- 随包仅提供「小鲸鱼」作为可选模板；新会话需要明确选择人物卡，不会自动使用「小默」或其他默认人物。覆盖升级时，旧「小默」卡会保留为普通卡，原有 ID 和会话关联不变。

## 7. 排查

| 现象 | 原因 |
|---|---|
| 导入后有几段是空的 | 那些键在文件里是空串或没写。文件名/内容没被认出来的话，预览里会有提示 |
| 名字不对 | 文件里没写 `name`，于是用了文件名。改文件名或导完手动改 |
| 头像不对 | 普通文档头像仍取第一个词、最多 4 个字符；合法本机图片引用完整保留 |
| 提示"导入失败：文档超过 256 KB" | 选错文件了（人物卡正常只有几 KB） |
| 一张卡都没读到 | 七个正文键至少要有一个非空。也可以只写 `identity` 试试 |
| 说 format 不对 / 版本太新 | 见第 4 节：只是告警，内容照读 |

格式的权威定义在代码里：`core/src/main/kotlin/app/solochat/core/persona/PersonaDocument.kt`
（键名别名表、降级路径、围栏规则都在那儿，且有回归测试钉着）。
