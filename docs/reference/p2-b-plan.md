## 1. 基线、目标与差距

P2-A 已提交为 `eaeb8f3`；本次准备任务书时 HEAD 仍为后续模型选择 UI 调整 `75a823a`；工作区另有本阶段设计/文档及既有 `.gitignore`、`AGENTS.md` 改动，均未提交。HANDOFF 另有正式候选包覆盖启动记录，但未据此证明真实资料核对、厂商响应或恢复演练完成；这些边界继续保留。P2-A 最终依据见[复核记录](p2-a-final-review.md)，实施契约见[任务书](p2-a-implementation.md)。

目标沿用 [PLAN §2.3](../PLAN.md#23-p2-b一份生效价格与参考库)：每个 Provider 一份生效报价，明确绑定本机模型；保留旧规则与存档，参考库不参加运行选择。继续使用 R4，不新建计费引擎、凭据系统或历史账本。

| 当前实际实现 | P2-B 差距 / 复用入口 |
|---|---|
| `RegistryProvider.legacyPricing` 保存选表、开关和兜底价；报价按小写请求名及一次后缀剥离匹配 | 缺少 modelId 绑定、结构化核价来源和只读旧存档；复用 DataStore 原文档与配置锁 |
| `ModelAwareCallPreparation` 已限制新模型的旧价资格，冻结价格输入；压缩按各次调用时间选价 | 报价来源仍是旧目录。B 只替换规则选择与装配，保留 PreparedAgentCall 的冻结/记账链 |
| `resolvePriceEntry`、`forInput`、`recordedCost` 已实现缓存、多时段、日历、整档阶梯和未知用量 | 原样复用，不能把每个模型的“当前计算结果”当成完整规则迁移 |
| 价格入口已传 providerId，但页面仍有表切换、通用兜底、可编辑请求名/渠道等字段 | 改为该提供商的模型报价列表；请求身份只读，高级规则收起，旧表退到存档 |
| `ReferencePrices.sheets` 有渠道、核对日期、来源和说明，采用仍是整表复制 | 改为逐条报价及条件；按模型选择、预览后加入报价草稿；保留无法表达项只读 |
| `PriceTableTransfer` 支持严格 v1/v2、2 MiB、CNY/百万 token | 保留旧解析器；增加 v3 承载精确请求 ID、来源/条件及未关联数据，不把外部 ID 当本机身份 |
| P2-A R6 修复了本页价格保存回填模型草稿 | B 要建立存储级版本检查和字段边界，不能只靠 Compose 回填避免覆盖 |

本轮不重新核对参考资料中的商业报价；现有核对日期只代表源文件记录。首批可采用条目须在交付前重新核对官方或对应渠道原始来源。

## 2. 推荐数据结构与运行边界

### 2.1 存储最小方案

保留现有 DataStore、Provider/Model ID 和 Room v9。建议在 `RegistryProvider` 增加可空的 `pricing: ProviderPricing`，独立携带内部 `version=1`；原 `legacyPricing` 在转换后只读保留为升级来源/旧表存档。已有文档缺少新字段时表示“该提供商尚未整理”，不能被解释成已整理但免费。

暂不为 B 整体提升 `ModelRegistryFormat.CURRENT_VERSION`：P2-A 的不可变冻结计划还嵌有 v2 candidate 并做校验，直接改常量可能再次阻断 READY 启动。新增字段提供兼容默认值，报价有自己的版本；价格交换 v3 与内部版本独立。旧 App 不承诺能读取 B 的新字段，不能把保留旧数据等同于可直接降级。

首批契约概要（字段与校验细节以任务书 B1.1 为准）：

| 数据 | 内容与职责 |
|---|---|
| `ModelRegistryDocument.revision` | 默认 0 的文档修订号；DataStore 配置文档正式写入时原子递增，用于拒绝过期草稿；不扩展到 Room 账目或会话绑定 |
| `ProviderPricing` | 内部版本、`modelId → BoundModelPrice`、未关联报价；同一 Provider 只有这一份运行配置 |
| `BoundModelPrice` | 精确 `requestModelId` 护栏、完整 R4 `ModelPriceEntry`、来源及少量适用条件；modelId 是查找主键，请求名用于核对身份 |
| `PriceOrigin` | 用户填写/旧表/旧兼容兜底/随包旧快照/导入/参考采用；附原条目或表标识、渠道、核对日期、来源链接、适用条件等可用信息。缺失不补造 |
| 未关联报价 | 独立条目 ID、原请求名/规则/来源及未关联原因；导入遗漏模型、删除模型留下的报价均可保留，不参加运行 |
| 旧存档 | 原 `LegacyProviderPricing` 全量内容，含开关、选中表、非生效表、原兜底与 null 语义；必要时冻结其实际使用的随包来源，避免以后随 assets 更新变化 |

不引入通用价格规则语言。R4 entry 的旧 `model` 字段只是适配所需的规则键，不能再代替本机模型身份；保留合法旧键或由适配器生成合法技术键。v3 的精确请求 ID 单独保存，不受旧键小写限制。

### 2.2 规则选择与冻结

整理后路径固定为：`providerId + modelId` → 校验绑定请求 ID → 取完整规则 → `resolvePriceEntry(at)` → 现有 `ModelPrice` / 冻结阶梯 → `recordedCost`。缺报价返回 `known=false`，不访问旧兜底、参考库或新版随包资产。

旧兼容价建议在整理时按原有模型逐项物化为带“旧配置兼容价”来源的绑定。这样保留原来实际费率，又不保留一个能被新模型继承的 Provider 通用默认价。原 `legacyPriceEligible` 保留作升级来源，整理后不再独立控制一条运行兜底链。

- 同名、大小写或后缀相近的不同请求，运行时均不推断价格继承；迁移时可按旧算法给当时已有模型复制相同规则。
- 改显示名保留绑定；已确认改实际请求 ID 时将旧报价转为未关联，当前模型变为未知。即使以后改回请求名，也不自动回挂旧报价；显式确认后才采用。
- 新模型、重新创建的模型没有报价；禁用模型可保留自己的绑定。模型删除只移动报价到未关联，报价与模型在同次配置发布中调整。
- 未知价格本身不阻止聊天；无效配置或不支持的调用仍按 P2-A 预检处理，不能借价格整理切换服务。
- 有条件报价先核对少量可判定条件，例如限定思考模式；使用本次用途的有效意图（含压缩独立 OFF），不能读取聊天设置代替。AUTO 无法证明满足限定模式时返回价格未知。输入上限交给 R4 有限阶梯处理，不新建条件表达式引擎。地域/渠道由采用时明确核对，连接配置变化影响该确认时要求重新确认，不继续宣称原参考适用。
- 调用准备捕获规则、来源和必要条件的不可变副本；每次实际调用按开始时间选时段，之后仅按接口返回输入量选阶梯。保留 R8 多段压缩行为。
- 历史 `CallRecord.price` 不改、不重算。来源版本/核对日期可冻结进既有 `ModelPrice.source`；本阶段不为此增建账表或强制升级 Room。

### 2.3 必须保持的数值语义

| 情况 | 行为 |
|---|---|
| 未配置/明确清除报价 | 未知，不生成默认 `PriceRates(0,0)`，不套兜底或随包价。清空必填输入只形成未完成编辑并拒绝提交；清除走独立确认操作 |
| 明确输入、输出均为 0 | 已知零价；保存必须确实填写，空白不能转为 0 |
| 缓存未单列（null） | 保持 R4 的按输入价估算语义，并显示“缓存随输入价”；不称为已核对缓存价 |
| 缓存明确为 0 | 已知免费缓存命中，不能转成 null |
| 缓存用量未知 | 按现有计算器返回费用范围/估算，不补造命中率 |
| 日历未确认、超有效期、阶梯缺接口输入量或超范围 | 继续由 R4 返回未知，不能退回普通单价 |
| 随包价 | 仅作为旧配置兼容来源被冻结；不等于实时官方报价，不自动赋给新模型 |

本阶段继续限定 CNY / 百万 token，不做自动换汇；其他币种参考可只读注明不支持采用。

## 3. 旧价整理、保存与可恢复性

### 3.1 按 Provider 转换，先预览后一次发布

首次进入尚未整理的提供商价格页，系统自动计算确定性结果，预览仅展示已关联、未知、未关联与旧表保留情况；用户一次确认保存，不逐项确认可可靠映射的数据。取消不发布，原调用继续按 P2-A 受限旧语义工作。

这是同一个 R4 计算器的短期格式转换分支，不提供切回旧表的开关：`pricing=null` 使用原受限输入；非空后唯一读取新绑定，异常也不静默回退旧源。新建提供商直接为空的新配置，不经过旧兼容路径。

1. 在配置修订号和所选 Provider 下读取所有当前模型、完整旧价格及必要随包源。包括禁用模型；不读取调用历史猜提供商，不扫描聊天正文。
2. 使用与 `ModelAwareCallPreparation` 相同的资格/null/开关输入，并复用 `PricingRules.matchedModelId` 找旧规则。必要时只提取一个共用的旧输入构造助手，不能复制一套近似匹配算法。
3. 启用表且匹配时复制**整个 entry**，包括阶梯、未启用峰价、日历和来源；不能只执行一次 resolve 后把当时单价存下来。
4. 关闭读表或未匹配时，只给原有资格模型保留原兜底；明确“已配置零价”仍为已知，原未知仍未知。没有资格的新模型不能因迁移而获得兜底或 null 随包价。
5. 当前存在且已经按明确目录正常取价的模型也要保留其实际规则，不因 `legacyPriceEligible=false` 丢弃明确报价。小写/后缀旧匹配可为多个已有模型分别复制，不合并模型身份。
6. 非生效表全部保留为只读存档；当前旧表中未匹配的条目进入未关联入口，不以模型目录裁剪报价。null 随包源保留来源区别，不能把打开页面物化出来的整份 initialCatalog 当成用户采用。
7. 保存前重新核对 revision、Provider 存在性及模型请求身份；源变化则拒绝过期预览。一次 DataStore edit 发布转换和原文存档，不写 Room 或 SecretStore。失败仍是完整旧状态；重试不重复追加存档或生成第二套绑定。

无法证明等价的项目明确列出原因，不自行用近似规则补齐。用户若明确改成未知或另填报价，应作为可见的行为变更，不能混入“无损迁移成功”。

### 3.2 防止模型与价格草稿互相覆盖

复用 `configMutex`，加修订检查与定向字段更新，不新建一套仓库：

- 价格提交只携带目标 providerId、基础 revision 和报价修改；在锁内从最新文档合并，不提交旧的整个 Provider/Registry。
- 模型提交只修改该页有权编辑的身份、连接、用途等字段；保留当前报价。删除/改请求 ID 所需的报价解绑在同次发布执行，旧模型草稿不能把旧报价写回。
- 所有配置文档正式写入口校验基础 revision 并原子递增，包含价格、模型、用途与凭据发布；不要漏掉某个直接 DataStore 保存入口。不改变 Room 会话选择原有的锁与事务。
- 同一设置页完成价格保存后，继续沿用 R6 的草稿回填，同时更新基准 revision，保留其他未保存编辑。未知外部变更则拒绝保存并保留草稿，提示重载/比较，不默默覆盖；不引入通用自动合并框架。
- 配置版本校验在写新 Key 前完成；写 Key 后发布失败仍沿用 P2-A 新槽位安全语义。价格接口本身不读写 Key。

保留源格式不等于支持旧 APK 回退。需要恢复旧报价时，走可预览的显式导入/重新采用；不能直接改标记回到旧运行分支。应用聊天 ZIP 仍不含 DataStore 价格配置，价格导出是独立备份途径，恢复界面须说明这一边界。

## 4. 页面信息架构与主要流程

沿用 P2-A 紧凑列表、双主题、正常字号和间距，不重设计全局设置。Demo v1 已获视觉批准，本次仅就地调整局部交互；Luna 后续 UI 对照该文件实现，不另起设计。

| 页面 | 主要内容 / 操作 |
|---|---|
| 模型价格：提供商列表 | 显示真实提供商名称；进入报价不改变默认模型。提供商详情的价格入口可直接进入对应列表 |
| 提供商模型报价 | 行内显示模型名、必要的精确请求 ID、输入/输出简要价格或“未配置”；复杂规则显示简短状态，不堆满详情。搜索只搜索该提供商 |
| 单模型报价 | 身份只读；输入、输出与缓存直接编辑。高级规则外层及峰谷、阶梯、日历与有效期三组分别折叠，摘要显示已启用 / N 档 / 未设置；来源和适用条件可展开 |
| 次级管理 | 参考报价、导入/导出、未关联报价、旧表存档。没有生效表切换器或通用兜底价表单 |
| 未关联 / 旧表存档 | 查看、导出、选择条目并关联当前模型；存档不直接切为生效表，重复采用必须预览覆盖 |

单模型“完成”确认本模型并返回父草稿，提供商报价页“保存报价”才持久化。父页显示轻量“有未保存修改”，成功短反馈；失败保留草稿，冲突提示重新载入且再次确认丢弃，取消/离页沿用现有机制，不常驻解释草稿横幅。明确“清除报价”确认后同样先进入父页待保存状态。高级编辑优先复用 `AdvancedPriceEditor`，完整保留 R4。折叠/展开只改变展示，不开关规则、不删除已填写数据；不能为了简化页面削弱峰谷功能。

已确认：有阶梯时，顶部基础价明确标注“第 1 档”，直接编辑同一档数据，不另维护一份实际不生效的基础价；峰谷启用时注明谷价。各档峰价仍在高级规则中编辑。没有阶梯时直接编辑普通标准价。

参考与导入共用一条明确流程：**选择渠道/文件 → 选择条目及目标模型 → 查看新增/覆盖/未关联差异 → 加入草稿 → 保存**。确认加入草稿后显示“待保存”，不能误报为已生效。未关联项可以保留，不自动创建模型或改变请求 ID。

## 5. 参考库与交换格式

### 5.1 参考库

将现有硬编码整表逐步整理为版本化只读数据，建议随包 JSON，复用同一组 R4 规则字段和校验，暂不增加联网更新、账号或远程覆盖机制。

- 每个条目有稳定参考 ID、渠道/地域/服务模式、精确请求 ID、核对日期、来源链接、适用条件、规则或明确的只读原因。Provider UUID 不作为参考渠道 ID；不凭自定义接口名称推断渠道。
- 核对日期不是自动失效时间；新版参考不会修改已采用报价。来源更新仅提示可比较，用户再次选择才替换未来价格。
- 默认只为已配置的目标模型给出匹配建议；仅在用户选定目标 Provider 后处理，不跨提供商按同名自动关联。渠道不一致要提示并要求明确确认，不能自动重分类 Provider。
- 主动采用参考时展示完整规则替换预览，默认整条替换；批量导入默认跳过已有项，明确选择后才替换，避免“只换基础价却留下旧高级规则”。手动编辑已有报价仍允许只改一个字段，保留其余规则。其他模型、价格存档和模型设置不受影响。
- 条件必须可表达或可明确核对：例如输入上限可用有限阶梯表达；缓存创建费、Batch、其他币种或无法识别的思考计价差异不能用近似规则冒充支持。特别是 AUTO 不能证明使用了非思考模式。
- 有峰谷条件的参考不能因默认关闭峰谷，就把谷价宣称为全天准确报价。条件无法确认时不采用为已核对参考；允许另行手动填写估算价，来源归为“用户自定义 · 估算”，不得保留已核对官方标记。旧配置已有开关状态在迁移时原样保留。
- 首批集中于已有两个渠道及用户实际需要的少量条目；逐条核对金额、地域、模式、缓存口径、阶梯和日历。参考覆盖广度不作为迟迟不能交付的理由。

### 5.2 v1/v2 与建议 v3

`PriceTableTransfer` 的 v1/v2 解析和原文件能力保留；B 不再将导入表选成另一张生效表，而是转换为待映射报价。旧表存档仍可原格式导出。

建议 v3 使用显式 `formatVersion/currency/unit/name/entries`；entry 包含文件内条目 ID、精确 `requestModelId`、可选显示名、R4 规则与结构化来源/条件。完整提供商报价导出还可携带未关联条目及只读旧存档；这些分区导入后也不自动生效。未知项明确表示未知，不能生成零价。

- 不导出地址、Key、当前默认或用途选择；不把本机 modelId/providerId 当作目标安装的关联依据。文件条目 ID 仅在文件内部标识，导入本机另生成身份。
- 先明确目标 Provider，再按精确请求 ID 给唯一匹配建议；重复请求名、大小写差异、旧文件规范化或后缀可能对应多个模型时要求选择。无匹配可保留未关联，绝不为补映射新建或启用收费服务。
- 现有模型报价默认跳过，用户明确勾选才覆盖；同一导入批次不能向同一目标写两份报价。相同规则可提示无需修改；未完成的冲突不得静默取第一项。
- 未知条目默认不清空目标已有报价；需要清空必须明确选择。覆盖建议按模型整条规则，不默认字段拼接。
- 默认导出 v3；兼容 v1/v2 只在费率/规则可表达时提供，并说明不携带完整元数据。精确请求 ID 的大小写碰撞或无法表达的信息不能静默合并，必要时要求改用 v3。
- 新增仓库内 JSON Schema 与示例；Schema 检查结构，Kotlin 继续检查非负有限数、必填价、重复目标、严格阶梯、时区/日历等语义。两者同测，不引入运行时联网 Schema 服务；格式有效不能证明来源报价正确。
- 延续 2 MiB 上限、BOM、严格字段和 SAF `*/*` 后按内容解析。解析失败不回显可能带秘密的原文；取消文件/预览不发布。金额与元数据完整往返后，才宣称 v3 可用。

## 6. 建议交付顺序、文件范围与验收

以下保留阶段依赖与验收基线；具体实施边界和审核安排见[实施任务书](p2-b-implementation.md)。先数据/接口、后接已评审 UI。

| 包 | 依赖 / 主要范围 | 交付与最小验收 |
|---|---|---|
| B0 方案与视觉确认 | 本方案、已批准 P2-A Demo | 视觉已通过，三组独立折叠、完成/保存、清除与空白/零语义已收敛；同一 Demo 为实施基准，不直接实施整套 UI |
| B1 数据与只读迁移计划 | B0 技术方向；新增 app `data/pricing/ProviderPricing.kt`、迁移计划，扩展 `ModelRegistryFormat` | 只用合成配置，生成绑定、未知、未关联及存档；验证所有旧来源、重试幂等与 v2 冻结计划仍可读，不启用真实转换 |
| B2 原子保存与调用适配 | B1；`SettingsStore`、`SoloChatApp`、`ModelAwareCallPreparation`、模型草稿 | 修订检查/字段合并、模型改请求 ID 后报价处理、正式/压缩冻结。旧新相同输入/时刻等价；过期草稿、发布失败、未知不回退；接口独立测试，不先动真价 |
| B3 交换格式 | B1；core `PriceTableTransfer` 旁的 v3 codec、Schema/示例及 app 边界适配 | v1/v2 继续读取与导出；v3 往返、冲突/大小写/未关联/秘密字段拒绝；不自动映射外部身份，不改变金额或活动模型 |
| B4 报价编辑与整理 UI | B0 视觉、B2、B3；`SettingsScreen`、`PriceTableEditor`、`ModelPriceEditorScreen`、`AdvancedPriceEditor` | 按 Provider 接列表/单模型/未关联/存档，替换旧切表入口；保存取消与并发回填正确；隔离设备检查必要表单、键盘、长名称、深浅主题 |
| B5 参考库与逐模型采用 | B2～B4；`ReferencePrices`、随包数据与复用的预览页 | 少量渠道逐条来源核对，按条件决定可采用/只读，比较新增覆盖，采用只入草稿。库更新不改生效价 |
| B6 集成与独立关闭 | B1～B5 | 验证转换→保存→重启、v3 导出再导入、旧表仍可取回、模型/价格交叉编辑与在途调用；只运行相关回归，独立复核后再决定启用/提交 |

验证优先复用 `PricingRulesTest`、`PriceCatalogTest`、`AdvancedPricingTest`、`PriceTableTransferTest`，以及 P2-A 的 `ModelAwareCallPreparationTest`、草稿和 `CompressionServiceTest`。按本包变化选择类，不把全量 App/core/Room 重跑设为门槛。

必须新增的证据集中于：旧解析到新绑定的完整规则等价、版本冲突与失败不发布、request ID/删除后的解绑、新参考/导入映射，以及跨段调用冻结。代表时刻覆盖峰谷边界、跨午夜、星期/日历、有效期内外；输入覆盖阶梯边界与缺返回量；数值覆盖零价、未知与缓存 null/0。不建立额外常驻测试网关。

不升级 Room 时，无需为了 B 重跑 P2-A 全套 migration instrumentation；仍需用既有调用记录/备份夹具证明改价前后历史记录内容与金额不变。若后续获准操作真实价格，才按 LESSONS 做必要的前后资料核对，不能将聊天 ZIP 当成设置回滚。

主要风险是规则迁移失真、过期草稿覆盖、请求身份变化错绑、参考条件不适用及把存档重新当生效表。它们分别由完整规则复制/对照、锁内 revision、精确绑定护栏、采用预览和单一来源限制解决。P2-A 尚未完成的正式厂商/恢复验证继续单列，不以 B 的本地计价测试代替。

## 7. 已确认产品决定与视觉评审边界

| 范围 | 已认可的设计基准 |
|---|---|
| 普通 / 高级 | 输入、输出、缓存直接编辑；高级外层及内部峰谷、阶梯、日历与有效期三组独立折叠，只改变展示，保留完整能力与数据；摘要展示已启用 / N 档 / 未设置 |
| 完成 / 保存 | 单模型完成只回父草稿；父页保存才生效，轻量未保存提示；失败保留、冲突不覆盖，重新载入须确认丢弃 |
| 空白 / 零 / 清除 | 空白不是 0；明确输入 0 为已知零价；独立确认清除报价才删除关联，缓存随输入价为 null，与明确 0 不同 |
| 覆盖 | 批量导入默认跳过已有报价；主动采用参考时预览完整替换，默认整条规则替换；手动编辑可局部修改 |
| 未核对参考 | 不自动采用、不将优惠时段价当全天价；可另行手动设置自定义估算，不能标为已核对官方报价 |
| 币种 | CNY / 百万 token；不自动换汇 |
| 提供商移除 | 展示报价和存档的影响范围，提供导出入口；无报价回收站，历史调用费用与保留 Key 槽位不变 |

模型身份绑定、完整复用 R4、无损迁移、revision 与原子保存、参考与生效价分离，以及修改实际请求 ID 后解绑原报价均已确认，不重新规划架构。
