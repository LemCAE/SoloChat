# P4｜人物表情包系统：统一方案与实施任务

> 2026-10-27，Sol 收敛。用户已确认双表情库、点击表情立即入队及本文对应的产品方向，授权创建全新 `[Luna]P4`（GPT-6 Luna High）实施。基线 `1efcbdc`，规划前工作区干净。本文是 P4 公共契约与唯一任务书；计划不代表实现或验收。
> 本文覆盖此前讨论稿中的“只有人物库”“表情先入草稿”“作为表情发送开关”。P3 已正式关闭，不重新打开其三项独立后续验证。

## 1. 已确认范围与协作授权

- 我的表情库全局共享，由用户添加、删除和管理，首版只有收藏关系与展示排序所需信息，不建立名称/描述/标签/场景/锁体系。添加收藏不产生消息、不入队、不调用模型、不公开给人物。
- 人物库按明确 personaId 隔离，同人物跨会话共享；AI 只可自行收藏已实际推送给当前人物的用户表情消息，不能浏览用户库，不能自动收藏普通图片或修改用户库。是否收藏由 AI 决定，无须逐次确认。
- 用户表情按钮默认打开我的表情库；点击已有表情立即创建一条独立、有序的用户消息并入队，不经过草稿或文字发送键。普通图片仍从原附件入口进入图文草稿；入口决定用途。
- 表情、已提交文字和普通图片共用 AUTO/MANUAL 防抖、批次认领、推送与失败重试。入队≠推送，推送≠收藏，收藏/描述更新≠AI 发出。不得因连点自动拆成多个收费调用。
- AI 可维护人物表情名称、描述、标签和使用场景。用户手动修改的具体字段自动锁定，可主动解锁；AI 只修改真正写入时未锁且版本有效的字段。
- AI 首版只在 chat 发表情；用户表情沿用两种模式已有的用户输入能力，不因 scene 将表情误记为动作或旁白。切换模式不能把场景中的 AI 表情意图延后到聊天模式偷偷播出。
- JPEG、PNG、静态 WebP，沿用 P3 实际内容、动画、大小及像素校验；GIF/动画 WebP/APNG 明确拒绝，不取首帧。不增第二视觉模型、通用工具框架、多轮检索、AI 生图、正式 LAN 网页、主动消息或群聊。
- Sol 负责契约、分解、集中独立复核；Luna High 连续完成一个二级阶段内的全部小任务、自测、修复和本地提交，整组结束或重大阻塞才返回 Sol。用户确认关键 UI 和最终关闭。
- **用户明确授权 Sol 与 Luna 的一般任务派发、复核/审批往来、修复反馈及阶段放行消息直接发送，无须再次征询消息发送授权。** Luna 可在整组交付或重大阻塞时主动向 Sol 回报；此授权不扩大安装、发布、收费请求或真实资料权限。
- 允许项目代码、合成数据、必要定向测试和本地提交。用户另明确授权：可新建本轮专用测试人物与测试会话，使用正常已配置模型进行必要真实调用；不得使用非测试人物、与其聊天或操作本轮之前的已有对话。测试资料默认保留。模型交互优先走接口，不为此反复操作 GUI；缺接口可在现有服务内补充。
- 不得擅自安装任何设备包、推送、发布、改真实 Key/服务配置/历史资料、执行真实库不可逆迁移、卸载或清数据。测试请求通过既有凭据和价格链路正常调用，不展示/修改凭据、不改全局配置迁就测试，不自动切服务或收费重试。不沿用旧设备地址。Room 迁移先用隔离合成库；真实资料升级另按现行授权和保护约定处理。当前无新增安装授权，缺运行新代码的宿主时可先实现/定向验证接口并说明设备运行尚未执行。

## 2. P3 复用与新增边界

复用 MediaAsset/MediaLibrary 的不可变原件、内容去重、缩略图、发送变体、大图/另存，InputSubmission 的稳定操作身份，SessionController/SessionRegistry，视觉预检、PreparedAgentCall、调用记账及 ZIP 媒体流校验/恢复续接。core 继续纯 JVM。

已核对的改动点：

- P3 MessageAttachment 只有 messageId/ordinal/mediaId，没有用途。P4 用新增语义关系区分普通图片与表情，不从 MediaAsset、文件名或图像内容猜用途。
- submitMedia 当前强耦合 MediaDraft 的保存和清理；不能将表情点击伪装成一次图文草稿提交。
- AUTO 文字目前可先留内存，媒体先持久化；submissionGate 与内存认领分别存在，混合输入需要统一顺序和认领边界，不能只在 UI 多起几个异步任务。
- Player/Timeline/ChatProjector 以 displayText 筛选可见事件；PlaybackStatus 没有事件 ID，控制器存在按正文定位。P4 须让媒体载荷参与可见性，并按事件 ID 播放与交付。
- ZIP v3 只允许 USER 消息附件，原图闭包仅取消息附件；旧格式不能悄悄夹带收藏与助手事件媒体。P4 写 v4，严格读 v1～v3。

## 3. 双收藏公共数据契约

类型与表名可按代码风格细化，以下身份、权限和生命周期不得改变。A-1 一次定义 A/B/C 的持久化和传输结构，不把后两组只留成含糊 TODO。

| 概念 | 身份、字段与不变量 |
|---|---|
| MediaAsset | 沿用 P3，不归属用户库或任何人物；原始字节不可变，摘要+大小确定内容，同图可复用原件。知道 mediaId/摘要不构成访问资格 |
| UserSticker | 独立 `user-sticker-UUID`、mediaId、创建/排序信息；同一全局用户库的同一内容只有一个有效收藏关系。无 AI 字段与锁。用户删除只解除这条收藏关系 |
| PersonaSticker | 独立 `persona-sticker-UUID`、personaId、内容身份（原件 SHA-256+大小）、mediaId、ACTIVE/REMOVED、collectionEpoch、四个元数据字段及各自锁/字段版本、必要创建/更新和实际使用记录。不同人物不共享上述状态 |
| MessageSticker | 与真实消息附件的 messageId+ordinal 一对一，表明 STICKER 用途，冻结发送目标 personaId、媒体内容身份、当时 collectionEpoch 和必要历史语义。可保留可空的用户收藏来源引用作追溯，绝不能靠它决定消息是否继续有效或向模型公开用户库 |
| EventSticker | 与 eventId 一对一，冻结人物收藏 ID、personaId、collectionEpoch、mediaId 和当时名称/必要描述。交付后可关联唯一助手上下文 messageId，禁止后查当前收藏重建旧语义 |
| StickerCallScope | 本次请求的不可变本地快照：当前人物、实际本批输入来源、允许收藏的消息附件、候选人物收藏及 epoch/字段版本、实际附图来源。随 PreparedAgentCall 传递，不由模型反向决定授权范围，无须另建通用任务系统 |
| StickerTurnResult | 以实际 callId 为幂等身份的本地提交结果，包含响应指纹、逐操作应用/跳过/拒绝结果及本轮事件身份。相同结果重入返回既有结果，冲突明确失败；不产生第二份用量账 |

### 3.1 去重、删除与重新收藏

- 用户库和人物库使用独立关系。导入同一文件可复用原件；给另一人物添加/收藏必须产生该人物自己的身份与元数据，不复制其他人物理解、锁或习惯。
- 同人物同内容复用一个人物收藏身份，包括移出后再次收藏；重复操作不能生成多条有效收藏。移出保留墓碑、字段/锁及 collectionEpoch，不删除历史。重新激活不得覆盖仍锁定的字段，不复用其他人物状态。
- 用户删除我的表情，不影响已入队消息、历史、人物收藏和进行中的模型调用；人物移出收藏不影响用户库或其他人物。共享原文件不随取消收藏立即删除，P4 不做全盘媒体 GC。
- `collectionEpoch` 初始为 0；人物移出时原子递增。每条新表情消息在入队事务中捕获该人物/内容当前代次（此前无人物关系时为 0）。AI 收藏须同时满足来源代次与当前代次一致。移出前的消息即使日后重试/重新进入上下文也不能重新激活；移出后用户新点发的同图捕获新代次，才重新获得资格。不用时间戳比较或“重新请求就算新授权”。
- 生成时已选中的 AI 表情在真正出口前复查 ACTIVE、人物、代次及媒体可用性；移出再重新收藏也不能让旧代次的发送意图复活。描述修改不等同于撤销收藏，不应无故取消可用表情。

### 3.2 历史快照与旧格式兼容

- 用户表情消息可空正文，原件使用真实 MessageAttachment；MessageSticker 记录用途与发送目标，不往用户原话写路径、ID 或伪造说明。删除用户收藏后仍能看图、重试与成为合法来源。
- 普通历史图片没有 MessageSticker 就保持普通图片；不得迁移为表情，不从当前库中的同内容关系反推旧消息用途。
- AI 历史媒体从 EventSticker 和已出口助手消息关联读取。助手上下文消息可复用 MessageAttachment，但必须通过 v4 的明确交付关系验证，不能仅放宽成任意 ASSISTANT 附件。
- 旧 Message/Event 不随意新增默认序列化字段导致旧指纹变化；优先用旁表/明确排除空扩展。统一扩展来源指纹：有表情时包含不可变用途/快照与媒体内容，不含当前描述、锁、缓存或后来统计。无表情路径逐字兼容。
- 正式上下文、压缩预览/启用、恢复重映射共用同一扩展指纹入口。历史显示和模型标记不从当前库重建；结构化引用与展示文字分开，恢复不能全文替换正文里的 UUID。

## 4. 用户入口、提交与批次调度

### 4.1 收藏与面板

- 输入栏独立表情按钮，默认简洁的“我的表情”网格；添加入口使用现有系统图片选择及 MediaLibrary。导入/验证/关系发布成功才显示收藏成功，取消或失败不产生消息。
- 表情面板与键盘、附件面板互斥，共用现有高度/返回处理，沿用当前 Material 配色、字体和密度，不改全局风格。添加/管理退居面板工具入口，删除不在每个主网格项上堆按钮。
- 人物库从人物管理或面板次级管理入口进入，用于查看、手动添加、移出和四字段编辑/解锁；不要求用户日常切库发送。不因打开、编辑或添加任一收藏自动调用模型。
- 普通历史图片可以通过明确“收藏”操作加入我的表情或明确选定人物库；只新增所选关系，原历史用途不变，也不制造一条可供 AI 自动收藏的表情消息。目标人物必须明确，不隐式跨人物复制描述。

### 4.2 点击表情的统一提交

- UI 在点击时同步捕获当前会话、人物、userStickerId、mediaId、稳定 submissionId、点击顺序；每次真实点击是新的消息操作，允许连续点击同一图；同一次操作的异步重试复用同一 ID。不能用按内容/短时间节流吞掉有意连发。
- 由应用级会话唯一写入者接收有序命令，复用并完善现有 submissionGate/认领边界。序号在点击入口分配，不能将竞争 Mutex 或文件读取完成顺序当作点击顺序。必要时使用轻量串行命令入口，不另建持久待发状态机。
- 在同一提交事务检查会话未暂停、人物明确有效、所选用户收藏仍有效、媒体完整，写一条空正文 SAY 的 USER Message、ordinal=0 的附件、MessageSticker 及 submission 映射。库提交确认后立即展示和计入待发；失败明确提示，不画成已保存成功。源收藏的校验和删除以事务先后为准，成功入队后不再依赖该收藏。
- 使用 InputSubmission 的幂等身份与消息映射。为新表情提交加入明确版本化的附件用途/语义指纹；同 submissionId 换用途、人物或内容须拒绝。旧普通图 payloadChecksum 算法及已保存 submission 保持兼容。`draftVersion=-1` 的表情提交不保存、读取、清除或重建 MediaDraft。
- **点击表情不提交或清除用户仍在输入的文字、普通图片草稿。** 只有此前已经明确提交的内容参与顺序和批次。
- 处理“已提交 AUTO 文字尚在内存 → 表情点击落库 → 后续文字/图片”时须保持原动作顺序。可在同一串行边界将先前已提交文字转为未推送行，再追加表情；成功后撤销对应内存占位，失败不丢原输入。不得触发模型、提前标 sentToModel、重复落盘或让新输入被旧批清空。
- UI/时间轴顺序、待发认领顺序、请求中的顺序须一致；同毫秒靠稳定提交顺序/消息主键区分，不靠 createdAt 去重。离页/切会话不把迟到点击写到新会话，应用级任务正确收尾。

### 4.3 AUTO/MANUAL、预算与失败

- AUTO 每次表情入队参与既有防抖重置和一次批次认领；MANUAL 只保存代发，显式推送才打断/起轮。不得新增每图独立的调用定时器；保持现有 AUTO 插话、MANUAL 推送的时机。
- 预检和认领使用同一个有序批次快照；预检挂起期间到达的输入留下一批或使旧计划失效重做，不能预检 A 后认领 A+B。现有内存文字与 Room 未推送媒体必须共用一次起轮边界。
- 沿用 P3 图片能力、单次普通图片提交上限、总图片数量/8 MiB/1600 万像素等现行请求预算；收藏本身不占请求预算。表情不豁免视觉校验，不能悄悄降为文字。预算以整批新输入计算，近期历史/理解候选只使用剩余预算。
- 连点超过单轮预算时保留整批并明确提示，不自动拆分、截断或无限循环收费重试。给出可操作的最小待发处理：允许用户明确移除指定尚未推送的表情再推送，提示影响范围；不动已推送消息、其他历史或库收藏。不建立庞大的队列管理页。
- 失败重试基于既有消息/submission 身份，不再追加消息、附件或授予新收藏代次；重新冻结当次配置/价格，每次真实请求有新 callId。沿用 P3 对取消、已有出口、新输入和进程中断的重试限制，不自动重发。
- 已确认入队的表情不会因用户之后删除收藏而失败；原件真实丢失则明确占位、拒绝需要该图的请求，保留输入。导入取消、页面生命周期取消与真实故障分别处理。

## 5. AI 来源、理解、维护与选择

### 5.1 来源权限

- 模型只获得当前会话实际推送的消息和当前人物自己的少量有效候选；绝不枚举我的表情库，不能将全局用户收藏表/ID/排序注入上下文。底层内容去重不能带出另一人物的描述、锁或使用记录。
- 每次请求建立 StickerCallScope。可收藏输入限本次明确推送或合法重试的真实 USER 表情消息；核对 conversationId、发送时 personaId、sentToModel、附件 ordinal/mediaId/原件摘要、代次及本轮实际附图来源。不能只凭 sentToModel 或历史里出现过就授权，也不接受任意 mediaId、网址、路径或另一个会话的消息号。
- 新表情按 P3 新图片规则全部预检并附入本轮；调用开始不等于理解成功。仅在完整响应提交时执行有效收藏操作；请求失败、超时、取消或无合法响应不宣称已收藏。是否收藏由 AI 决定，不由本地“凡表情必收”。
- 普通图片、未提交草稿、未推送代发、用户库中未发送条目、其他人物收藏以及 AI 自己的历史事件不获得自动收藏资格。手动添加人物库是独立用户操作，不受上述自动收藏来源规则限制。

### 5.2 JSON 与副作用提交

保留每轮一个脚本；增加可选 `sticker_ops`（collect/update）与可播放 `sticker` 事件，无工具返回轮次。

```json
{
  "events": [
    {"type": "say", "text": "这下满意了吧"},
    {"type": "sticker", "sticker_id": "persona-sticker-example", "gap_ms": 700}
  ],
  "sticker_ops": [
    {"op": "collect", "source_ref": "本轮提供的消息附件引用", "patch": {"name": "得意", "description": "带点得意的笑", "tags": ["得意"], "usage_contexts": ["开玩笑时回应"]}},
    {"op": "update", "sticker_id": "persona-sticker-example", "patch": {"tags": ["得意", "开玩笑"]}}
  ]
}
```

- source_ref 由本地提供并映射到本轮许可输入，不由模型自造授权；collect 由本地分配/复用人物收藏 ID。新收藏从后续轮次进入候选，不提供同轮临时 ID 引用。
- patch 只接受四个元数据字段，缺省保持原值；空值与清除含义明确，类型/长度/列表项数有小型合理上限。锁、人物、媒体、状态、代次、统计不可由模型写入。每轮同一来源收藏及同一目标字段更新只允许一个明确操作，冲突拒绝而不靠数组末项偷偷覆盖。
- 副作用仅从完整可校验的根对象严格解析，不从截断/抢救/降级文字猜执行；可抢救普通事件，但不能把仅含无效表情/操作的 JSON 作为 SAY 显示。无效 ID/字段逐项给出诊断，其他有效文字保留，不伪装成功。
- 同一 Room 事务发布人物变更、操作结果和本轮 PENDING 事件/载荷，失败整体回滚；事务成功后的 UI/播放取消不回滚已收藏与描述。取消发生在提交前须阻止旧代次发布。已提交后记账/通知异常应先识别结果，不让同一响应被重新应用。
- 复用现有 call_record/config/media 首写与收尾；不将本地写库异常冒充厂商未收费，不为补描述多发请求。仅执行已确认幂等收尾，不能以 NonCancellable 包住整段网络或无边界工作。

### 5.3 字段锁、并发与候选

- 每个字段独立锁和递增版本。用户修改和自动上锁同事务；解锁也递增该字段版本。写入时按本地请求快照核对当前字段版本与未锁状态，不能信模型提供的版本。用户修改/锁后又解锁也不能被旧结果覆盖。
- 同人物多会话、用户编辑和模型更新统一走存储事务/乐观比较；冲突字段跳过，其他合法字段仍可应用，不用会话锁假装保护跨会话共享状态。不持人物锁等待网络，不引入会话锁/配置锁反向嵌套。
- collect 命中已存在人物关系时只幂等复用身份、按同样字段版本规则补充；不能通过 collect 绕开锁、移出屏障或新建第二条同内容关系。
- 候选按当前人物 ACTIVE/资源完整过滤，以名称、标签、场景与近期文字做简单匹配，结合近期真实使用选少量条目。初值约 10 个并设字符预算；不建向量库、额外检索调用或新调参页。默认鼓励 0～1 个表情，计入现有回复条数，不按次数验收。
- 有可靠用户/历史描述的候选可只提供文字并按 ID 发送；没有附图不声称本轮重新看过。手动添加但未理解的少量收藏可在有剩余视觉预算的聊天轮次中附图完善，新增用户输入优先，预算不足延后，不自动后台调用。
- P4 协议可追加固定静态说明块，保留既有静态块内容和顺序并准确更新 stablePrefixChars；日常候选、锁/版本、许可来源、理解状态一律在动态区，相同人物/模式/协议版本下前缀逐字节稳定，不将整库变化写进稳定前缀。
- 收藏图片可能没有任何 messageId；扩展调用媒体来源为有类型的 MESSAGE / PERSONA_STICKER 引用，复用变体与预算，不能伪造 messageId=0 或把候选图片挂到无关消息。旧 CallMediaInput 继续兼容，v4 明确保存新来源；新的来源字段不允许我的表情库入口。实际图片顺序、来源标记和费用未知口径保持一致。

## 6. AI 事件、实际出口与历史

- `sticker` 事件只接受 StickerCallScope 中的当前人物候选 ID，不接受用户收藏 ID/裸 mediaId。发布前校验，播出前再复核身份、ACTIVE/epoch 和媒体完整性；scene 拒绝该事件但保留其他合法输出。
- EventSticker 是本轮冻结载荷；不通过 SAY 中特殊文本假装图片，不把元数据塞进 text 后再全局字符串解析。Player、Timeline、投影、Live、历史定位、首页预览采用统一“有可见载荷”的规则。
- PlaybackStatus/播放步骤携带 eventId，重复文字或重复表情仍按事件身份定位。表情整张显示，使用短准备/间隔，不按描述字数计算打字或逐字动画；保持逐条刷新，不重载整时间轴。
- 实际出口入口以 eventId 幂等，同事务更新 delivery/deliveredAt、唯一助手上下文消息及附件/发送快照关联、AI 实际使用计数/最近使用。正常完成与打断补写共用该入口；不能只靠内存 writtenIds 防进程重建重复。
- DELIVERED/已显示的 INTERRUPTED 算已发；PENDING/PLAYING/CANCELED 不进入已发历史或统计。还在阅读/间隔中被取消的表情从未发出。已完成的收藏/描述不随播出取消撤销。
- 失效 ID/收藏撤销/播出前缺文件：该表情明确取消且给出简短原因，其他有效事件继续；不改成“[已发送表情]”或自动收费补发。真正写库失败不能发布成功 UI，启动收尾不补造曾经出口。
- 时间轴、上下文、搜索、定位与首页读取当时快照。默认搜索可靠文字/发送时名称，不做 OCR；表情显示与大图/另存复用媒体控件。模型上下文与压缩不读取今天的收藏说明改过去含义。

## 7. Room v11 与 ZIP v4 公共契约

### 7.1 数据迁移

- A-1 基于 v10 新增双收藏、消息语义、事件载荷/交付关联和结果幂等等必要结构，整体升级 v11，导出 schema。不重建旧表/改旧行，不改 v10 历史迁移、不把普通图自动收进任一库。
- 不把用户库建成特殊人物卡或空 personaId 人物库，不建第二媒体文件系统。有效关系有明确唯一性和索引；文件提升仍先于引用发布，失败仅清理本次新建且未引用的文件。
- A-1 同时建立 B/C 使用的数据/端口/备份 DTO 与约束，可分文件但不可在 B/C 私自改既有 v11 语义。需要再迁移或破坏性契约变化先交 Sol 分析，不直接重写已运行迁移。
- 只在合成隔离 v10→v11 库验证旧表原行/索引保护、事务回滚与新 schema；遵守现有按主键核对要求。真实库未获单独授权不打开、不迁移。

### 7.2 导出、恢复与用户库冲突

- 新写 ZIP v4，严格读取 v1/v2/v3 各自结构与语义；媒体流限制、实际解码、摘要/长度、路径与重复条目校验复用 P3。旧写入/快照 API 对存在 P4 资料必须明确拒绝遗漏，不能只检测 message_attachment 数量。
- v4 媒体闭包：全部现存消息附件、历史/待播事件所需原件、有效用户收藏、有效人物收藏。同内容一份字节；只收藏未发送也必须可恢复，取消收藏但仍有历史的图片必须保留。草稿/缓存/Key/提供商设置继续排除。
- 人物移出墓碑的 ID、内容身份、epoch、字段及锁随备份保存，避免恢复后失去撤销语义；没有历史/有效收藏需要的墓碑原件不强制打包。传输模型允许 REMOVED 关系仅有内容身份、mediaId 为空；ACTIVE 必须引用完整包内资源。不要为了墓碑打包所有无引用文件。
- 用户库恢复是**不覆盖的追加恢复**：包内用户收藏按已核验媒体内容匹配本机现存用户收藏；已存在则复用用户关系，不覆盖本机顺序/状态，不重复网格项；不存在则新建 user-sticker ID 并按包内顺序追加。明确恢复本身是用户授权，不触发人物收藏或 AI。
- 人物、会话、人物收藏、消息与事件仍建立独立副本身份，不按姓名/媒体将人物收藏合并进本机真实人物。媒体文件可以去重，人物字段/锁/计数不合并。历史里已删除的用户收藏来源允许隔离悬空；历史展示只依赖自己的媒体快照，不强制补造收藏。
- 原包合法性先校验，再统一重映射两类收藏、人物、事件/助手消息/附件、代次来源与调用媒体引用；不得因重映射将失效摘要洗成有效。旧消息无表情关系仍为普通图。待播事件取消，副本会话持久暂停，不重放 AI 操作或历史调用。
- 本地操作提交回执/本次许可快照不作为恢复后执行权限；恢复结果只带已应用业务状态，已知来源历史按明确类型保留。暂停解除后的代发推送仍须重新预检，并遵守原消息的收藏代次，不能借恢复或重试刷新旧授权。
- 沿用固定 importId 续接、先查已提交结果、文件先校验提升再单事务发布、清理失败与提交失败区分。用户库追加/复用、人物副本和引用必须同事务提交；失败不得留下半份新收藏。重复同一操作幂等，主动再次导入可新增人物/会话副本，但不重复全局同图收藏。
- A 先完成用户/人物收藏及用户表情消息的 v4 基础闭环，并定义完整事件/类型来源 DTO；C 接通 AI 事件后补运行路径验收，不另换一套格式。中间阶段若存在尚不支持的新内容，明确阻止相关导出/导入，不能丢内容报成功。
