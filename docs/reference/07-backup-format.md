# 备份协议、导出与副本恢复（阶段 4A）

> 2026-10-22 已接入 Room 一致读取、事务副本导入与 SAF 预览/确认入口。
> 导出曾实机保存成功；副本恢复已有定向与离线检查，完整跨安装实机迁移仍待确认。这里保留该验证欠项，设备授权与后续安排以当前会话及 [HANDOFF](../HANDOFF.md) 为准。

## 1. 文件与内容

实现位于 `core/backup/BackupData.kt`、`BackupCodec.kt`、`BackupImportPlan.kt`，不依赖 Android。

`BackupCodec.writeV3` 接收业务数据和文件流，输出 ZIP v3；`read` 流式读取并校验后返回 `BackupArchive`。
外层调用者负责关闭输入输出流以及呈现文件读写失败。v3 有 `manifest.json`、`data.json` 和媒体条目；每个媒体条目只在校验期间流式暂存，不将整个 ZIP 或媒体内容驻留内存。旧 `write` 接口只写 v2，并拒绝含媒体数据的输入；新 UI 只走 v3。

| 条目 | 内容 |
|---|---|
| `manifest.json` | `format=solochat-backup`、版本、备份 ID、生成时间、正文 SHA-256、各类条数、排除项目 |
| `data.json` | 会话、消息、事件、人物卡、记忆、旧摘要、上下文修订与段、全部旧用量、新调用及 usageId 关联；v3 增加资源、消息附件、提交映射和调用媒体输入元数据 |
| `media/<sha256>-<byteSize>.bin` | v3 的原始媒体字节；每份不同内容一条，摘要与长度由实际字节复核 |

正文为严格 UTF-8 JSON，枚举使用领域模型的序列化格式。包中只存业务字段，不复制 Room 数据库文件。
新调用按结构化 `CallRecord` 保存，保留原价格与用量来源，不按导入时配置重算。

协议排除密钥、接口配置、其他设置、日志、网页命令、草稿/缓存与头像文件。`avatar` 字符串保留，消息附件原图随 v3 迁移；缩略图、发送压缩缓存及无引用文件不打包。v1/v2 保持严格兼容且不得夹带媒体字段或条目。增加文件种类或改变字段语义须升级格式并兼容已导出的版本。

## 2. 校验边界

- 限制压缩输入总量 1 GiB，JSON 正文展开最多 64 MiB、清单最多 64 KiB；v3 单资源最多 32 MiB、媒体总量最多 512 MiB、最多 2048 项，单图最多 4000 万像素且像素总量最多 5.12 亿；按实际读取字节计数，不信任 ZIP 声明大小。
- 拒绝未知/重复条目、目录与路径、缺失正文/清单、不支持格式/版本、损坏正文、数量不符及未知序列化字段/枚举。
- 各表主键必须唯一；数字主键为正数。消息/事件/摘要必须有所属会话；摘要来源、分段端点、父版本和启用指针不得跨会话或缺失，父链不能成环。
- 调用的 usageId 关系必须存在且一致，不能一份用量被多次关联；保留价格的数值必须有效，旧用量不能为负数。
- 删除会话后仍保留的记忆、用量和调用来源允许悬空；已经删除的人物卡归属也允许保留，不能误判成包损坏。
- 摘要指纹失配与结构引用缺失分开处理：前者保留版本但停用，后者拒绝进入写库规划。
- v3 拒绝未知、重复、非法、缺失媒体条目及不匹配的摘要/长度；附件必须引用已有 USER 消息和包内资源，资源清单必须是实际附件闭包。App 还会核对实际 MIME、尺寸、方向及静态图片格式。
- 调用图片来源若仍能在包内找到原消息，必须属于调用记录的同一会话，并匹配实际附件序号、资源 ID、原件摘要与媒体元数据。原消息已删除时允许历史引用悬空；导入会将其隔离，避免碰巧命中目标设备的消息或媒体 ID。

这些校验用于备份文件完整性与恢复安全，不是每次日常开发的固定验证流程。

## 3. 副本规划

`planBackupImport` 只接收已经通过 `BackupCodec.read` 的包。调用者提供写库事务内取得的消息/事件/用量最大 ID，
函数分配新 ID 并返回 `BackupImportPlan`；它不会访问数据库、调用模型或改变原包。

1. 会话、人物卡、记忆、摘要版本/段、调用与操作号建立新身份。消息/事件/用量按原主键顺序映射，
   保留正文、时间、turnId 和相对顺序。真正写库前，适配层仍须确认新字符串 ID 不与本机记录冲突。
2. 包内人物卡按新身份导入为副本。会话归属明确且人物卡存在时映射到对应副本；空归属或来源卡缺失时保留隔离的待确认归属，不能按默认值或名称合并，也不自动创建“对方”人物卡。用户之后明确修复归属。
3. 原包中仍有效的摘要重建消息/事件指纹、人设校验与段校验，随后再次通过现有摘要校验函数。
   原本失效的版本保持文本和编辑/完成状态，来源人设校验置空、清启用指针，并在 `disabledRevisions` 中提供原因。
4. `PENDING`/`PLAYING` 事件转为 `CANCELED`，不续播。代发消息保持 `sentToModel=false`；
   **所有副本会话列入 `pausedConversationIds`，必须由 app 持久化隔离，不能仅依赖本次内存对象。**
5. 悬空会话/人物卡来源使用 `backup:<导入ID>:missing:<原ID>` 保存原标识并避免匹配本机现有资料。
   已删会话的调用上下文消息号以负数保存原号，不能作为本机正数消息主键使用；再次备份仍可保留。
6. 包中未结束的 STARTED 调用变成 INTERRUPTED，保留已收到的用量并标明不完整，不恢复执行权限。

会话名加“（导入副本）”。每次规划使用新导入 ID，重复导入不会覆盖已有副本；是否已导入同一备份需由 app 持久化来源并在预览中提示。

## 4. Room 与页面适配

**已接入导出**：`BackupDao` 提供不带界面分页和日期过滤的全表查询；`RoomBackupReader.readWithMedia` 在单个读事务内取业务及媒体关联快照，事务外校验并建立不可变文件源。包括归档会话、全部消息/事件、完整摘要版本及分段、已删除来源的记忆/账目，不按最近 400 条或统计范围截取。媒体仅导出消息附件闭包，读取时逐项检查私有原文件。调用状态读取索引列，保留启动收尾已标记的 INTERRUPTED，不把旧 JSON 内 STARTED 当作当前状态。

设置的“本地备份”进入独立页面：说明包含/排除项目 → 整理到 App 私有缓存 → 展示归档大小、图片数量和原图字节数 → 系统选择位置 → 写出 ZIP。准备失败不进入保存；保存位置失败保留暂存以便重试并提示可能留下不完整文件。文件没有额外加密；不打包本机 API Key、价格表和设置。整理之后的新消息不自动补入既有暂存文件，需重新整理。进程意外退出后未承诺恢复导出任务，遗留私有缓存由系统缓存管理，不作为可恢复的备份。

**已接入副本恢复**：媒体先校验并提升至 App 私有对象目录，再由单个 Room 事务插入映射后的业务行、资源、附件、提交及调用媒体清单，同时保存导入来源与隔离标记；事务提交前业务行不可见，冲突/异常回滚，不使用 REPLACE。恢复操作号在同一次重试中固定，已提交则幂等返回；用户再次明确导入同一文件会生成新的暂停副本并复用本机已核验内容。文件提升与 Room 提交之间进程崩溃可能留下无引用私有文件，不会产生半份可见会话。Room schema 未变更。

用户确认恢复后，私有续接记录保留本次 `importId`、备份身份和原 ZIP；页面/进程重建时先查询同一 ID 是否已提交。已提交显示完成状态，未提交可从同一归档续接，主动重新选择并确认备份才会生成新操作 ID。未确认的预览仍属于临时缓存，取消不写入业务表。

- 页面通过 SAF 将所选 ZIP 暂存到 App 私有缓存，流式校验 ZIP 与媒体并在预览前做有界实际图像解码；业务档案只在内存待确认。预览显示来源时间、全部类别数量、旧代发、失效摘要、重复导入与通用记忆。只有明确确认才将归档复制到私有续接目录并调用写库；取消/无效文件不写业务表。
- 所有副本会话持久暂停；控制器在打开、自动补推、后续发送/组合发送、起轮和模式切换路径检查暂停，不伪造 sentToModel、不改全局发送模式。输入禁用并显示只读提示；用户确认恢复后才解除，自动模式可推送旧代发，手动模式仍需按推送。未播事件由规划取消，不恢复播放。
- 导入旧调用及旧用量按行标记，在统计中单独展示，不加入本机新消费；副本会话之后实际产生的新调用正常计入本机。清空账目时同时清理对应来源标记，避免数值 ID 后续重用时冲突。
- 同一文件再次导入会提示先前次数；用户仍可明确建立另一份副本，不覆盖第一次导入。导入记录不是跨设备自动同步或按姓名合并。
- 新导出协议为 v3，v1/v2 仍可读；旧格式写入 API 与旧快照路径仍保留遗漏保护。接口/Key/价格表、其他偏好和头像图片没有包含，须另行配置/补充；通用记忆进入全局范围，人物记忆保持独立副本归属。

**未验证边界**：P3-C 本轮没有实际手机，未走系统文件管理器的恢复选择/确认，也未在真实发布包升级后打开恢复会话；未运行 Android Room runtime。自动用例证明 Core ZIP/映射规则与 App 行转换/旧快照保护，不能替代 Room 真机验证。首次跨安装验证安排：使用合成账户与合成图片生成 v3 包，在同发布签名目标安装中恢复到隔离测试资料，重新打开会话并历史引用图片，核对媒体可读、角色/模型待确认、所有副本暂停、记忆/费用隔离；不得拿真实会话或 Key 做验证。
