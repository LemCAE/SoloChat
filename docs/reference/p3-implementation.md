# P3｜图片多模态与媒体基础：统一方案与实施任务

> 2026-10-26，Sol 定稿。用户已批准本文产品范围及按二级阶段连续实施的方式。基线 `70223f2`，派发前工作区干净。本文规定跨阶段语义与验收，具体类型名、文件划分和内部算法由 Luna 选择。计划不代表已实现或已验收。

## 1. 目标、授权与阶段门槛

完整闭环：用户发送图片 → 当前聊天模型理解 → 历史回看与引用 → 备份恢复。

- JPEG、PNG、静态 WebP；一次明确提交最多 4 张，含从历史引用的图片。检测实际内容，不只信扩展名/MIME；GIF、动画 WebP/APNG 明确拒绝，不静默取首帧。
- 选图只进草稿；用户明确提交才进入原有 AUTO 防抖或 MANUAL 代发。图片、说明及面对面各格文字属于完整提交批次。
- 当前聊天模型优先；能力可靠识别优先、手动确认兜底。不支持或未知不得静默丢图、切服务、额外探测或重试到其他模型。
- 原始导入字节保存在私有持久文件目录；请求发送经过方向校正、尺寸控制及去除位置等元数据的版本。尺寸、质量、窗口与字节预算由实现及定向兼容验证收敛为少量合理默认值，不新增一页调参设置。
- 压缩不额外调用视觉模型或自动生成图片描述；Usage、开始时价格冻结及历史统计沿用 P2，不把 Base64 长度当 Token 或把未知费用当零。
- 不含动画、拍照、AI 发图、表情包收藏/描述维护、生成编辑、音视频、文件解析、OCR 搜索、头像存储改造。现有头像文件仍按原排除规则；P3 必须备份全部消息媒体。
- Luna 可修改代码、做定向测试与本地提交。不得推送、发布、批量删除、操作真实 Key/配置/价格/历史资料、正式包安装或不可逆真实数据迁移。隔离合成 Room 验证可做；设备地址以本次用户授权为准，不沿用旧地址或自行安装隔离包。

验收单位为 P3-A、P3-B、P3-C；每组内部任务连续完成，不逐小任务请求 Sol 放行。Sol 集中反馈并增量复核，技术通过后给同一 Luna 下组授权；用户负责关键 UI 和阶段关闭确认。没有设备/真实厂商证据时明确记欠项，不能声称通过，也不扩大无关测试。

阶段中间保护：A 的本地媒体/输入可验证，但 B 接通前任何需要图片的模型调用必须明确拒绝并保留输入；不能退成文本。C 接通前，含新媒体资料的备份必须明确阻止旧格式导出，不能漏图报成功；无新媒体的旧资料仍可按现有格式备份。P3 完整闭环以前不宣称正式可用。

## 2. 公共数据与存储契约（A 建立，B/C 直接消费）

| 概念 | 稳定语义 |
|---|---|
| MediaAsset | 独立稳定资源 ID；SHA-256、实际 MIME、原始字节数、宽高/方向、内部相对文件键。原始内容不可变；路径不作身份、不导出绝对路径。按原始字节摘要和大小去重，命中时确认本机文件可用且一致；不能按文件名或缩略图去重 |
| MessageAttachment | 所属 messageId、0 起有序序号、mediaId；一条用户图片消息可带 1～4 图及可空说明。历史引用创建新的附件关系，复用 MediaAsset，不改原消息。P3 用途固定为普通图片，未来收藏身份/人物描述与文件分离 |
| InputSubmission | 一次点击的稳定 submissionId、有序文字项（保留 SAY/ACT/SCENE）与附件、内容指纹。持久化 submissionId→有序 messageIds 的关系；相同 ID/相同内容复用原结果，不同内容拒绝，不依时间戳去重。原有纯文本 Message 的序列化形状不增加字段 |
| MediaDraft | 以会话隔离的已导入资源引用、有序图片与配套各格文字；至少支持选图往返、旋转、离页返回。成功持久化的图文草稿可在进程重启恢复；未完成导入不得画成成功。不扩展既有纯文本草稿保证 |
| MediaContextPlan | 有序文本/图片引用块；明确本轮新增/显式引用/近期历史/仅文字标记；携带资源摘要、发送变体规格和预算结果。预览、预检、实际请求使用同一规划规则，实际请求冻结同一清单，不编码 Android Uri 或位图 |
| CallMediaInput | 依附既有 callId 的非秘密图片输入清单（顺序、来源消息/资源、内容摘要与发送变体标识）；不另记费用。只证明请求计划使用了图片，不把认领/HTTP 发起写成“模型看过”。旧调用缺清单仍为未记录 |

### 2.1 Room 与文件一致性

- A-1 一次设计 P3 所需追加表：资源、消息附件、提交映射、图文草稿及调用媒体清单。可合并合理的表/行结构，不增加第二套 sentToModel 状态机。基于 Room v9 追加 v10，保留 schema；既有业务表/行与旧迁移不重建、不回填。B/C 若需改变持久契约，先报告跨阶段和已有 v10 数据影响，不私自重写 v10 迁移。
- core 只放纯数据、规则和端口；app 实现 Uri 导入、解码、文件、Room、网络。MediaAsset 不归属人物，访问权限由消息/草稿/未来人物收藏引用决定；资源去重不允许跨会话自动注入历史内容。
- 导入在 IO 线程流式复制到本次临时文件，按实际读取字节及像素上限检查；识别格式/动画、读取尺寸方向、校验内容后提升为私有不可变文件，再以 Room 事务发布资源和引用。磁盘不足/权限失效/解码错误保留原草稿，不发布缺文件引用。
- 缩略图是有界可再生缓存；大图按展示尺寸解码，不在列表解码所有原图。发送版本有确定规格/变体标识；在途请求固定所用内容，缓存替换或配置变化不能改变在途请求。
- 提交时同事务写该批消息、附件及提交映射，再清除相应草稿；失败不清草稿。只有一个控制器/存储入口写入，防连点/取消重入重复追加。
- AUTO 图片批次可以为资料安全提前保存为未推送，防抖后原子认领，不出现内存和 Room 两份独立队列。MANUAL 仍首次落盘代发、再次推送。纯文本可保留原路径，但必须与结构化批次共用提交/调度边界，不能互相漏掉或重复认领。
- 丢失原文件明确占位并拒绝需要该文件的请求。取消草稿/删会话只解除引用，不立即删除可能共享的原文件。P3 不做全盘媒体 GC；失败清理只处理已核实由当前操作新建且无任何引用/在途使用的文件，禁止删除去重命中的既有文件。崩溃留下的未引用文件可暂留，不可误删用户资料。

### 2.2 输入与重试

- 图片附着于同批 SAY 消息（无 SAY 文字时允许空正文图片消息），ACT/SCENE 按既有类型保存；不把路径、Base64 或“[图片]”占位写成用户原话。同批文字顺序保持，图片顺序独立明确。
- 图文全批准备成功才提交；选图本身不打断播出。提交后的 AUTO 插话和 MANUAL 第二次推送沿用原时机；预检失败不能认领待发、清草稿或丢掉一部分附件。
- 单次点击最多 4 图不等于防抖/手动积累后只能有 4 图。待推送合并批次必须在认领前验证整体预算；超限原批保留并明确提示，不截断、拆成多个收费调用或无限等待。请求预算优先保证本轮全部新图/显式引用，剩余才给历史。
- 当前错误卡只有关闭/设置/日志，未提供完整显式失败回合重试。P3 补充媒体失败重试入口，基于已保存 submission/messageIds 发起新调用，不再经过用户消息追加入口；每个实际请求仍有独立 callId。重试不复用失效凭据；重新预检并冻结当次配置/价格，保留原输入身份和顺序。
- 只允许明确失败且尚无已出口回复的媒体输入重试；SUCCESS/SILENT、用户取消、已有出口或后来已开始新输入时不重放旧回合。重启后不能把 STARTED 当作必然失败或自动重发（接口可能已收费），提供明确未完成状态并由用户选择。常规问题由 Luna 自主处理，不能改成自动收费重试。
- 输入含附件时不把配套 `/system`、`/compress` 等文字误当控制命令；控制命令解释只沿用原纯文本入口。调试/网关若支持图片必须复用同一入口；暂不支持的入口须明确拒绝图片，不伪装 UI 等价成功。

## 3. 视觉调用、来源与计费契约

### 3.1 能力、请求与上下文

- 在原 RegistryModel/ModelDefinition 的稳定身份上补视觉 SUPPORT/UNSUPPORTED/UNKNOWN 和来源，旧文档缺字段为 UNKNOWN。复用原 READY 发布、revision/CAS、用途解析和 PreparedAgentCall，不改 P2-B pricing、旧价格资格或升级准备身份。
- 自动能力只采信已核验的提供商官方 endpoint＋具体型号声明；自定义/中转同名不套用官方声明，手动确认可覆盖。只有原图将实际附入请求时才要求支持；纯文本及只含历史图片标记的请求仍可用。
- ApiMessage 可小型扩展为文本/有序内容块，旧文本调用构造及最终 JSON 保持兼容。保留现有“一份带时间戳聊天材料”的布局，在所属图片记录位置插入图块，不顺便重写为整套 role 交替历史；system 稳定前缀逐字节与 stablePrefixChars 口径不变。
- OpenAI-compatible Chat Completions 使用 text/image_url data URL；图片只在 app 传输层解析文件和编码。不得将文件路径传给远端、建图片托管、改 Responses 或引入通用多模态插件框架。具体兼容参数只按可核验文档发送。
- 历史有限窗口＋图片数＋发送字节/像素预算，按确定顺序选取；新增/引用图片不可省略，历史图片超预算降为明确“本轮未附原图”的标记。较早、压缩范围内的图不因全历史文本默认不限而无限重传。当前图片能力不明时不静默移除既已选择附图的内容。
- 来源/发送变体清单、模型能力和 PreparedAgentCall 在同一会话串行边界下准备，并在认领前验证；准备期间出现新提交/配置变化则重新准备或拒绝旧计划。不能先按旧清单检查，再从最新队列认领另一批。
- 请求图文清单含缩放后的发送内容，UI 不称其为逐字节原图；近期窗口仅表示本轮选择附图，不宣称模型持久记住图片。日志仅打印媒体 ID/尺寸/大小/状态，不打印 Base64、二进制、临时内容 URI、凭据或完整含图请求体。

### 3.2 摘要与旧版本

- 保留现有 Message/SourceFingerprint 的旧序列化和无附件指纹算法，旧摘要校验逐字兼容。附件通过独立关联读取，不把默认空字段加进旧 Message 序列化后再算旧指纹。
- 对含附件来源定义明确版本化的扩展指纹：既有消息内容＋有序附件的不可变资源内容摘要/必要语义；不含缩略图、缓存状态、绝对路径、后来补充的描述或历史窗口选择。同图重引用是新消息关系，不改旧来源。
- ContextPlanner、CompressionService、压缩来源生成/验证和备份导入必须共用同一附件感知指纹入口；缺附件时不能误用旧算法将新来源洗成有效。A-1 先稳定该数据/函数契约，B 接入运行，C 重映射使用。
- 压缩只处理已有文字、图片标记和可靠聊天信息，标明没有重新查看图片。不额外看图、不补造图片描述。应用摘要不删原图；撤销摘要可按普通预算重新选择原历史图。
- v3 导入先校验原包来源有效性，再对新 messageId/资源引用重新计算合法来源和段摘要；无效来源保留停用，不能重映射后变成有效。v1/v2 的有效与失效判定保持原样。

### 3.3 用量与成本

- call_record、调用配置快照及图片输入清单在同一首写事务中关联，已有完成记账入口收尾，不重复造 usage 或按图片数额外加费用。
- 接口返回输入总 Token 足以表达本次全部输入且规则适用时，复用冻结 R4 规则；缺图 Token 口径时不把文本估算当完整输入量。纯文本沿用原估算，含图缺总用量时输入为 UNKNOWN，文本估算只能单独说明。
- 缺失价格/用量或存在尚不能表达的媒体计费项，完整费用保持未知；统计计入缺失数量，不显示为已知零或将部分费用标为总价。保留原 usageFrames 和旧账目，不从今天的模型/报价反推历史。

## 4. ZIP v3 与副本恢复契约（A 预留，C 实现）

- 新写 v3，继续严格读取 v1/v2；旧格式不允许夹带新媒体字段/条目。价格交换 JSON v3 与备份 ZIP v3 是不同格式，不混用。
- manifest/data.json 延续原业务协议，增加资源、消息附件、提交映射及调用媒体清单；草稿不是聊天历史，不纳入备份。只导出快照实际需要的消息原图，每份内容一份媒体条目；缩略图/发送缓存重建，历史调用清单只保留元数据，不强制保留已删会话的图片文件。
- 媒体清单记录资源 ID、摘要、实际类型、尺寸/字节数与受约束的内部条目键。内容摘要是跨包校验依据，媒体 ID 不是目标本机可信路径。备份是全部消息媒体的闭包，不导出本地无引用垃圾文件。
- 压缩输入、单条展开、媒体总展开、正文、数量及像素均有界，按实际字节计数；采用文件流，不把整个媒体 ZIP/Base64 放进内存。拒绝重复/未知条目、缺失、摘要或类型不符、路径穿越及悬空消息附件。阈值由合理设备预算决定并注明，不照搬当前 64 MiB JSON 限制作为整包上限。
- 导出先取得一致业务/媒体引用快照，并固定所需不可变文件；后续新消息不补进既有快照。源媒体缺失/损坏时明确失败，不报完整成功。失败保留既有可重试暂存语义，不更改原资料。
- 恢复先有界暂存完整文件并校验所有关系，预览确认前不发布业务数据；确认后先使本次不可变文件可用，再 Room 单事务写副本/新 ID 关系/来源/暂停标记。文件与 Room 不能假装同一物理事务：崩溃时以“无业务行则不可见孤立文件；有业务行则所需文件已存在”为不变量。
- 复用已核验本机相同内容文件可去重，不覆盖任何既有文件；不同内容绝不复用身份。消息、会话、提交及附件映射均分配副本身份；重复导入创建独立暂停副本，可共用底层文件，不重复旧账单参与本机费用。
- Room 提交前故障：无可见副本；提交后/返回前故障：恢复状态能依据已提交 importId 判断，不再次写同一操作。用户重新主动导入仍是新的副本操作。仅清理本次新文件，保留共享及既有文件。
- 继续不备份 Key/提供商设置/价格配置/日志；保留有效人物映射、缺人物待确认、本机模型待确认、暂停及记忆/费用隔离。旧调用来源允许按现有语义悬空；它不同于必须存在的消息附件引用。

## 5. UI 范围与验收基准

沿用现有 Material/Compose、颜色、字体和密度，参照 mobile-android-design；不改全局视觉。Luna 可直接制作局部 Compose Preview/实现，不要求另做多套 HTML 方案。关键画面在 A 报告集中交用户验收，不逐组件等待。

| 位置 | 必要行为 |
|---|---|
| 输入区 | 单一附件入口、最多 4 图预览、删除/补选、图文一起提交；导入中/失败明确，控件对齐。复用系统 Photo Picker/文件选择，不索取整个相册权限；回退多选也在 app 校验数量 |
| 草稿与发送 | 选图不提交；成功交给控制器后清相应草稿。手动代发与已推送可区分；能力/预算/资源拒绝保留整批，失败重试入口在 B 接通 |
| 消息与历史 | 单图/多图、长图、透明图、混合说明；无 OCR。列表摘要“[图片]＋文字”；搜索只搜文字，定位页、大图沿同一附件读取。加载按当前页有界批量读取，避免每条附件单独扫库 |
| 大图 | 缩放/返回、另存到设备、引用到当前草稿。另存成功才提示成功；取消选择无写入。历史定位页引用不获取运行控制器、不自动请求，明确目标会话并走导航/草稿接口 |
| 边界 | 未导入/缺图/损坏不画成空白成功；普通图不出现已实现的收藏管理入口。正常字体、现有明暗主题局部检查，不重验 P1 全 App |
| 备份 | 数量/体积、准备与保存、缺失失败、恢复预览/暂停状态；减少技术说明，不新增冗余设置 |
