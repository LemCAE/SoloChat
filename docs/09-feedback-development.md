## 1. 先处理行为正确性

1. **发送冲突**：用户观察到模型发送消息时用户发送可能冲突。先沿 `SessionController` 的手动代发、push、自动插话、播出落定、旧 turn 取消链定位，补能复现具体现象的定向用例；只修复实际证明的竞态，不重写整套控制器。
2. **直接模式切换**：`/system` 用于切换面对面时应直接执行模式切换，不先保存系统消息再等模型解释。明确命令形式和普通系统记录的边界；复用同一控制器与唯一写入规则，不制造假用户气泡。模式切换是否自动开场、忙碌时行为须按源码核实并在 UI 明示。
3. **等价调试接口**：新增调试入口必须复用 UI 的同一控制器/命令调度，包含代发、push、插话、模式和状态；旧 `TestGateway.send` 跳过控制器的路径不能宣称 UI 等价。沿用日志服务鉴权、明确指定目标会话并防重复提交；接口面向已有会话通用复用，测试过程仍只使用专用测试人物/会话，不删除或重置旧资料。模型交互可经接口完成，布局、键盘、选图等仍用 UI 检查，不新增无必要的探针或门禁。
4. **专用测试人物**：建立明确配合测试、按指令切换/短回复、不写通用记忆的独立人物卡。当前已创建 TEST-UI-1022 人物/会话；第一轮英文请求未得到模式提议，后续先完善测试人设，避免盲目反复请求。此前获准约 1～2 次短调用，当前实际已执行 2 次；新调用按用户当前授权与必要范围控制。

5. **离页续聊与界面同步**：会话控制器由应用按会话持有，聊天页面只订阅同一实例。返回首页、进入其他人物或设置不取消已开始的生成/播出；接口也获取该实例，重新打开会话可观察真实测试进展。不得重进页面时再次初始化并重复推送。明确删除时先取消并等待收尾再删记录。当前目标是应用进程内的导航连续性，不将此扩大为系统杀进程后的自动恢复承诺。

## 2. 界面调整

- **首页**：标题栏与会话区域的对比更明确；按人物卡分组，先选人物，再显示该人物的多个对话。不得改会话真实归属；`resolvePersona` 只认明确有效的关联，缺失人物需用户选择，不自动回退。新建入口须明确创建给谁，不引入第二套会话数据。
- **聊天顶栏**：适度弱化冗余内容和操作，保留会话识别、进行中状态、返回及设置入口；图片头像小尺寸呈现。
- **人物编辑**：多行文本框有最大可见高度（优先用 maxLines / 内部滚动），长内容可以在框内继续滚动编辑，保留外层页面滚动、键盘避让与原八段映射。
- **价格页**：首屏只显示当前有效模型的价格与匹配/兜底状态；完整价格表移入子页，按服务商/模型归属筛选或分组。用户自建模型归属不可凭名称强行判定，不明项明确未分类；原表切换、逐模型峰谷、全局自填、两层草稿与历史冻结规则继续保留。
- **统计**：已参考 RikkaHub 完成今天/本月/累计范围、指标网格、按模型调用次数分布。后续根据实际反馈细化，不借此补造历史用量或命中率。
