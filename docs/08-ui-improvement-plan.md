# UI 改进计划

> 2026-10-22 初稿按用户要求先规划；后续已开始分批实施，当前状态见 §7。
> 判断来自当前源码与 Rikkahub 对应组件的阅读，不将源码观察写成实机观感结论。

## 1. 方向与范围

方向：**安静、清晰、以人物和聊天内容为中心**。延续现有靛蓝主色、冷灰容器与明暗主题；借鉴 Rikkahub 的分组、信息层级和操作反馈。先整理常用路径，不新增主题商店、底部多标签导航、复杂动画或桌面/平板布局。

目标是让用户更容易找到功能、读懂当前状态和完成编辑。保留 chat/scene、逐条播出、三格草稿、手动两段发送和设置分组保存；不借 UI 调整改模型上下文、人物卡归属或历史费用。

## 2. 当前问题与处理方式

| 源码中的现状 | 改进 |
|---|---|
| `SettingsScreen` 主菜单平铺；“本地备份”作为新增项排在最前面，常用设置与排查入口缺少分组 | 按聊天、资料、应用分组，常用项优先，说明控制在一行 |
| 聊天使用 `CompactTopBar`，部分工具页使用标准 `TopAppBar`，缺少两类页面明确的统一约定 | 聊天保留紧凑双行标题，工具页统一标准标题、返回与操作位置 |
| 会话行没有独立头像区，人物、模式和时间拼在同一条副标题 | 头像独立，时间靠右，标题与人物/模式分层；最近消息预览需要查询支持，另一步接入 |
| 价格页有表选择、四个管理按钮、搜索、分页及全局兜底；模型编辑使用长表单 `AlertDialog` | 表管理收进菜单，模型列表简化；长编辑改为独立页面，短命名/删除继续用弹窗 |
| 人物卡每行展开多个操作，记忆也常驻“固定/改/删”按钮 | 保留一个主要操作，其余归入更多菜单；危险操作仍明确确认 |
| 最近调用的每张卡重复解释缓存/推理计费口径 | 页面集中解释一次，默认列表只显示摘要，详情再展示来源和完整字段 |
| 备份页逐行显示十项数量，首次进入仍以说明和整理按钮为主 | 展示核心数量和明确主动作，其余数量可展开；恢复完成后再形成导出/恢复两组 |

## 3. 统一视觉与交互约定

以下为设计初值，实施时用正常字体实际调整，不作为固定像素验收门槛。

| 项目 | 初始约定 |
|---|---|
| 页面边距 | 通常左右 16dp；段落间 16～24dp；同组项间 8～12dp |
| 字级 | 页面标题沿用 Material 标题级；正文约 16sp，辅助说明 14sp，时间/元信息 12sp；正文不用小字承载 |
| 容器 | 页面底色与分组表面形成轻层次；组外圆角约 16～20dp；组内用留白或细分隔，不为每一行单独套卡 |
| 颜色 | 主色用于主要动作、选中和少量强调；错误与警告用已有语义色；明暗槽位成对调整 |
| 图标 | 同一套 Material 图标与尺寸，替换“备份也用扳手”等语义不符项；装饰图标不添加重复朗读说明 |
| 触摸 | 常用操作优先 48dp 触摸范围；聊天输入区的视觉高度与触摸范围分别处理，不直接把整条输入区加厚 |
| 主要动作 | 同一视区一个主要动作；次要动作使用文字/描边或菜单；删除不与保存并排同等突出 |
| 长编辑 | 独立编辑页，顶栏保存；短选择/改名/确认使用弹窗或底部面板，具体形态按内容长度选 |
| 反馈 | 工作中显示简短状态并防重复提交；普通成功用短提示，错误保留可执行的重试/修正入口 |
| 空状态 | 一句话说明空在哪里，加一个当前可用动作；尚未实现的功能不显示可点击占位 |

先提取实际复用的分组容器、设置行、状态说明、危险操作确认；不先建设组件 DSL、完整设计系统或全站状态框架。新组件使用当前 Compose/Material3 依赖，不因参考库用了更新组件就升级技术栈。

## 4. 页面方案

### 4.1 设置：先把功能放对位置

建议结构如下。现有入口先整理，再按需要接通同一既有页面；不复制另一份保存逻辑。

```text
设置
  聊天
    接口与模型       当前默认模型 / 尚未配置
    节奏             常用节奏参数
    聊天行为         发送方式、模式提议与等待
  资料
    人物卡           管理与导入导出
    记忆             通用与人物记忆
    模型价格         当前价格表 / 自填兜底
    用量统计         已有统计页面
    本地备份         导出；恢复接齐后再显示恢复入口
  应用
    版本信息         GitHub 更新实现后改为“关于与更新”
    排查与日志       文件日志、日志网页
```

“价格与统计”改为更准确的“模型价格”，统计仍进入已有统计页。首次整理可保留主页更多菜单的原快捷入口，避免用户原路径突然失效。

设置子页保持顶部保存与离页草稿提示：未修改时不突出保存；保存成功不把旧提示永久留在页面。接口页把连接/认证、模型选择、生成参数分组，测试连接和获取模型放在对应组内；只保存当前分组，不改现有请求语义。

### 4.2 模型价格：先选表，再选模型，再编辑

页面顺序：计价模式 → 当前表选择与更多管理 → 搜索/新增模型 → 模型列表；全局自填兜底收在独立说明明确的区域。

- 表的复制、改名、删除归入更多菜单；新增保留明确入口。切表、改表仍先改本页草稿。
- 模型行显示模型 ID、标准输入/输出价与峰谷状态；缓存价、来源、备注到详情查看，不把所有字段挤进一行。
- 模型编辑改为独立页：模型 ID → 标准/谷价 → 峰谷开关 → 开启后展开峰价/时段/时区 → 备注与来源。缓存单价设置在对应价格组内。
- 编辑页“完成”只应用到价格页草稿，价格页“保存”才生效；取消/返回不丢其他模型的草稿。文案明确两层作用，不暗改为即时保存。
- 数字单位固定在组标题或字段辅助信息中，区分“缓存随输入”“缓存免费”；峰谷默认关闭、历史费用冻结规则不变。
- 首步保留现有搜索与分页逻辑，只换布局；不顺便改计价或引入大表格。

### 4.3 会话列表：让人物成为识别线索

左侧使用现有 emoji/头像的独立区域；中间显示会话标题与人物信息；右上显示时间，模式用低强调标识。标题优先，不让附属信息挤占全部宽度。

新建仍先选人物卡；选择列表显示头像、名称与短简介。改名、换人物、删除保留在会话菜单，删除补清晰确认；不让整行长按成为唯一操作方式。

**最近消息预览另一步实施**：需要批量读取每个会话最新可见内容，不能每行扫描全历史。只取用户记录或已出口的助手事件；PENDING、取消内容和记忆指令不进预览。它是带数据查询的功能，不能作为纯样式替换顺手加入。

### 4.4 聊天页：集中处理标题、状态与输入区

- 保留紧凑顶栏。会话标题是主行，人物和模式是辅行；状态区域保持固定占位，避免生成/播出切换让标题抖动。
- 现有等待输入、生成、播出三种状态仍分开。改善状态文案位置和一致性，不统一成一个无区别转圈。
- 气泡统一正文、内边距与连续消息间距；保留现有逐条时间戳，不改为按组隐藏。动作/旁白保持单独语义色和留白，不套成另一种普通气泡。
- 输入区优先保证光标、键盘避让、底部贴合与发送按钮对齐。scene 的“说/做/景”改为清晰的紧凑分段选择，三份草稿仍独立保留。
- 手动发送模式保留“写入气泡”与“推给模型”的两步含义；有代发时提供可读的数量和推送含义，不只靠按钮变色表达。
- `/system`、`/compress` 等推荐用统一动作面板呈现，不新增模型切换、附件等尚不在本批范围的输入工具。
- 错误只展示简短原因和一个首要恢复入口，日志入口放次级操作；不改变自动重试行为或制造重试承诺。

### 4.5 人物、记忆、统计与备份

| 页面 | 整理方式 |
|---|---|
| 人物卡 | 名称、头像、简介形成主信息；编辑是主操作，复制/导出/删除收进更多。编辑页按身份、表达、场景素材、边界与秘密分区，仍映射原八段，不合并其业务含义；导入预览继续单独确认 |
| 记忆 | 归属筛选置顶，通用/当前人物清楚标识；正文优先，固定状态轻量展示，编辑/删除收进菜单。共享规则集中说明，不能因视觉压缩变得不可见 |
| 用量 | 总览展示费用、输入/输出与缓存；未知/估算仍明确标识。调用列表默认精简，点开看完整口径和来源；计费说明集中一次展示，不重算历史金额 |
| 备份 | 导出动作与摘要预览分层；会话、消息、人物卡、记忆等核心数量先展示，事件/分段/账目等展开查看。包含/排除与未加密说明保留；恢复完成后独立展示文件选择、预览与确认 |
| 关于与更新 | 当前版本/安装渠道常驻；检查、下载、安装按真实状态切换。遵循 06 §11，未实现前不做假按钮；更新说明允许折叠，失败不伪装成“已是最新” |

## 5. 实施顺序与完成条件

| 批次 | 交付 | 必要检查 |
|---|---|---|
| UI-1 · 基础与设置 | 少量共用间距/容器、设置分组、工具页标题规范；先以设置页确认视觉方向 | 正常字体下查看设置主菜单与一张子页；涉及配色再补明暗，不触发模型请求 |
| UI-2 · 价格编辑 | 价格页层级、表管理菜单、独立模型编辑页及草稿往返 | 新建专用测试表，检查编辑/取消/回到价格草稿/保存；只在保存逻辑确有变化时跑相关用例 |
| UI-3 · 会话与聊天 | 头像与信息层级、输入区、scene 分段、手动推送反馈 | 专用测试会话检查键盘、草稿切换、手动两段及正常播出；控制器/投影未变则不整套重验 |
| UI-4 · 资料与工具 | 人物卡/记忆操作收纳、统计详情、备份展示；更新页面随真实更新功能落地 | 只走实际修改路径，涉及删除用独立测试资料；不重做之前已确认的文件保存和价格规则 |

会话最近内容预览随历史查询阶段接入，不阻塞 UI-3 的纯呈现改进。UI-1 是下一次实际界面改动的起点；备份恢复/GitHub 更新的业务顺序仍按 06 执行，可与对应工具页整理衔接。每批单独交付与提交，不把四批攒成整站重写。

本方案不要求先做三套主题、截图归档、快照测试、百轮对话、性能基线或全仓测试。共享交互、持久化或状态流转确有变化时才增加相应定向回归。修改源码前仍先读 02 §3；每批完成如实记录实际检查与未确认项。
