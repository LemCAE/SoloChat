### 2.1 P2-A｜提供商与模型体系（技术已关闭）

**改造前差距与复用**：旧 `ApiProfile`/DataStore/SecretStore 按组保存连接、目录和价格；全局接口组及只有请求名的会话 `modelOverride` 限制了用途选择。现已接入唯一 READY v2 来源、稳定身份与独立用途解析，复用原密钥存储、配置/会话锁、`ChatConfig`、`RequestEndpoint` 和独立记账，不重建计价引擎。新增 provider/model 使用 UUID，新 Key 槽位独立分配；旧配置升级保留原身份与槽位。

**定稿的数据边界**（类型名可按代码习惯精简，语义不变）：

| 数据 | 边界与语义 |
|---|---|
| Provider | `id/name/baseUrl/keyId/protocol`；原组 ID 与 Key 槽位沿用，首版协议仍为 OpenAI compatible；同品牌旧组不按名称/地址自动合并 |
| Model | 稳定 `modelId/providerId/displayName/requestModelId`；同提供商同一实际请求 ID 原则上只保留一个配置模型，跨提供商同名完全独立；请求 ID 保留原大小写，不以价格键或显示名替换 |
| ModelSelection | 全局默认、聊天/压缩/标题用途保存模型引用；区分“继承/未设置”“显式引用”“待确认旧引用”，不能把失效引用转为空值；未启用标题逻辑不参与聊天/压缩可用性判定 |
| ConversationModelBinding | Room 追加以会话 ID 为键的关联表，存新选择/待确认及迁移来源；不改原 `conversation.modelOverride`、消息、事件和摘要行。v2 生效后旧字段只作来源说明，不再作为运行时兜底 |
| ResolvedCallConfig | 选中模型、提供商、继承来源、能力、连接与价格规则的不可变快照；继续交给原 `ChatConfig`/请求及计价链路。含凭据对象必须隐藏日志输出，不能默认打印整个配置 |
| ModelThinking | 模型上的聊天思考 `mode=AUTO/ON/OFF`、可选 `effort`；压缩为独立用途策略，本阶段固定 OFF，不读聊天思考。另存模型协议能力及来源；调用开始冻结意图、用途来源与实际参数 |
| CallConfigSnapshot | Room 追加与 call_record 一对一的非秘密配置快照；旧 call_record 行原样保留。通过既有记账入口同事务写入，新备份带可选快照；旧记录缺失即“未记录” |
| 能力状态 | 先有文本/视觉的支持、不支持、未知及来源；旧模型视觉能力默认未知，不按名字猜。未知不妨碍原有文本聊天；视觉限制在图片阶段接入，不增第二视觉模型 |

模型/提供商元数据与全局/功能选择放版本化 DataStore 文档，密钥仍仅在 SecretStore；会话关联放 Room，因为它属于会话且需随副本备份。比把提供商、密钥、所有偏好都搬进 Room 的方案小；不把每会话选择塞入设置的大字典，也不在旧模型名中编码新引用。

**标题生成与思考配置（本轮补充）**：

- 模型用途增加可配置的“标题生成”，复用聊天/压缩的统一选择器、继承来源显示及保存机制，默认继承全局，可单独指定模型；P2-A 保存独立用途偏好，但暂不接入标题生成逻辑、调度或额外调用。此未启用用途的失效选择不得阻止聊天/压缩或被当作实际调用记录。
- 聊天默认 AUTO，省略思考控制字段并遵循模型默认；用户可明确 ON/OFF，支持时再选真实强度档位。旧全局 `thinkingEffort` 原来仅将 OFF 转 false、其他档位转 true，迁移仅保留其原作用模型：空→AUTO、OFF→OFF、其他有效值→ON 且强度未指定，不能凭旧档位制造以前未发送的 reasoning_effort。未知/不兼容旧值待处理，不扩散给其他旧组/新模型。
- 聊天和压缩分别控制：压缩本阶段始终使用独立 OFF，模型用于聊天时的 ON 不影响压缩；本轮不新增压缩思考设置 UI。未来增加专用设置时优先于压缩默认，不能引入对聊天设置的继承。
- 思考能力采用自动识别优先、手动配置兜底：自动适配只采信已知厂商/具体模型的可靠声明，不能只按模型名猜；允许用户手动覆盖能力与有限参数方言，以支持自定义 API/中转站。能力未知时 AUTO 可用；显式 ON/OFF 必须有已确认能力，不能静默忽略或改写用户意图。A-8/9 已提供内存草稿设置，持久化留 A-10。
- 模型无法关闭或协议能力未确认时，不伪装 OFF 成功、不省略参数当关闭，不静默换模型/服务；返回明确原因，阻止这次压缩/显式 OFF 请求。保留待发与压缩原文/原启用版本，让用户修正配置或选择另一个已配置模型后重试。不通过收费探测或仅按模型名猜能力。
- 沿用 OpenAI-compatible Chat Completions 客户端，仅增加小型、可测试的参数适配：输入为提供商协议配置 + 具体模型能力 + 冻结的思考意图，输出为请求字段或明确不支持。支持开关与支持强度分开；只展示有来源的档位，不把 low/high 等强度近似成 token 预算，不同时发送互相冲突的方言；不新增 Responses/原生 SDK/通用插件引擎。
- 核对依据：[DeepSeek](https://api-docs.deepseek.com/guides/thinking_mode/) 的 Chat Completions 使用 `thinking.type` 与 `reasoning_effort`；[百炼](https://www.alibabacloud.com/help/en/model-studio/deep-thinking) 的控制方式因模型而异，部分支持 `enable_thinking`、部分不能关闭；[OpenAI](https://developers.openai.com/api/docs/guides/reasoning?api-mode=chat) 支持项也依模型而定。2026-10-25 核对，仅作为首批适配依据，不能把一个模型的档位套给同名的其他渠道。实现时按实际目标型号及接口再核对。
- 复用 `CallRecord.reasoning`、`measuredUsage`、SSE usage 解析及计价，旧记录不回填。调用明细分开发起时配置与接口返回推理 Token，旧配置显示“未记录”，缺用量显示“未知”，不由 ON/OFF 推断实际用量，不重复把 reasoning 加到 completion 计费。正文不新增展示、持久化、历史查看或回传路径。
- 定向验证：AUTO 前后请求兼容、旧显式值/压缩默认、不同协议字段、模型专属档位、不可关闭及未知能力、配置在途冻结、用量缺失与旧备份记录。沿用现有网络对象/用量用例，不为此搭建新测试设施。

**解析与调用**：

- core 提供一个纯选择解析入口，返回明确结果或失效原因；app 用同一已发布配置版本装配凭据及 `ChatConfig`。`ContextPlanner` 取聊天结果，`CompressionService` 单独按压缩继承链取结果；摘要预览到生成之间配置变化，沿用现有重新预览规则。`deps.config()` 中仍可沿用共享行为参数，但不再代表全局当前连接。
- 同一会话锁内，配置校验与 AUTO/MANUAL 输入认领采用同一解析结果；配置失效不先把待发标为已推送，再到 runner 才发现无接口。冻结结果传至执行器，不在构造请求或重试时另读当前默认。保持既有发送节奏与一轮一次调用。
- `SoloChatApp` 复用发布锁：构造并校验候选，持久化后一次发布；保存失败不显示成功。删除/失效须发布阻止调用状态，不继续使用已删除的旧服务；已发起的请求保留原地址、Key、请求 ID 和开始时价格，Key 清理不影响持有快照的请求。
- 设置、聊天标题/设置、压缩预览都显示同一解析结果及继承来源；统一选择器读取各提供商已配置模型，获取远端目录不会选默认或自动发请求，目录遗漏不等于手填模型无效。新调用可加可空的提供商/模型身份快照；旧 `call_record` 与费用不回填、不改写、不按当前提供商重分账。
- 涉及模块：`ApiProfile/SettingsStore/SecretStore/SoloChatApp`，`Conversation` 新关联及 Room 适配、`AgentDeps/ContextPlan/CompressionService/AgentTurnRunner`，`SessionController` 认领边界，`ChatScreen/ConversationSettingsScreen/SettingsScreen`，备份编解码与导入映射。网络 SSE、提示词稳定前缀、播放器和 token 计费口径保持原样；仅增加明确配置适配，不引入通用多提供商引擎。

### 2.2 P2-A 迁移与备份：定稿保护边界

当前 Room 源码为 **v8**（AGENTS 表格的 v7 已滞后）；首轮合并追加会话关联、调用配置快照两表，升级到 v9，旧业务表不重建/回填。DataStore 写版本化 v2，旧键/旧组只作迁移来源和恢复依据，Key 槽位沿用。迁移只建立未来请求的明确对应，不推断历史归属。

| 旧情况 | 建议映射与保护 |
|---|---|
| 已保存接口组 | 一对一成为 Provider，保留 ID、名称、连接及原价格。相同品牌/地址也不合并，不搬动 Key |
| 原有效组有默认模型 | 全局默认映射到该组同一请求 ID；聊天/压缩功能覆盖初始为继承。原无有效选择或默认为空，仍保持未配置，不选第一组/第一个目录模型 |
| 会话无覆盖 | 新选择为继承；不因历史出现的模型名称生成会话指定 |
| 会话有模型名覆盖 | 按最新决定，旧有效组明确且原请求名有可靠对应时自动绑定该组合，只保留下一次请求的原行为，不宣称这是历史提供商；有效组缺失、引用失效或无法可靠确定时单独要求选择，不能跨组同名猜配 |
| 默认/会话手填模型不在目录 | 为原来明确指定的名字建立稳定模型记录；凭据/地址缺失依然阻止调用，不因补记录而激活新服务 |
| 同名、大小写或失效配置 | 跨提供商身份分离；实际请求名不规范化。保留不可用关联及原因，不按目录顺序/相似名字修复；价格大小写碰撞留给 B 显式处理 |

**跨存储的一致发布**：在应用启动配置门闩和既有发布锁内保存带迁移 ID 的原始源快照、稳定 ID 映射及待发布 v2 草案；迁移期间不允许新建运行请求或并发修改源设置。然后 Room 单事务追加会话关联，最后 DataStore 一次发布 v2 ready，才放行新解析。中断重启使用同一草案/ID，只补缺失关联；已有行必须一致，冲突则停止并说明，不能 REPLACE 或生成第二套身份。发布后不再读取 v1 做静默兜底；迁移失败允许浏览旧聊天与修复配置，不能自动请求旧/别的服务。

配置转换只在存在 v1 且未完成升级时运行；全新安装与 ready 用户不出现升级页。确定项自动发布，歧义项以 unresolved 发布并只阻止受影响的调用，支持稍后在该会话设置修复；记录稍后处理状态，不每次启动反复弹升级向导。实际存储失败不伪装为部分成功，也不将失败字段置空触发继承。自动转换只保留原请求行为，不自动启用新服务。

迁移前保留一致数据库副本及旧偏好；后按主键逐行核对既有业务行改动/消失为零，新增关联另计；Key 不进明文迁移清单。保留源数据是可恢复依据，**不承诺安装旧 APK 就能正确读取新选择**；v2 已编辑后，回退须有明确恢复/转换流程，不能用运行时双读伪装兼容。

**备份兼容属于 A**：新增 ZIP v2，继续读取严格校验的 v1；副本导入同时重映射会话关联及调用配置快照，不按原 modelId/同名自动关联目标安装的提供商。接口/Key/用途偏好仍不导出；仅附非秘密的原选择说明，所有副本保持暂停，用户明确选择本机模型或“继承本机默认”后才能恢复发送。v1 的裸模型名同样待确认；旧调用的冻结价格/字段来源原样保留。缺失人物保持待确认，恢复提供明确入口；现有无卡时自动创建“对方”的路径须移除，不只改旧失败用例。原备份内有效人物 ID 自动重映射为副本，不合并本机真实卡。

快照重映射只关联新的 callId/会话副本；其中旧提供商/模型身份是来源说明，不注册为本机服务、不获得本机旧兜底资格。历史思考参数/价格不应用到恢复后选择的模型，未来请求仍按目标安装的明确配置生成。

旧兜底价的适用范围也属于 A 的身份边界：迁移时记录其原有模型关联，装配调用配置时限制适用资格；新增模型/新提供商没有资格，价格未知就保持未知。不能因为 B 尚未改价格页，就让 A 新增的模型沿用旧提供商兜底价。

**A 的交付顺序**：已确认方案 → 纯数据契约/解析 → 配置存储与升级计划 → Room 追加结构 → 幂等升级与 v1/v2 备份 → 请求方言/独立思考 → 调用冻结与价格兼容 → 选择器/用途 → 提供商详情 → 升级/恢复页面及最终启用。首批详细任务与后续依赖统一放 [实施任务](reference/p2-a-implementation.md)，不在多个文件重复任务书。中间数据/接口任务保持不启用 v2；调用入口、备份和修复 UI 全部就绪后才一次切换，不能让旧运行器消费新引用。

### 2.3 P2-B｜一份生效价格与参考库

**差距与复用**：当前每组有 `PriceCatalog(selectedTableId,tables)`，`useOfficialPrice` 决定是否读表，另有本组兜底单价；匹配是小写请求 ID + 快照后缀。`ReferencePrices` 已独立保留渠道/日期/来源/适用条件，但采用是整表复制。继续复用 `ModelPriceEntry/PriceRates/PriceSchedule/PriceTier`、`resolvePriceEntry`、调用开始冻结全部档位及 `recordedCost`；只改管理、关联、格式与编辑适配，不写第二个计算器。

**建议结构/迁移**：每个 Provider 一份 `ProviderPricing`，其中 `modelId → R4 报价规则` 是正式模型报价；保留独立只读的旧表存档和未关联旧报价，参考库始终不参加运行时选择。规则对象原样承载缓存、整档阶梯、峰谷、日历及币种单位；模型请求身份与规则内旧模型键分开，使用小适配层调用现有计算器。

- A 内先原样保留各提供商旧价格及编辑器，只给价格入口传明确 providerId，不再依赖全局当前组；这样 A 可独立交付。B 才执行价格迁移。
- `useOfficialPrice=true` 时按旧解析实际生效的表/精确或后缀匹配，为所有当前配置及会话引用模型复制完整规则。关闭读表时，不能把选中的旧表启用；旧本组自填价按原“已配置”语义迁入兼容默认规则。表缺失、`priceCatalog=null` 的随包快照路径、未匹配及未知价均按旧计算结果处理，并显示迁移来源。
- 非生效表、禁用表和目录外旧报价完整保留整理/导出；不自动合并冲突，不以目录裁掉价格。不同实际请求 ID 曾因小写/后缀共用旧价时可复制成独立配置，规则数值保持相同；存在无法无损映射的项留待确认，不猜近似价。原配置保留至用户明确整理。
- 旧兜底价保留为明确标注的“旧配置兼容价”，适用集合随迁移原有模型关联记录，不作为提供商通用默认规则；新增模型/新提供商价格未知时不套用，也不自动采纳参考库。它与正式报价同属一份有效配置，不是第二套可切表。未知、显式零、缓存未单列继续按原规则区分。
- 参考按渠道展示，用户勾选模型 → 预览新增/覆盖字段、来源日期和条件 → 保存才应用。导入同样先选择目标提供商并预览冲突，不携带地址/Key，也不新增或启用模型。修改未来报价不重算历史；无法表达的规则明确不支持。

**格式与边界**：A 的设置格式与 B 的报价交换格式分别版本化。B 继续导入现有价格 v1/v2；建议增加 v3 载明模型请求 ID、报价规则及来源日期/适用条件，用稳定 modelId 在目标安装内显式关联，不直接信任外部 UUID。提供仓库内 JSON Schema 和同源格式校验；数值、重复、阶梯单调、日历有效期/确认等保留 Kotlin 语义校验，不能用 Schema 证明官方报价正确。导入/导出做边界适配，R4 算法不随格式改写；参考库的来源核对在具体采用范围内安排，本轮不承诺已重新核价。

**B 的交付顺序与验收**：A 验收完成 → 生效价/旧存档迁移预览与 P2-B 视觉稿确认 → 旧规则无损适配 → 单模型编辑及 v1/v2/v3 交换 → 按模型采纳参考 → 定向计价与真机表单验收。用相同模型/输入/调用时刻对照旧解析结果，覆盖开/关表、未知/零价、后缀、缓存、跨午夜/日历、阶梯及缺返回量；旧账目逐字不改，取消编辑/导入不发布，非生效表仍可导出。真实服务账单一致性不以本地测试替代。

### 2.4 页面信息架构（Demo 已定稿）

- 设置首页：提供商、模型用途、模型价格三条入口，移除快速切组。浏览或编辑某提供商不改变任何功能的默认选择。
- 提供商列表 → 详情分“连接 / 模型”两个标签，必要高级项在连接页折叠；只有明确保存才发布。模板只预填地址，自定义保留；同品牌旧组按原名称独立显示，不增加多实例管理层。
- 模型用途：全局默认、聊天、压缩、标题生成。功能项显示“继承全局 · 提供商/模型”或单独指定；会话设置显示会话/聊天功能/全局三层来源。点击均打开同一个跨提供商搜索选择器，行上显示提供商、显示名及必要的真实请求 ID；失效项可见原因，不自动替换。标题生成现在可选/保存，但暂不执行生成逻辑。
- 模型价格：提供商 → 模型报价；标准/缓存价直接编辑，阶梯/峰谷/日历按需展开。参考采纳、导入导出、旧表存档为次级入口。保存沿用父草稿一致发布，取消/返回保留已有未保存提示，不形成套层长表单。
- 已确认 Demo 的仓库独立副本：[`docs/reference/solochat-provider-model-design-v2.html`](reference/solochat-provider-model-design-v2.html)；以原 Codex 预览为视觉和交互基准，旧稿仅对照，不另做整套视觉。沿用 P1 紧凑间距与靛蓝双主题，分提供商、用途与选择、配置升级、备份恢复、思考模式五组。模型页思考控件明确标为“聊天思考模式”，不影响压缩；标题可选/保存但不执行。实现中若需改变已确认交互再回产品层，不自行重设计。
- “升级模型配置”正常情况自动完成并显示简短完成反馈；只为歧义或失效项显示对话名称、原模型及选择入口，可稍后到对话设置处理。选择器增加“使用当前默认模型”快捷项，显示全局默认的提供商及模型；点击后选中该具体模型，确认时保存为会话指定，不新增继承规则。默认未设或不可用时说明原因，不替选其他服务。不展示逐项勾选、内部映射术语或重复的保护清单；不是日常管理入口。
- “恢复备份”自动按备份内明确 ID 对应人物副本，仅列缺失/歧义项；必要时明确新建恢复人物，不按姓名合并真实卡。目标安装的模型不能凭同名或旧 UUID 自动启用，仍由用户选本机模型或明确继承。可先导入查看，完成页说明不能发送的原因及“选择人物/选择模型”入口；补齐后仍手动恢复发送。旧摘要继续按来源校验，不能将失效摘要洗成有效。
- 原 Codex 可视化预览曾通过主要交互、820/360/320 宽度及明暗预览检查；该证据只代表 Codex 预览片段。仓库独立副本的 Edge 视觉、浏览器控制台和实际交互待手动验收，不代表 Android 实现或厂商真实兼容验收。

### 2.5 已确认产品决策

1. 旧会话覆盖沿用迁移时有效接口；最新决定取代早先“明确项也逐项/批量确认”：可靠对应自动升级，只让用户决定歧义或失效项，不补造历史提供商。
2. 同品牌旧组保留原名称和独立配置，不自动合并，不新增复杂多实例管理 UI。
3. 保留旧兜底价格为明确标注的兼容规则，仅维持原有配置的计费语义；新配置价格未知不套用。
4. 旧备份缺失人物归属保持待确认，不绑定默认人物；恢复流程增加明确的归属确认入口。

以上规则、Demo 与聊天/压缩独立思考策略均已确认。A-8/9 深色主题视觉与交互验收通过；A-10 将页面草稿接入 READY v2 持久化并统一调用入口。正式用户资料升级、不可逆清理和发布均不在本轮自动执行。

## 3. 后续范围与既有欠项

- 图片：限 JPEG/PNG/静态 WebP，优先当前聊天模型；需贯通图文提交、私有媒体、近期原图/旧图/摘要区分、历史回看及媒体备份，不把头像缩略图管线当原图管线。
- 人物表情包：建立在媒体上，人物独立收藏/逐字段锁/稳定 ID，允许设备添加；普通图不自动收藏、不建跨人物个人库。复用单次调用与事件播出，取消收藏不破坏历史。
- U3 系统更新及完整跨安装恢复仍有端到端欠项；百轮/长场景/超大库未证明，按具体问题与预算安排。
- 正式 LAN 网页、主动消息、群聊、全 App 重设计、自动压缩、云同步与语音不在本轮。
