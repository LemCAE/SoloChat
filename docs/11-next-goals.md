# 后续目标与阶段交接

本页按 2026-10-23 用户要求整理后续目标，不表示这些功能已经开发。当前状态以 [HANDOFF](HANDOFF.md) 及 [04](04-changes.md) 的实际验证记录为准；既有历史阶段不据此重复实施。

U3 功能已实现，实机走到厂商安装器确认处并取消，未提交实际覆盖。后续合适的新发行包需在专用安装完成系统覆盖与资料保留检查；不使用旧 rc.4 覆盖真实资料所在的开发预览来凑验收。该验证边界保留在 04，不与下列历史查询开发混为一项。

## 1. 下一业务阶段：完整历史、分页、搜索与定位

沿用 06 §5 的顺序，F2 基础修复已完成，继续扩展搜索与定位。H1 已统一时间轴可见性/旧数据映射与来源位置，移除最近 400 消息限制；H2 已将聊天切为数据库有界游标读取，默认每页 80 条，上翻加载和返回最新已接入。实际验证边界见 04。下一步为 H3 完整历史搜索，再做 H4 点击定位。

| 小步 | 可交付结果 | 必要验证 |
|---|---|---|
| H1 统一时间轴查询（已实施） | 带来源类型、ID 与确定性排序信息的定位键；用户/系统消息和已出口可见事件共用完整读取边界，助手消息副本不重复展示 | 超过 400 条混合历史回归已从失败转通过；同毫秒、同文、同 ID 来源及既有播放投影通过相关 JVM 检查。未真机大历史验收 |
| H2 有界分页与阅读位置（已实施） | 默认每页 80 条，按来源位置游标读取；上翻后点击加载前页、保持正文锚点，新内容只提示，返回最新收回一页 | 相关 JVM/实际 DAO SQL 检查通过；专用会话实测 80→160 条、相同正文位置、新记录提示与返回 80 条。实际模型播出未在手机上调用，播出与翻页并发由定向回归覆盖 |
| H3 完整历史搜索 | 先当前会话，再接全局；结果包含会话、摘要与定位键。数据库有界查询，正确转义 LIKE 的 `%`、`_` 和转义符 | 中文、emoji、重复文本、特殊字符、已压缩历史；排除隐藏/未出口事件和记忆，不请求模型，不改摘要或记忆使用次数 |
| H4 定位与返回最新 | 点击结果加载目标前后文并高亮，可返回最新；目标已删除时给出可恢复提示 | 跨页定位、目标删除、播出中定位与返回，保持草稿；同来源 ID 不能与另一张表的 ID 混淆 |

H1/H2 已完成，下一批从 H3 当前会话搜索开始，再接全局范围，之后实施 H4 定位。继续复用稳定来源键、排序与可见性语义；搜索直接查完整库，不能只搜已加载页。先处理 LIKE 转义与有界结果，不提前引入 FTS，不改模型上下文或历史业务行。

## 2. 随后的配置能力：多组 baseURL/API Key

新增用户需求见 09 §7。建议在历史链路稳定后推进：P1 配置数据与现有单接口迁移 → P2 分组编辑/加密 Key/显式切换 → P3 模型目录、连通测试及请求快照接入。

完成标准：可保存多组地址和 Key、一键选择当前组；下一次调用使用匹配的地址与凭据，进行中调用保持开始时配置；Key 不进入公开文件、日志或备份。会话模型覆盖、默认模型、价格表与配置的关系在实施前写清，不以保存多个 Key 代替完整切换能力。

## 4. H3/H4 接手起点

| 位置（相对仓库根目录） | 复用职责 |
|---|---|
| core/src/main/kotlin/app/solochat/core/model/Timeline.kt | 可见时间轴映射、来源键与稳定排序；搜索可见性与显示保持一致 |
| core/src/main/kotlin/app/solochat/core/ports/Ports.kt | 查询端口，继续保持纯 Kotlin、无 Android 依赖 |
| app/src/main/kotlin/app/solochat/data/db/Daos.kt、RoomStore.kt、TimelineCursorRow.kt | 数据库候选读取、正文映射与游标；搜索查完整库并限制每批结果规模 |
| app/src/main/kotlin/app/solochat/play/SessionController.kt、ChatProjector.kt | 已加载页、live 交接、串行合并与返回最新；不另外创建会话运行实例 |
| app/src/main/kotlin/app/solochat/ui/chat/ChatScreen.kt | 当前会话搜索入口、结果状态、后续定位和滚动锚点 |

H3 可先交付当前会话搜索，再在同阶段接全局范围；每个结果必须带稳定位置，H4 再接跳转。搜索词为空、无结果、失败和结果变化都要可恢复；代发若显示须标未推送。不能通过搜索修改 sentToModel、触发调用、消耗记忆或重算历史账目。可见性仍以统一映射为准，记忆、未出口/取消事件、空白及等待/阅读提示不作为聊天搜索正文。

H4 需按目标读取前后文而非逐页无限回溯；定位中收到新内容仍沿用阅读位置保护。目标失效时保留搜索词/草稿，提示返回结果或最新记录；不能以 message.id 与 event.id 数值相同认作同一目标。

## 5. 多组接口配置分步交付

| 阶段 | 交付范围 | 需要证明 |
|---|---|---|
| P1 数据与迁移 | 稳定配置 ID、名称、地址和密钥引用；保留现有单接口为一组 | 旧地址/Key 不丢失，空 Key/无效地址可恢复，迁移不重复创建或泄露密钥 |
| P2 编辑与切换 | 分组列表、草稿保存/放弃、掩码、显式当前组、删除引用处理 | URL 与 Key 成对切换；缺凭据不自动使用别组，不因删除自动触发付费调用 |
| P3 请求与模型接入 | 模型目录/连接测试绑定选择组；请求开始冻结配置，沿用调用账目与冻结价格 | 进行中调用不被切换改写，后续调用用新组；凭据不跨服务、日志或备份泄露，历史费用不重算 |

实施 P1 前先确定：全局组与会话模型覆盖的关系、默认模型/模型目录/价格归属、同名模型失效提示、编辑与保存是否影响当前组。首版全局显式选择是一项建议，尚未据此引入每会话多供应商调度。现有备份不含 Key；若扩展非敏感配置备份，另行更新协议，不能隐式把密钥打包。

## 6. 阶段结束与提交

每阶段只交付该范围内的可用结果，按具体风险选择既有定向测试或必要实机路径；文档整理不跑构建。改动历史资料时保留双份一致快照核对要求，其他阶段不为交接新增探针或全量验证。

完成后记录：实际改动、已执行检查、未验证项、保留的测试资料和下一步；更新 HANDOFF/04，并按用户要求独立提交 commit。提交不代表发布或远端同步；未经实际执行不得写成已推送、已发布或已实机验收。
