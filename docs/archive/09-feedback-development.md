# 用户反馈与后续需求边界

本页保留 2026-10-22 起的用户需求来源和范围，不再承担滚动实施顺序；当前状态见 [HANDOFF](../HANDOFF.md)，后续顺序与完成标准见 [11](11-next-goals.md)。不得将计划当成已完成。整体 UI 改风格须提前审批，用户已明确提出的本页局部布局调整可直接推进。

本批已实施直接模式命令、应用级会话持有和 UI 同步调试接口；实机检查的实际范围见 04。人物分组、顶栏、编辑高度和价格子页也已实施并完成对应实机检查，实际范围见 04；中远期条目仍仅为计划。

## 1. 行为正确性需求与既有实现

1. **发送冲突**：用户观察到模型发送消息时用户发送可能冲突。先沿 `SessionController` 的手动代发、push、自动插话、播出落定、旧 turn 取消链定位，补能复现具体现象的定向用例；只修复实际证明的竞态，不重写整套控制器。
2. **直接模式切换**：`/system` 用于切换面对面时应直接执行模式切换，不先保存系统消息再等模型解释。明确命令形式和普通系统记录的边界；复用同一控制器与唯一写入规则，不制造假用户气泡。模式切换是否自动开场、忙碌时行为须按源码核实并在 UI 明示。
3. **等价调试接口**：新增调试入口必须复用 UI 的同一控制器/命令调度，包含代发、push、插话、模式和状态；旧 `TestGateway.send` 跳过控制器的路径不能宣称 UI 等价。沿用日志服务鉴权、明确指定目标会话并防重复提交；接口面向已有会话通用复用，测试过程仍只使用专用测试人物/会话，不删除或重置旧资料。模型交互可经接口完成，布局、键盘、选图等仍用 UI 检查，不新增无必要的探针或门禁。
4. **专用测试人物**：建立明确配合测试、按指令切换/短回复、不写通用记忆的独立人物卡。当前已创建 TEST-UI-1022 人物/会话；第一轮英文请求未得到模式提议，后续先完善测试人设，避免盲目反复请求。2026-10-22 该批获准约 1～2 次短调用，实际执行 2 次；这是历史用量记录，新调用按当前授权与必要范围控制。

5. **离页续聊与界面同步**：会话控制器由应用按会话持有，聊天页面只订阅同一实例。返回首页、进入其他人物或设置不取消已开始的生成/播出；接口也获取该实例，重新打开会话可观察真实测试进展。不得重进页面时再次初始化并重复推送。明确删除时先取消并等待收尾再删记录。当前目标是应用进程内的导航连续性，不将此扩大为系统杀进程后的自动恢复承诺。

## 2. 界面调整

- **首页**：标题栏与会话区域的对比更明确；按人物卡分组，先选人物，再显示该人物的多个对话。不得改会话真实归属；`resolvePersona` 只认明确有效的关联，缺失人物需用户选择，不自动回退。新建入口须明确创建给谁，不引入第二套会话数据。
- **聊天顶栏**：适度弱化冗余内容和操作，保留会话识别、进行中状态、返回及设置入口；图片头像小尺寸呈现。
- **人物编辑**：多行文本框有最大可见高度（优先用 maxLines / 内部滚动），长内容可以在框内继续滚动编辑，保留外层页面滚动、键盘避让与原八段映射。
- **价格页**：首屏只显示当前有效模型的价格与匹配/兜底状态；完整价格表移入子页，按服务商/模型归属筛选或分组。用户自建模型归属不可凭名称强行判定，不明项明确未分类；原表切换、逐模型峰谷、全局自填、两层草稿与历史冻结规则继续保留。
- **统计**：已参考 RikkaHub 完成今天/本月/累计范围、指标网格、按模型调用次数分布。后续根据实际反馈细化，不借此补造历史用量或命中率。

## 3. 长远目标：多模型群聊（尚不开发）

记录为远期产品方向，本轮不实现。后续需先设计参与者/人物与模型映射、轮次发言调度、引用与可见历史、并发/打断、逐请求费用归属及备份兼容。现有“一轮一次 API”仅对应当前单角色会话，不未经决策就扩大成多个模型静默并发调用。

## 4. 中期目标：依据上下文自动发送消息（尚不开发）

根据上下文判断人物是否主动开口，复用同一会话调度和播出，不能另造绕过 UI 的发送器。设计前先明确触发条件、免打扰时段、频率/冷却、单次与累计费用边界、用户关闭入口，以及与进行中回合/用户插话的优先关系。当前前台服务只有闲置检测和通知提示，不等于已实现自动生成；本轮不启用自动调用或定时付费任务。

## 6. 本轮追加反馈（2026-10-22）

- 会话设置与人物卡列表改为紧凑行，人物正文输入默认两行、最多六行，超出后在框内滚动。
- 首页只列有对话的人物并压缩间距；不再新建小默作为默认人物。旧卡与旧会话保留，缺少关联时须显式选人。
- 用量首页只展示紧凑概览与模型分布，最近调用移至子页。范围读取只查询当前选择，增加近七天；缓存命中率只计算接口同时返回输入与缓存的样本。
- 复用既有独立调用账目和请求开始时冻结的价格，追加保存原始 usage 分片及明细查看。旧记录保持原样，无价格或用量时继续标未知，不回填猜测值。
- 全部模型价格的归属筛选改为限高、可搜索、可滚动的底部面板；选择后收起，保留所选条件。

以上为实现范围，实际验证结果按 `04-changes.md` 本轮记录为准；未完成的验证不得据此视为通过。

2026-10-22 的额度暂停已由用户在 2026-10-23 恢复开发的指令解除，不再作为当前阻塞。人物长正文键盘避让、文本惯性边界、调用详情/原始 usage 等后续局部检查已记录于 04；测试草稿已放弃，未为这些只读检查额外调用模型。

## 7. 后续目标：多组接口配置与快速切换（2026-10-23，仅计划）

用户追加：保存多方的 baseURL/API Key 并直接切换。本项已列为 H3/H4 之后的后续目标，U3 已实施；当前仍未接入配置组，不因记录需求而接入新服务或发起模型请求。

- 每组配置有独立 ID、名称、baseURL 与加密保存的 API Key；列表仅展示掩码，不回显密钥。现有单接口配置应保留并迁移为一组，不清空或覆盖用户原配置。
- 首版建议全局明确选择一组；地址与 Key 原子切换，避免新地址配旧 Key。会话模型覆盖与不同接口的模型目录如何协作，实施前明确失效提示，不因模型同名推断可用。
- 调用开始时冻结所选配置，进行中的请求不被切换改写；后续请求使用新配置。连通测试/模型目录请求也只使用明确选择的组，鉴权不跨服务转发。不能借此启用多模型并发。
- Key 继续放本机加密存储，不写日志、仓库或现有备份 ZIP；删除配置前处理当前选择和引用，不自动换到另一组付费调用。调用账目仍沿用单次记录和开始时冻结价格，不重算历史。
- 开发前确定默认模型/价格与配置的归属、编辑草稿/保存语义、缺 Key 和无效地址的提示及旧配置迁移方式；按该范围做定向验证。具体阶段见 [后续目标](11-next-goals.md)。
