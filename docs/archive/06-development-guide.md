## 1. 开发方向与顺序

继续围绕“像跟一个人聊天”，先保证资料可保存、历史可找回，再扩展配置和入口。错误/记忆说明小修、备份副本恢复及 U1～U3 已实施；H1/H2 已完成。**当前按 H3 搜索→H4 定位→多组接口配置推进**，细分见 11。

正式网页、主动消息和多模型群聊保留为后续设计；长会话质量验证按明确问题与调用预算安排，不作为日常开发前置百轮测试。

## 3. 修复与改进清单

编号供后续任务与变更记录引用。旧 P1/P2 为发现时分级，不再代表当前实施顺序。**未经复现的风险不标成紧急生产故障。**

### F1 · 已修：错误提示与超时语义

2026-10-21 已去除未兑现的自动重试承诺；请求超时以 TIMEOUT/FAILED 收尾，上层取消继续传播并记 CANCELED，旧记录不回填。

显式“重新请求”仍是可选增强：复用已保存输入、不复制用户消息、新调用独立记账，并明确采用最新上下文还是保存请求；超时不等于服务端未计费，不启动不可见的无限重试。只有实施该增强时才按实际重试次数和失败恢复做定向验证。

### F2 · H1/H2 已修，继续 H3/H4

旧故障是全部事件与最近 400 消息混用，导致早期助手事件可见而用户/系统消息缺席；并非原记录删除或模型上下文截断。

2026-10-23 H1 统一可见历史、来源位置及同毫秒稳定排序，H2 接入有界数据库分页与阅读位置保护。下一步完整库搜索和点击定位见 §5/11，不再按旧故障重复修复，不把 400 换成更大常数。

### F3 · 已修：记忆共享说明

2026-10-21 已修正文案：同卡会话共享，通用记忆可用于所有卡；未选入本轮仍然保存。去除字面星号与未接入的自动淘汰承诺，没有改变记忆查询、排序、保存与删除行为。后续不要将存储、候选和实际注入混为一谈。

### F4 · 已修并持续维护：用户说明

日志持久化、未知费用、实际模式/保活入口和历史测试口径已修正。此次文档整理进一步拆开当前状态与旧计划；以后同步被改功能的说明即可，不为更新数字重跑全量测试，也不将局部 SAF 或 UI 结果扩大为全部路径验收。

### F5 · 已实现进程内离页续聊，进程恢复仍有边界

应用级 SessionRegistry 按会话持有唯一控制器，ChatScreen 离页只解除订阅，UI 调试接口复用同一实例。旧“页面销毁即关闭控制器”的描述已失效。

未来涉及进程中断恢复或持久化待发送队列时，再明确唯一写入源、输入保存位置和恢复策略；不得重启后自动重新收费或让未出口内容冒出。进程内导航验证不能替代系统杀进程或长时后台验证。

### F6 · P2：压缩减少请求长度，不一定减少本地成本

`ContextPlanner.prepareUnlocked` 每次取全模型历史和全事件；启用摘要后仍校验来源指纹。H2 已限制聊天页数据库读取窗口；模型上下文装配与摘要来源校验仍须分别评估，不能由 UI 分页推断全部成本已下降。**尚无本轮性能测量，不能直接声称已出现卡顿。**

先记录数据规模、装配/投影耗时、主线程卡顿与峰值内存；确认瓶颈后再做分页、增量投影或有明确失效条件的校验缓存。不能禁止逐条刷新来掩盖问题，也不能绕过人物卡/历史改变后的摘要回退。

## 4. 阶段 4A：备份与副本恢复

**当前状态（2026-10-23）**：core 协议、Room 一致导出、SAF 预览/文件入口与副本事务导入已接入，v7 保存恢复来源、账目标识与发送隔离。完整跨安装实机迁移仍待确认；具体排除项以 [07](../reference/07-backup-format.md) 为准。下列保留协议与数据保护约束，不表示这些基础链路尚未开发。

### 4A-1 交付范围

沿用 05 §7.1：SAF 文件选择、版本化 ZIP、manifest、JSON 与校验值、预览后导入副本。保留当前会话，不提供整库覆盖与自动合并。

包含会话、原消息、事件、人物卡、记忆、旧摘要、上下文修订/段、调用与用量/价格快照；排除密钥、网页密码、日志与临时连接凭证。数据库取一致快照，文件编码/写出放在事务外。当前协议不含设置和头像文件；以后如扩展非敏感设置，须独立预览应用，不声称数据库与 DataStore 跨存储原子恢复。

网页命令表未来若有数据，必须明确其运行态/审计用途：**导入不得恢复执行权限或重放命令**。不得恢复为可执行任务，清单写明排除规则。本地头像等文件若纳入，应打包实际内容，不能只保存失效 URI。

### 4A-2 当前代码额外要求的边界

1. **摘要指纹含旧身份。** [ContextRevision.kt](../../core/src/main/kotlin/app/solochat/core/model/ContextRevision.kt) 对完整 Message/Event 序列化做指纹，人设也有校验。先验证原包，再重映射消息/事件、人设、父修订、段边界并重算指纹和段校验，最后执行现有 `validateSegments` / `validateCompressionSource`。不能只替换外层 ID，也不能关闭校验。原包中本来失效的摘要不得被重算“洗成有效”：保留文本、停用并说明原因。
2. **导入代发可能自动推送。** `SessionController.open` 在 AUTO 下调用 `pushUnpushed`。仅取消未播事件不够：需导入后的待发送隔离状态或等价机制，保留 `sentToModel=false` 语义，首次打开也不请求模型，明确推送才解除。不能靠改全局发送模式或伪造已发送规避。
3. **部分悬空来源是合法历史。** `RoomStore.deleteConversation` 保留记忆、调用和用量，它们的来源会话可能已删。校验要区分允许缺失的审计来源与必须存在的摘要关系；保留原来源标识，不能误指向本机已有会话。
4. **JSON 内也有引用。** 映射须覆盖 `sourceSnapshotJson`、调用 `detailJson` 内历史 ID、`usageId` 和父修订等。`turnId` 是历史回合标识，不当表主键随意重编号；保持消息/事件回合对应和相对顺序。内置人物卡导入副本不能覆盖本机默认卡。

### 4A-3 拆分与验收

| 小步 | 代码归属建议 | 完成判据 |
|---|---|---|
| 格式与导入计划 | core 新增纯数据校验/映射模块 | 未知版本、损坏校验、缺必需引用、重复 ID、过量展开/路径穿越均在写库前拒绝 |
| 一致导出 | app/data 与 Room 事务适配 | 原库不变，清单与内容一致，失败不报成功 |
| 副本导入 | Room 单事务写入 | 任一步失败全回滚；原记录不变；重复导入提示副本 |
| SAF 页面 | 设置增加数据入口 | 中文文件名、取消选择、不可写位置、损坏包与预览取消均可恢复 |
| 恢复后使用 | 时间轴/压缩/统计联验 | 顺序正确，摘要状态正确，金额不按现价重算，打开不续播/不请求模型 |

合成资料先做导出→导入→再导出，比较语义与引用完整性，重映射后的副本不要求字节相同；真机原有记录仍须双份一致快照逐列核对。导入账目会增加副本，应标识来源并明确统计是否纳入，避免重复导入被误认成新增消费。

## 5. 阶段 4B：完整历史、搜索与定位

**2026-10-23 H1/H2 实施**：统一可见时间轴读取、来源定位键和稳定排序，修复全量事件/最近 400 消息混用；聊天已改为数据库游标分页，默认 80 条，提供上翻加载、正文锚点保持、新内容提示与返回最新。Room 每页在同一事务分批读取候选与正文，不改 schema/历史行/模型上下文。H3 搜索、H4 定位未实现，阶段拆分见 [11 后续目标](11-next-goals.md)，验证以 04 为准。

F2 与搜索一起设计，按“时间轴查询→分页→搜索→点击定位”分步交付。

- 定义稳定定位键，至少含来源类型与 ID，message.id 与 event.id 不能混为一类。沿用可见投影的确定性排序，处理同毫秒时间，不仅靠插入 ID 判断发生顺序。
- 助手结果以出口事件为准，不再返回 assistant 消息副本；隐藏事件与记忆不进聊天搜索。用户/系统沿用显示语义；代发若可搜到，标明未推送，不因此送入模型/摘要。
- 当前/全局范围都查完整数据库历史；正确转义 LIKE 的 `%`、`_` 与转义符。先用有界查询，是否需要 FTS 由实测决定。
- 结果提供会话、摘要、定位键；按目标加载前后文，提供高亮和返回最新。搜索不请求模型、不改摘要或记忆使用次数。
- 翻旧记录时，新回复只提示有新消息，保持滚动锚点；仍遵守 live 气泡交接，不重播旧事件。

**验收集**：空词、中文、emoji、同文多次出现、LIKE 特殊字符、已压缩记录、超出 400 条窗口、chat/scene/system 混合、取消事件、播出时翻页、点击前目标被删；可恢复失败，不丢草稿。

## 6. 长会话与压缩验证

以下规模为**建议设计，尚未实测**。

1. **离线层**：100 轮以上、上千事件的合成材料，包含系统补充、否定偏好、未兑现计划、插话、模式切换、重复短句和人物卡变化。三种压缩均验证前缀覆盖无重复/遗漏、原记录不变、失效回退、编辑应用与恢复。
2. **模型层**：新建 `TEST-LONG-<日期>` / `TEST-SCENE-<日期>` 与独立人物卡。先短样本核脚本及费用，再分段长测；固定对照组记忆条件，避免自动记忆掩盖摘要丢失。测试网关不走正常播放和助手历史写入，不能拿连续 send 当完整多轮 UI 验收；应走正常控制器或有等价落盘语义的专用适配器。
3. **质量层**：记录事实正确/缺失/冲突、否定反转、计划误当已发生、场景位置/未完成动作、重复回复。实际请求与下一轮回答都要看，“摘要有这个词”不等于模型会正确用。
4. **成本与性能层**：分别记摘要调用成本、后续估算/返回 token、缓存字段、本地装配耗时。短摘要不必然降低总费用，价格或缓存字段缺失就保留未知。

按覆盖一致性、事实保留、角色语气、成本、本地性能分别交付，不笼统称全部通过。记录资料版本、模型配置、调用记录、失败例和保留的测试会话；正文私有证据在忽略目录，文档只写脱敏结论。

## 7. 阶段 5：正式局域网网页

应用级 SessionRegistry 与 UI 等价命令已接入；以下持久化幂等、正式业务鉴权/SSE/页面仍为后续范围，不能把共享控制器重复列为从零开发。

沿用 05 §8 的前台使用基线，备份可用后再推进；先业务基础，再网页外观。

1. 应用级 `SessionRegistry` 按会话持有唯一控制器，手机与网页订阅共享状态、提交命令。页面退出不释放工作实例，空闲可回收；会话锁不跨网络等待。
2. 持久化 `clientCommandId`、正文校验、处理状态，区分发送/保存代发/推送/切模式。同 ID 同文返回同结果，异文拒绝；断线/刷新/重启不静默重复收费，未知结果显式显示。
3. 独立业务路由，不复用 `TestGateway.send`。SSE 状态带版本，重连取快照或有界增量，手机决定出口事实，PENDING 不提前展示。
4. 业务/SSE 均鉴权，改密码或关服务撤销会话；新入口不把长期密码放 URL 或 localStorage。正文按文本渲染，静态资源随 APK 提供。
5. 先验列表、选择会话、双端发送、手动两段，再接模型、模式、压缩与统计，复用手机校验。

验收含同时输入、重复点击、同 ID 异文、断网、刷新、请求中杀进程、多会话、手机返回与锁屏。后台可用性只按实测描述，实施时再核目标 Android 版本官方限制，不沿用旧平台行为推测。

## 8. 可选功能建议

本表不是已确认范围。优先选择改善现有体验、无需新增模型调用的项目。

| 建议 | 价值与最小边界 | 时机 |
|---|---|---|
| 明确的失败恢复入口 | F1 的显式重新请求，不复制历史，不隐瞒新计费 | 小修后 |
| 记忆来源/本轮选用预览 | 显示来源、共享范围、固定状态和实际选入项；来源已删则明确提示 | 数据阶段后 |
| 自动记忆保存开关 | 临时话题/测试不污染共享记忆；区分允许新写入与使用已有记忆，关闭不删旧内容，默认维持现行为 | 随记忆改进评估 |
| 上下文压力提醒 | 复用本地全文估算，上限未知不编百分比；只提醒，不自动摘要或截历史 | 长测后 |
| 会话草稿恢复 | 区分编辑草稿、已保存代发、已推送；恢复不发送，删除会话时清该草稿 | 生命周期策略确定后 |
| 文件日志管理 | 区分清空显示/删除文件，显示占用与保留范围；文件清理与写队列串行，不夹带聊天清理 | 相关设置小修 |
| 可阅读的聊天导出 | Markdown/文本按可见投影导出，区别于可恢复备份，不含隐藏记忆或未出口内容 | 备份与分页后 |

主动消息/联网搜索不列下一批必做。前者先明确打扰预算、免打扰、冷却与后台取证；后者触及 D3 的调用次数与成本，需要单独设计，不能因已有字段就判断工作很小。

## 11. 追加：GitHub 版本状态与更新下载（2026-10-22，分步实施）

用户要求加入版本检查与拉取更新。已核对当前远端为 `LemCAE/SoloChat`，发布工作流在 Release（含预发布）发布后生成并上传签名 APK。更新功能安排在备份导出/副本恢复之后、历史搜索之前，先能保护资料，再交付覆盖升级。

首版流程：设置新增“关于与更新”→ 手动检查 → 展示当前/远端版本、正式版/预发布、发布日期和更新说明 → 用户点击下载 → 展示进度、取消与失败重试 → 下载完成后交给系统确认安装。默认正式版，可显式启用预发布；不在聊天过程中弹出更新，不静默安装、不自动改数据库。网络失败与限流显示检查失败/可重试时间，不显示成“已是最新”。

| 小步 | 实施范围 |
|---|---|
| U1 · 查询与版本状态 | 从固定仓库的 GitHub Releases API 读取发布信息与 assets；稳定渠道过滤草稿/预发布，测试渠道包含预发布。按版本语义比较，不使用字符串排序，不把 debug 后缀当远端预发布渠道；处理未发布版本、无安装包及无可比较版本。保留发布页入口与本次检查状态，重复点击复用正在进行的检查，不新增后台轮询 |
| U2 · 拉取安装包 | 只提供当前发布对应的 Android APK；使用 GitHub 返回的下载链接，不把模型 Key 或日志网页密码带给 GitHub。固定同一版本/asset 的下载任务，显示进度/取消；网络失败可以重试。下载完成才显示“安装”，需要时可打开发布页手动下载 |
| U3 · 系统安装与资料边界 | 检查下载 APK 的包名、版本码和签名是否支持当前安装的覆盖更新，再启动 Android 系统安装确认；按系统提示处理安装来源授权。本机预览与发行统一 `app.solochat` 和发布签名；历史 `app.solochat.debug` 如仍存在须提示独立资料，不能声称会覆盖迁移。覆盖升级前提供备份入口，不自动执行恢复 |

**发布状态边界**：当前流程先发布 Release、再构建上传，API 中可能暂时没有 `app-release.apk`。此时显示“版本已发布，安装包尚未就绪”，保留稍后手动刷新/打开发布页，不伪造下载地址、不直接判断构建失败，也不向 App 暴露 Actions Secrets。安装后的可升级性以包内版本码与签名为准；同版本重发或版本码回退不能仅靠 tag 判断。

**必要检查**：版本比较、渠道过滤、缺失 APK 和失败状态用定向用例；下载/系统安装在功能接齐后用同包名、同签名的专用安装验证。现有 debug 包不直接切换覆盖为 release，真实资料不用于升级试错。不增加日常全量重跑或哈希/取证流程。

接口依据：[GitHub Releases API](https://docs.github.com/en/rest/releases/releases)、[Android PackageInstaller](https://developer.android.com/reference/android/content/pm/PackageInstaller)。U1 已于 2026-10-23 接入手动在线检查；同日接入 U2 下载与 U3 安装预检查/系统入口，实际验证范围见 04，不把标签比较或下载完成当作已验证可覆盖升级。

**U1 实施（2026-10-23）**：关于与更新页显示当前安装；默认只查正式发布，可明确包含预发布。按页读取公开 Releases（每页 100，超过 10 页未读完报无法完整比较，不拿部分结果冒充最新）；同一检查期间重复点击复用任务，切换渠道清除旧结果且不自动联网。按 SemVer 数值段和预发布规则比较，构建元数据不参与优先级；可比较标签选最高版本，若全不可比较则展示最近发布并标明无法比较。草稿始终过滤。

错误、限流与可用重试时间明确展示；空列表、同版、本机较新、发现更新、不可比较分别说明。APK 缺失时显示尚未就绪，更新说明按需展开。专用无鉴权 HTTP 客户端只访问固定 GitHub 仓库，不携带模型 Key 或日志服务凭据，不新增后台轮询。接口参数依据 [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#list-releases)，实际验证范围见 04。

**U2 实施（2026-10-23）**：按当前发布的 `app-release.apk` 下载地址、asset id 与大小固定任务，专用无鉴权客户端处理 GitHub 的 HTTPS 下载重定向。应用级唯一下载器跨页面持有；显示版本、字节进度、取消与原任务重试，切换查询渠道不会改动正在下载的目标。取消、网络失败及大小不符不标成完成；每次尝试独立临时文件，完成才改为 APK，失败/取消清理本次残片。下载使用私有缓存，系统可能回收；进程重启不恢复或自动续传。安装入口已接 U3 包名/版本码/签名检查，只有检查允许时才能继续，页面保留发布页手动下载入口。依据 [GitHub asset 下载字段](https://docs.github.com/en/rest/releases/assets) 与 [Android 应用专属存储](https://developer.android.com/training/data-storage/app-specific)。

**U3 实施（2026-10-23）**：下载完成后读取真实 APK 身份，包名必须匹配正式版，版本码不低于当前，当前签名者集合须完全一致，最低系统版本须满足；缺包/解析失败/无签名都阻止安装。签名 API 在 Android 28+ 使用 GET_SIGNING_CERTIFICATES，26～27 使用 GET_SIGNATURES。首版不支持证书轮换推断，即使系统可能兼容仍保守拒绝。同版本覆盖允许，不仅依赖 release tag。

页面展示检查结果、APK 版本码与“先备份资料”；点击安装再次确认并可进入本地备份。来源未授权时打开本应用的系统授权页，返回仍需用户再次点击；交给系统前重新检查 APK 和当前安装，通过仅共享更新缓存的只读 FileProvider URI 启动系统安装确认。返回 App 不据 Activity 返回值声称安装成功，不自动恢复、卸载或清数据。依据 [PackageManager](https://developer.android.com/reference/android/content/pm/PackageManager) 与 [FileProvider](https://developer.android.com/reference/androidx/core/content/FileProvider)。后续按 [目标拆分](11-next-goals.md) 进入历史查询；多组接口配置为新增后续目标。
