## 1. 决策速查

| # | 决定了什么 | 一句话理由 | 详见 |
|---|---|---|---|
| D1 | 只做 Android 原生（Kotlin + Compose） | 用户只在 Android 上用；通知/前台服务/分享这些"聊天基本盘"网页给不了 | 01-decisions D1 |
| D2 | "常驻" = App 内的前台服务，**不做外部服务端** | 数据只有一份、离线可用、Key 不离开手机；用户真正要的是"主动消息可靠" | D2 |

| D7 | 面对面是**同一会话的状态属性**，不是独立会话 | 切回聊天后模型仍记得门口那段；自动切换判错代价明显，所以默认要确认 | D7 |
| D8 | 不做图像生成、语音、桌面壳 | 会让"像在用微信"这个核心体验失焦 | D8 |

| D11 | 解析**宽进**：四层，一个字符写坏不赔掉整轮 | 一次输出 = 一整轮；真机 216 条里 27 条因一个多余冒号整轮降级 | D11 |

## 2. 最容易被违反的四条

1. **D3/D4：不要把"生成"和"播出"揉在一起。** 请求结束即返回；播出由播放器异步做。
   任何"发一句请求一次"的实现都会让成本与语义同时变差。
2. **D7：模式是会话上的属性。** 不要为 `scene` 新建会话、不要在事件里塞"这是场景模式"以外的假设；
   历史是一条线，`Event.mode` 只用来还原"这段是当时的场景"。
3. **D10：稳定前缀必须逐字节不变。** 任何每轮都变的东西（时间、要不要提醒、刚被打断）只能进**变动区**；
   摘要在最前、状态与指令在最后。原理与判据见 02-handoff §5 的 KV 取证手法。
4. **D11：宽容解析的产物不能当范例喂回去。** 历史里出现模型自己写坏的 JSON，
   它会把错误当成"协议允许的写法"照抄（实测 11 处范例 → 提示词改了也照错）。
   凡是"把模型输出原样存下来再喂回去"的地方（摘要、记忆、撤回重发）都要过这一条。

## 3. 踩过的坑（现象 → 根因 → 现在的规矩）

> 每条都在代码注释或文档里留了痕迹。带 §的可以去 [02-handoff.md](02-handoff.md) 看细节。

| 现象 | 根因 | 现在的规矩 |
|---|---|---|
| 模型"重新回答"已经答过的话 | 写助手历史的代码**从来没执行过**（`eventsToAssistantText` 过滤 `usableAsContext`，而那一刻事件全是 `PENDING`） | 助手历史由**播出方**在每条出口后写；界面与上下文都只认 `delivery.spoken` |
| 重启后凭空冒出 7 条消息 | 残留事件被标成 `INTERRUPTED`（= 说过），而它们从没播出去 | 没出口的一律 **`CANCELED`**（"当没说过"） |
| 测试骗过三轮调试 | 假替身只改了自己的一份记录，没改"事件本身" | 测试替身**必须照抄真实现的语义**（包括 SQL 语义，见 `FakeStore.modelVisibleMessages`） |
| 用例卡在 `advanceUntilIdle()` | 它推不动 `backgroundScope` 里的协程 | 用"推进虚拟时间 + 轮询终态"（`awaitSettled`） |
| 手写 JSON 出错两次（emoji 变 `�`、`bubbles` 少 `]`） | 手工拼字符串 | 所有 JSON 出口走 `ResponseJson.kt`（纯函数 + 往返测试） |
| 屏幕上只有一条气泡、被逐条覆盖 | 播出期间整场不刷新 `items` | **每条播完就地刷新并撤活气泡**，但演出期间不许 reload 整个时间轴 |
| 上下文整个空掉且不报错 | `LIMIT 0`（一条都不要）与 `LIMIT -1`（全都要）只差一个字面量 | 0/负 → `-1` 的翻译**只在 `ChatConfig.historyWindow` 一处**做 |
| 同一轮几条挤在同一帧出现 | `deliveredAt` 等整场演完统一补 | **每条播出的那一刻**就落定 |
| 已看到的气泡往下跳 | 被切断的事件统一盖"打断发生的时间" | 用**它开始播出的那一刻** |
| 界面上一条气泡里全是 JSON | 模型输出多一个冒号 → 整份语法作废 → 降级成一条 `say` | 解析四层宽进（D11）；已落库的用 `DegradedTurn` + 打开会话时修复，**只改形状不改内容** |
| 提示词改了模型还是照错 | 历史里躺着它自己以前写坏的 11 处"范例" | 历史装配时先把"整段 JSON"还原成正常几行 |
| 发送键要点两次才变灰 | 推送成功后**漏了一次状态刷新**，靠回合收尾那次 `reload` 蒙对 | "推送成功"是它变灰的**唯一**触发点；测试要在"请求已发出、回合未结束"那一帧取状态 |
| 测试数字长期写小（256 vs 276） | 用 `--tests` 跑单测会清空结果目录，之后 UP-TO-DATE 不重写 XML | 权威数字只在 **`--rerun-tasks`** 之后读（§原文） |
| 验收脚本误报"4 个表被动过" | 拿**整表指纹**比对两份快照，而用户中间又聊了一轮 | 判据改成"**快照里已有的行**按主键逐行比，改动 0、消失 0" |
| 面对面里照样弹"要见面了" | 协议示例自己写着 `"next_mode": "scene"` —— **示例比规则硬** | 同模式的提议在装配层就丢掉；协议示例不许示范已存在的模式 |
| 模型连着两轮用同一个词开头 | 提示词约束不够（"让它别重复"不是确定性的） | 代码里兜一层：只对短 `say` 做"与上一轮 assistant 消息相同则丢弃"，且**一轮不能被丢空** |
| 用户消息成对出现 | "取批 + 清空"不在同一个临界区，两条并发路径各取到同一批 | 取批与清空放进同一把锁 |
| 键盘弹出时底部被算两遍 | 少了 `consumeWindowInsets(padding)`（`Scaffold` 与 `imePadding()` 的 inset 都含导航栏） | 见 02-handoff §3 ⑨ |
| 编译直接报 `Unresolved reference` | `material3 1.3.1` 的 `TextField` **没有** `contentPadding`（那是 `BasicTextField` 的） | 压高度用 `Modifier.heightIn` |
| `TopAppBar` 里的菜单弹不出来 | `actions` 里叠了两个可点区域 | 一个 `actions` 只放一个可点区域 |

## 4. 试过但不可行的方案 / 刻意不做

| 方案 | 为什么放弃 |
|---|---|
| **流式中途解析**（边收边播） | JSON 被截断时给不出可靠结果；播出半截脚本比晚几百毫秒糟糕得多（D4）。**已经完整的那几条会留下**，半截的不播 |
| **语义预判防抖**（每条都问模型"他说完了吗"） | 成本与正式回复一样贵，收益只是省几秒；判断权交给模型用 `wait` 表达更便宜（D6） |
| **工具驱动的 `send_message`** | 一轮 3 条 = 前缀重发 3 遍，且会诱发元文本与拆断的长句（D3） |
| **给 `scene` 建独立会话** | 切回聊天后模型就不记得门口那段了（D7） |
| **滑动窗口截历史**（曾经默认 40 条） | **窗口自己在毁缓存**：每轮丢掉最旧几条 → 历史段开头变了 → 历史从来没被缓存过。实测放开上限后每轮更便宜（D10） |
| **用 Room 迁移做"内容修复"** | 迁移写错会**打不开 App**（`Migrations.kt` 文件头第 1 条纪律）。改成"打开会话时按会话修 + 失败只记日志" |
| **猜"未转义的引号该在哪结束"** | 猜错等于**替模型编内容**，比降级更糟。宁可让它明确坏掉（D11） |
| **`fallbackToDestructiveMigration()`** | 把"用户数据丢光"变成静默默认行为，绝对不能接受 |
| **外部 Node 服务端** | 数据离开手机、多一跳依赖；前台服务已能满足"常驻"（D2）。**若以后要"手机电脑同一份数据"再考虑** |
| **Robolectric / instrumentation / `MigrationTestHelper`** | Robolectric 运行时才去下 `android-all`，离线/受限网络必然失败（实测）；项目刻意不用模拟器。所以需要 Context 的逻辑抽成纯函数再测；迁移只能靠"导出 schema + 真机装一遍 + 拉库核对" |
| **galgame 选项（`choice`）** | 用户从"想说什么说什么"变成"在框里选"，聊天变关卡（D5） |
| **图像生成 / 语音 / 桌面壳** | 用户明确不要，且会让核心体验失焦（D8） |
| **本机 `screenrecord`** | 完全不可用：写 `/sdcard` 与 `/data/local/tmp` 都被 SELinux 拒，流式也拿不到字节（试过一轮） |
| **`uiautomator dump` 逐帧观测** | 一次 0.5~2.5 秒，"逐条出现"的差别就在秒级两帧之间；抓了 7/14/8 帧三次全错过。改用"抓状态快照" |
| **`adb shell input text` 打中文** | 报 `NullPointerException`，只能发 ASCII（用英文+拼音代打） |

## 5. 待定 / 不确定（写文档时不要替它下结论）

**阶段 3 决策（2026-10-10）**：D10 动态内容移到 user 尾部，稳定 system 前缀内容与计数保持原样。手动压缩的来源采用模型可见消息前缀及已出口事件指纹，切点必须验证完整助手调用组；不能用用户/助手 turnId 相等配问答。应用重新校验来源和父指针，原消息/事件不修改；无来源的旧 scene_summary 不启用。模式切换后可保留带模式事实的摘要，人设变化停用旧摘要。

生成只保存草稿，点击应用才改变下一轮；返回页面不取消应用级生成任务，进程退出不自动续费续跑。单段完整交流超预算时拒绝并要求提高预算，不能暗拆边界；合并需减少段数，落单摘要不重复请求，无进展则失败，不无限递归。预览后模型配置/价格变化必须重预览；每次实际调用独立记账，失败/取消不启用部分结果。构建、真机取证及验证边界见 04-changes.md。

**摘要输出预算陷阱**：真机接口在 `max_tokens=1712` 时返回 1712 个推理 token、没有正文，即使请求携带 `enable_thinking=false`。摘要目标字数不能换算成包含推理的硬输出上限。摘要请求改为沿用会话有效 maxTokens（0 为接口默认），长度由正文提示词约束；界面同时显示输入预算、目标字数和输出限制。生成可能比原文更长，需据实际全文预览决定是否应用，不能承诺必然节省 token。故障请求保留失败账目，未产生草稿或切换指针。

**模型行为取证陷阱**：ADB 的 ASCII 输入异常会进入真实历史，诱导角色怀疑盗号并持续拒答；仅在摘要里能找到事实不足以证明回答质量。改用手机拼音键盘、发送前逐字检查，另建中文对照会话及人物卡副本。普通聊天的 remember 会写共享人物记忆，摘要调用不会；隔离验收需同时隔离人物卡。只清理本轮测试产生且来源可确认的记忆，原记录逐主键核对。

**历史规划与当前状态**：2026-10-10 原方案见 [05-next-development.md](05-next-development.md)，不再承担当前待办表。备份接入与 H1/H2 已实施，下一阶段为 H3 搜索、H4 定位；多组接口配置、正式网页等后续顺序见 [11-next-goals.md](11-next-goals.md)，当前验证边界见 [HANDOFF.md](../HANDOFF.md)。时间功能仍暂缓，规划不能当成已实现功能。

**阶段 2 已落地的选择**：

- 模型覆盖只写会话 modelOverride，空指针继承全局，接口与密钥共用。不能靠切会话时改全局模型实现隔离；正式请求和统计预览共用 ContextPlanner。配置修改与请求准备在按会话锁内完成，锁不跨网络；回合收尾、改模式/归属使用局部 UPDATE，避免旧快照覆盖后来改名或模型。
- 逐字段区分接口返回、本地估算和未知；明确返回 0 与缺失不同。正式请求添加 stream_options.include_usage；没有 usage 仍只有一次请求，不为补统计重试。缓存为输入子集，当前兼容协议的推理为输出明细，不重复相加。依据：[OpenAI 流式返回](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)、[DeepSeek 返回字段](https://api-docs.deepseek.com/api/create-chat-completion/)、[缓存口径](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)。其他不符合此口径的供应商需要单独适配，不能猜。
- 价格在请求前冻结为单价/来源/币种快照；零价必须明确已配置才是免费，未配置是未知。缓存分布未知且有不同缓存价给范围；币种不混算。旧 usage 不回填价格、来源或重写数值，费用未知；新调用与兼容行事务关联，不能重复汇总。
- 失败、取消、静默均保存实际请求尝试；终态落盘用 NonCancellable，残留 STARTED 启动时标中断。调用记账在 ScriptReady 前完成，播出打断不丢已产生的用量。缺最终用量或仅部分输出必须说明未知/不完整，不声称精确账单。
- v6 只追加字段与表；阶段 2 的上下文版本/分段、网页命令只作基础，阶段 3 才启用手动压缩，网页幂等仍未接。旧 scene_summary 缺消息覆盖依据，不自动注入，也不拿事件边界替换用户/系统历史。D10 已与阶段 3 同批改变。

**界面投入约定（用户 2026-10-10 补充）**：优先正常字体下的布局与体验，不为超大字体的极端场景持续增加适配投入；保留已经修好的键盘避让与基础滚动。

**阶段 1 已落地的选择**：会话设置先用聊天上层的全屏覆盖页，订阅原控制器，避免导航离开 ChatScreen 时触发 close、取消正在进行的回合；返回时输入草稿保留。人物卡管理只在空闲时可进入，修改共享卡的影响明确说明。正式网页阶段仍需 SessionRegistry，当前覆盖页不能替代控制器共享改造。全局设置按选中组校验与原子保存；测试连通/拉取模型使用草稿，不隐式写接口、密钥或网页配置。

**系统栏陷阱**：Manifest 自行处理 uiMode，Activity 不会随主题重建；只在 onCreate 调 enableEdgeToEdge 会留下旧图标颜色。需在 onConfigurationChanged 再调用。早期全屏 Dialog 在这台设备的浅色模式仍有灰色系统栏遮罩，已改成同一窗口内的全屏覆盖页，减少额外窗口样式处理。问题来自真机截图，不能只看 Compose 预览判断。

**会话管理（2026-10-10 用户补充）**：会话设置增加改名和删除。改名使用局部 UPDATE，不拿 UI 会话快照整行覆盖其他属性；空名称不可提交。删除必须确认，在回合结束后操作，并在同一事务中清理该会话的事件、消息、摘要和会话行；人物卡、已保存记忆、历史用量继续保留，确认文案明确范围。失败留在设置页，成功关闭控制器并返回主页。

**2026-10-10 补充决策**：用户系统消息用 `/system 正文` 写入 SYSTEM 历史，下一轮生效，避免为了补充事实多花一次 API；日志从“仅内存”改为私有目录轮转落盘并提供导出（用户明确要求）。两项都不改变稳定提示词前缀。

**已排除的推测**：SecretStore 的 `degraded = false` 源码位于 prefs 初始化之后，并不等于运行时覆盖降级标志。Kotlin 2.1.0 构造器省略默认 false 赋值，模拟初始化失败后实测标志为 true；不能仅凭源码顺序报告 bug。

**2026-10-10 测试入口约定**：`TestGateway.reset` 只新建专用测试会话，绝不能隐式清空旧会话（旧实现确实会删全部）。HTTP 测试发送跳过手动代发阶段，所以落盘时必须设 `sentToModel = true`；否则界面能看到输入、模型提示词却没有输入，测试结论会失真。清理保留为独立显式操作。

- **`ChatConfig.modeSwitchPolicy`（AUTO / CONFIRM / OFF）没有消费者**：设置页只写布尔
