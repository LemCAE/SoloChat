# 备份协议、导出与副本恢复（阶段 4A）

> 2026-10-22 已接入 Room 一致读取、事务副本导入与 SAF 预览/确认入口。
> 导出曾实机保存成功；副本恢复已有定向与离线检查，完整跨安装实机迁移仍待确认。这里保留该验证欠项，设备授权与后续安排以当前会话及 [HANDOFF](HANDOFF.md) 为准。

## 1. 文件与内容

实现位于 `core/backup/BackupData.kt`、`BackupCodec.kt`、`BackupImportPlan.kt`，不依赖 Android。

`BackupCodec.write` 接收完整业务数据，输出版本化 ZIP；`read` 完整读取、校验后返回 `BackupArchive`。
外层调用者负责关闭输入输出流以及呈现文件读写失败。ZIP 不解压到文件系统，只有两个合法条目：

| 条目 | 内容 |
|---|---|
| `manifest.json` | `format=solochat-backup`、`version=1`、备份 ID、生成时间、正文 SHA-256、各类条数、排除项目 |
| `data.json` | 会话、消息、事件、人物卡、记忆、旧摘要、上下文修订与段、全部旧用量、新调用及 usageId 关联 |

正文为严格 UTF-8 JSON，枚举使用领域模型的序列化格式。包中只存业务字段，不复制 Room 数据库文件。
新调用按结构化 `CallRecord` 保存，保留原价格与用量来源，不按导入时配置重算。

此协议小步明确排除密钥、接口配置、其他设置、日志、网页命令及头像文件。`avatar` 字符串保留，
**没有打包本地图片内容，也不声称图片路径可跨设备恢复**。当前支持 emoji/文字与本机图片引用；跨设备文件缺失时显示名字首字，头像文件随包迁移仍属于后续扩展，
不应在尚未实现时写成已支持。增加文件种类或改变字段语义须升级格式并兼容已导出的版本。

## 2. 校验边界

- 限制压缩输入总量，正文展开最多 64 MiB、清单最多 64 KiB；按实际读取字节计数，不信任 ZIP 声明大小。
- 拒绝未知/重复条目、目录与路径、缺失正文/清单、不支持格式/版本、损坏正文、数量不符及未知序列化字段/枚举。
- 各表主键必须唯一；数字主键为正数。消息/事件/摘要必须有所属会话；摘要来源、分段端点、父版本和启用指针不得跨会话或缺失，父链不能成环。
- 调用的 usageId 关系必须存在且一致，不能一份用量被多次关联；保留价格的数值必须有效，旧用量不能为负数。
- 删除会话后仍保留的记忆、用量和调用来源允许悬空；已经删除的人物卡归属也允许保留，不能误判成包损坏。
- 摘要指纹失配与结构引用缺失分开处理：前者保留版本但停用，后者拒绝进入写库规划。

这些校验用于备份文件完整性与恢复安全，不是每次日常开发的固定验证流程。

## 3. 副本规划

`planBackupImport` 只接收已经通过 `BackupCodec.read` 的包。调用者提供写库事务内取得的消息/事件/用量最大 ID，
函数分配新 ID 并返回 `BackupImportPlan`；它不会访问数据库、调用模型或改变原包。

1. 会话、人物卡、记忆、摘要版本/段、调用与操作号建立新身份。消息/事件/用量按原主键顺序映射，
   保留正文、时间、turnId 和相对顺序。真正写库前，适配层仍须确认新字符串 ID 不与本机记录冲突。
2. 内置人物卡成为普通副本。会话空归属或归属已删时，固定到原包实际兜底人物卡的副本；
   包中没有人物卡则创建独立“对方”兜底，避免落到导入设备上的日常人物卡。
3. 原包中仍有效的摘要重建消息/事件指纹、人设校验与段校验，随后再次通过现有摘要校验函数。
   原本失效的版本保持文本和编辑/完成状态，来源人设校验置空、清启用指针，并在 `disabledRevisions` 中提供原因。
4. `PENDING`/`PLAYING` 事件转为 `CANCELED`，不续播。代发消息保持 `sentToModel=false`；
   **所有副本会话列入 `pausedConversationIds`，必须由 app 持久化隔离，不能仅依赖本次内存对象。**
5. 悬空会话/人物卡来源使用 `backup:<导入ID>:missing:<原ID>` 保存原标识并避免匹配本机现有资料。
   已删会话的调用上下文消息号以负数保存原号，不能作为本机正数消息主键使用；再次备份仍可保留。
6. 包中未结束的 STARTED 调用变成 INTERRUPTED，保留已收到的用量并标明不完整，不恢复执行权限。

会话名加“（导入副本）”。每次规划使用新导入 ID，重复导入不会覆盖已有副本；是否已导入同一备份需由 app 持久化来源并在预览中提示。

## 4. Room 与页面适配

**已接入导出**：`BackupDao` 提供不带界面分页和日期过滤的全表查询；`RoomBackupReader` 在单个读事务内取原始行，事务外还原业务结构、校验与编码。包括归档会话、全部消息/事件、完整摘要版本及分段、已删除来源的记忆/账目，不按最近 400 条或统计范围截取。调用状态读取索引列，保留启动收尾已标记的 INTERRUPTED，不把旧 JSON 内 STARTED 当作当前状态。

设置的“本地备份”进入独立页面：说明包含/排除项目 → 整理到 App 私有缓存 → 展示数量与整理时间 → 系统选择位置 → 写出 ZIP。缓存由页面 ViewModel 持有，旋屏/文件选择期间保留，正常离页清理。准备失败不进入保存；保存位置失败保留暂存以便重试并提示可能留下不完整文件。文件没有额外加密；不打包本机 API Key、价格表和设置。整理之后的新消息不自动补入既有暂存文件，需重新整理。进程意外退出后未承诺恢复导出任务，遗留私有缓存由系统缓存管理，不作为可恢复的备份。

**已接入副本恢复**：`RoomBackupImporter` 在一个 `withTransaction` 内取当前数字主键上限、规划映射并使用默认 ABORT 插入所有业务行，同时保存导入来源与隔离标记；任何冲突/异常回滚，不使用 REPLACE。Room v7 仅追加 `backup_import`、`backup_origin` 两表，注册 v6→v7 迁移，不更新/重建旧业务表。

- 页面通过 SAF 完整读取并校验 ZIP，在内存中保留待确认档案；预览显示来源时间、全部类别数量、旧代发、失效摘要、重复导入与通用记忆。只有明确确认才调用写库；取消/无效文件不写库。
- 所有副本会话持久暂停；控制器在打开、自动补推、后续发送/组合发送、起轮和模式切换路径检查暂停，不伪造 sentToModel、不改全局发送模式。输入禁用并显示只读提示；用户确认恢复后才解除，自动模式可推送旧代发，手动模式仍需按推送。未播事件由规划取消，不恢复播放。
- 导入旧调用及旧用量按行标记，在统计中单独展示，不加入本机新消费；副本会话之后实际产生的新调用正常计入本机。清空账目时同时清理对应来源标记，避免数值 ID 后续重用时冲突。
- 同一文件再次导入会提示先前次数；用户仍可明确建立另一份副本，不覆盖第一次导入。导入记录不是跨设备自动同步或按姓名合并。
- 导出协议仍是 v1，旧调试包导出的 ZIP 可读取。接口/Key/价格表、其他偏好和头像图片没有包含，须另行配置/补充；通用记忆进入全局范围，人物记忆保持独立副本归属。

**未验证边界**：本次没有实际手机，未走系统文件管理器的恢复选择/确认，也未在真实发布包升级后打开恢复会话。自动用例只证明对应控制器规则；SQLite 离线检查证明迁移列/索引及冲突回滚语义，不等同于 Room 真机验证。首次完整跨包迁移由用户下载预发布包确认，不把导出实机结果扩写为恢复实机结果。
