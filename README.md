# SoloChat

一个跑在你自己 Android 手机上的**一对一 AI 聊天应用**。不接任何平台、不需要账号、
不用中间服务器 —— 填一个模型接口地址和 Key 就能用。所有数据（对话、人设、记忆、用量）
只存在这台设备上。

它想做的不是"另一个 ChatGPT 客户端"，而是**像在用微信跟一个人聊天**：

- **一次回复不是一整段，而是 2~3 条独立气泡**，每条长短和间隔都像真人在打字
- **你连发三条半句话，它会等你说完才回**，不会对着"我今天"抢答
- **它会自己决定不回**（"还在等你说话"、"不想理你"），而不是每条都必须接
- **同一会话可以在“发消息”和“面对面”之间切换**，模型可提议，确认后生效

## 快速开始

聊天输入开头的 `/` 会显示命令选项。选择 `/system` 后输入系统事实，例如
`/system 现在是晚上，外面开始下雨`；发送后保存为系统记录，在下一轮模型回复时生效。

日志会在应用私有目录中轮转保存，最多约 8 MiB；日志页的“导出日志文件”可保存跨重启记录。
“清空”只清当前内存显示；关闭“记完整正文”后，不再记录新的完整提示词和模型原文。

### 1. 构建

```powershell
# Windows：双击 构建.bat，或者
pwsh tools/build.ps1                    # 编译 debug APK
pwsh tools/build.ps1 :core:test         # 只跑纯 Kotlin 单元测试
```

编译检查产物在 `app\build\outputs\apk\debug\app-debug.apk`；这是历史独立 debug 变体，不再作为默认装机预览包。

**GitHub 版本发布**：只有发布 Release（包含勾选 Pre-release 的测试版）才触发云端构建；普通推送、PR、仅推送标签和保存 Release 草稿均不构建。在 Releases 中选择包含最新工作流的提交，创建版本标签并发布即可；工作流运行原有核心/Release JVM 单测，生成固定密钥签名的 `app-release.apk`，随后附到该 Release。应用版本名取标签并去掉开头的 `v`，版本号取工作流运行序号。失败时查看 Actions 日志和测试报告，修复后发布指向修复提交的新版本。

Release 使用包名 `app.solochat`，与本地 debug 包 `app.solochat.debug` 独立安装，数据不会自动迁移；正式版和测试预发布共用发布签名。仓库需要配置四个 Actions Secrets：`SOLOCHAT_KEYSTORE_BASE64`、`SOLOCHAT_KEYSTORE_PASSWORD`、`SOLOCHAT_KEY_ALIAS`、`SOLOCHAT_KEY_PASSWORD`。发布密钥及密码须在仓库外另行备份，不能提交；丢失后无法用原签名覆盖升级。

> 为什么要有 `tools/build.ps1` 这层包装：本机环境有四处约束（JDK 21、工作区内的
> `GRADLE_USER_HOME`、`ANDROID_PREFS_ROOT`、`local.properties` 里的 `sdk.dir`），
> 手敲 `gradlew` 每次都会踩一个。**详细原因和绕法都写在脚本顶部的注释里**。
> 用 Android Studio 打开时需要自己把 Gradle JDK 选成 21，并设置 `ANDROID_PREFS_ROOT`。

首次构建需要联网下载 Gradle 发行版与依赖（国内镜像已配好）。
`tools/download-gradle.mjs` 走 Node 下载而不是 curl —— 原因见
[docs/00-plan.md](docs/00-plan.md) 的"本机环境上踩过的坑"。

### 2. 装机

默认下载 GitHub 预发布/正式版的 `app-release.apk`，在手机上安装即可。后续本机预览也须沿用 `app.solochat` 和同一发布签名，以覆盖升级并保留资料；不要仅改包名后改用 debug 签名，也不要为此卸载旧包。统一规则见 `AGENTS.md` §4。

通过 USB 安装已下载的发布包时：

```powershell
adb install -r app-release.apk
```

### 3. 配置

打开 App → 右上角菜单 → **设置**：

| 填什么 | 说明 |
|---|---|
| Base URL | 例如 `https://api.deepseek.com`。不带 `https://` 会自动补；带不带 `/v1` 都行 |
| API Key | 加密保存（Android Keystore），界面上只显示掩码 |
| 模型 | 点「获取模型列表」自动拉，或直接手填模型名 |
| 单价 | 价格页可切换、新增、复制和编辑价格表；随包快照可能过时。仍支持全局自填兜底价，已配置的 0 表示免费，未配置表示未知 |

填完点「测试连通」——它会告诉你"连上了，延迟 320ms"或者"地址或模型名不对"。

**阿里云百炼 DashScope**：可点“填入 DashScope 地址”，或手动填写
`https://dashscope.aliyuncs.com/compatible-mode/v1`，再填写该地域的百炼 API Key 与已开通模型名（如 `qwen-plus`）。
快捷填写只修改地址草稿，不替换已填模型/Key，也不自动保存或调用接口。百炼连通测试走流式请求，兼容仅支持流式的模型；
正式聊天保留 `compatible-mode/v1` 前缀，读取思考内容与最后独立返回的用量帧。模型目录使用同域 `/api/v1/models` 原生接口与分页，
不使用聊天前缀下的 `/models`；目录返回不代表账号已获得每个模型的调用权限，仍可手填模型名。
配置及地域规则见 [阿里云兼容接口说明](https://www.alibabacloud.com/help/zh/model-studio/compatibility-of-openai-with-dashscope)。

测试连通只使用当前草稿；点本页「保存」才会写入这一组设置，离页时可选择保存、放弃或继续编辑。节奏页默认展示四个常用参数，其余在高级设置中。

然后回到会话列表，右下角 **+** 开一个对话（会让你先选一张人物卡）。

聊天右上角的齿轮打开会话设置，可修改对话名、删除对话、管理人物卡、选择本会话模型、压缩上下文和查看统计。模型默认继承全局，也可指定模型名称；共用全局接口与密钥，下一轮生效，不影响其他会话。回合结束后可修改；统计随时可看。删除需确认，清理本对话的聊天记录，保留人物卡、已保存记忆和历史用量；聊天顶栏不显示 token 和金额。

输入 `/compress` 或从会话设置进入压缩页，选择早期范围、输入预算与摘要目标字数，先预览，再明确生成。较新原文保留，聊天窗口中的记录全部原样。生成后可编辑草稿、查看前后上下文估算，点击“应用摘要”才改变下一轮；退出页面草稿仍保留。“恢复原文”重新读取完整历史，摘要版本也保留。重复压缩可选原文重新摘要、旧摘要加新增原文、保留多段摘要。摘要可能比原文更长；目标字数不是接口输出上限，生成会实际请求模型并记入压缩用量，预览与编辑不请求模型。

统计区分接口返回、本地估算、未知与旧版记录。当前上下文按实际提示词全文估算，查看或刷新不调用模型。新调用保存当时单价，后续改价格不会重算历史；缓存分布未知时可能显示费用范围。旧版记录没有价格快照，历史费用显示未知。这里的费用始终是估算，不是账单；失败、取消和静默也记录调用尝试。

## 两种模式

| | 发消息 | 面对面 |
|---|---|---|
| 什么时候 | 默认 | 模型读到"我到你楼下了"这类信号时提议，**你确认后**才切 |
| 显示 | 聊天气泡，一条一条蹦 | 对白 + 动作描写 + 环境旁白 |
| 你能输入 | 说话 | 说话，或写自己的动作 |
| 历史 | 同一个会话里一条线，切回来它还记得刚才见面聊过什么 | 同 |

模型提议的模式切换**需要你确认**，可在设置里关闭模式提议。不想要就直接发一条消息 ——
那会被当作拒绝，卡片不会挡住输入。

## 关于人设

出厂带**两张**人物卡：「小默」（话不多的熟人，也是**兜底那张** —— 没指定人设的会话都用它）
和「小鲸鱼」（DeepSeek 的网络形象，傲娇嘴硬心软）。

想改就去 **人物卡** 页。一张卡有**八段**，它们进提示词的不同段落，
而且**不是每段在两种模式下都出现**：

| 段落 | 决定什么 | 发消息 | 面对面 |
|---|---|---|---|
| **它是谁** | 身份、背景、性格、外形、你们的关系 | ✅ | ✅ |
| **怎么说话** | 打字时的口头禅、句子长短、标点习惯（**这一段最影响观感**） | ✅ | ✅ |
| **面对面时怎么说话** | 当面和打字的差别：更短、更碎、靠动作 | — | ✅ |
| **习惯与小动作** | 它常做的小动作、神态（**动作的素材库**） | ✅ | ✅ |
| **它身边的样子** | 住处、光线、声音、桌上的东西（**景物的素材库**） | — | ✅ |
| **怎么描写动作与景物** | 上面两样该**写成什么样**：偏听觉还是偏视觉、句子长短、用不用比喻 | — | ✅ |
| **关系与边界** | 称呼、亲密程度、不该做的事 | ✅ | ✅ |
| **只有它知道的事** | 里设定，提示词里明确要求不要直接说出来 | ✅ | ✅ |

后三段只在面对面注入，是因为它们是**面对面专用的**：在发消息模式里给模型一堆环境、
笔法和"当面怎么说"，它就会开始写小作文。反过来，面对面模式的表达手段只有 `act`（动作）
和 `scene`（环境）—— **没有素材，模型只能每轮自己发明一个动作**；
**没有笔法，它就会用同一种腔调描写所有人**。

三段的分工：`习惯与小动作` / `它身边的样子` 管**写什么**，`怎么描写动作与景物` 管**写成什么样**，
而全局的 `20-style-scene.txt` 管**不许写成什么样**（不写内心独白、不堆排比、不写成小说）。

**人设是每个对话各选一张的**：点右下角 **+** 时会先让你选人设；已有的对话用行菜单里的
**换人设**（从下一轮开始生效，之前聊过的内容不会重写）。会话列表和聊天标题栏都会标出
当前用的是谁 —— 显示成「小默（默认）」就说明这个对话没有指定人设（或指定那张已经被
删掉了），现在用的是兜底的出厂那张。

之所以不做一个全局人设：一段历史只对应一个人，提示词的稳定前缀才稳（前缀一变，
KV 缓存就全丢）；而且你可以同时开「小默」和「小鲸鱼」两段对话，各自记各自的事。

### 导入人物卡文件

手写八段很麻烦，所以有一整条路：**人物卡页 → 右上角菜单 → 格式说明与模板 → 复制模板
→ 粘给模型让它填 → 存成 `.json` 文件 → 人物卡页 → 导入文档…**

文件格式是 **JSON**（键名与字段一一对应；空字段也写出来，所以文件自己就是文档）。
导入前会先给一份预览：读到几张卡、每张有哪些字段有内容、哪些地方**没读懂**（它不会
悄悄丢内容）。导入一律**新建**卡、不覆盖已有的。反过来，卡片上的 **导出** 会把一张卡
复制成同一份 JSON，可以直接拿去改，也可以当**格式示例**贴给模型。

八段各自怎么写、文件里能写哪些键、以及**一段可以直接复制给模型的提示词**，都在
[docs/03-persona-format.md](docs/03-persona-format.md)。

## 它怎么记东西

模型会在回复的 JSON 里顺手加一条 `remember` 事件（**不出现在聊天里**），你把记忆页打开
就能看到它记住了什么、用过几次、来源是哪个会话，也可以自己手动加、固定、删掉。

同一人物卡的多个会话共享该卡记忆，通用记忆可用于所有人物卡。每轮只选取部分可用记忆，
优先固定和常用内容；本轮没选入不代表已删除。

涉及密码、证件号、银行卡这类内容，提示词里禁止它记，代码里还有一道正则兜底 ——
记忆会被反复注入上下文，写错一次的代价是不可逆的。

## 成本

用量页按 今日 / 本月 / 按模型 三个维度显示 token 与金额。两个必须知道的细节：

- **网关没返回 usage 时，token 是本地估的**，页面上会明确标出来，金额只代表数量级
- **模型名没匹配到所选价格表时走你明确配置的自填单价**，两者都没有则费用未知；已配置的零单价表示免费

初始表来自 QQ-agent 的 `src/model-prices.js` 快照，共 140 条，单位为元 / 百万 token，可能过时。
在“设置 → 资料 → 模型价格”可查看、搜索并编辑条目，也可新建空表、复制、重命名和删除价格表（至少保留一张）。
编辑模型后先“应用到本页草稿”，再保存价格页；取消或放弃草稿不更改持久化配置。

每个模型均可独立设置标准/谷价、峰价、缓存价、每日峰时起止与时区。**初始全部关闭峰谷计价**，
包括原快照中已有峰价的模型；新模型也默认关闭。开启时必须填写有效时段与峰价，含开始、不含结束，支持跨午夜。
不单设缓存价时按输入价算，单设的 0 表示缓存免费。价格表未匹配或关闭时使用原有全局自填价。
聊天与摘要调用各按开始时间选择峰谷价并保存快照；进行中的任务保留其价格配置，修改不会重算历史。
不自动联网刷新或把百炼目录中的分段报价直接套成统一单价。

## 排查：日志

出问题时**先看日志**，别猜。三个入口：会话列表右上角菜单 → 日志、设置 → 应用 → 排查与日志 → 文件日志、出错卡片的「看日志」。

日志记录每次请求的**完整提示词、模型原始输出、解析结果、播出时间线**，按 tag 与级别过滤，
长内容可展开、可复制全部。版本号显示在标题栏。

日志同时保留内存显示与应用私有目录中的轮转文件，文件总量最多约 8 MiB，可跨重启导出。
“清空”只清内存显示，不删除文件；关闭“记完整正文”只影响后续正文记录，不清除已有内容。

### 在电脑上看（日志网页）

手机上翻日志很麻烦，所以可以把日志开成一个网页：

设置 → 应用 → 排查与日志 → 日志网页 → **开启日志网页**并保存，然后把显示的地址复制到电脑浏览器。

| 模式 | 监听 | 需要密码 | 怎么访问 |
|---|---|---|---|
| 默认 | `127.0.0.1` | 否 | 手机自带浏览器打开；或电脑上 `adb forward tcp:8787 tcp:8787` 后访问 |
| 允许局域网 | `0.0.0.0` | **必须设** | 电脑浏览器打开 `http://<手机IP>:8787/?t=<密码>` |

> ⚠️ 日志里有你与对方的**完整对话内容**。所以默认只监听本机、默认关闭；
> 要开局域网就**必须**设访问密码，否则保存会被拒绝。用完就关掉。

也可以直接用命令行拉：

```powershell
curl "http://127.0.0.1:8787/api/logs?t=你的密码"
curl "http://127.0.0.1:8787/api/health"          # 探活
```

当前没有“常驻服务”的设置入口，息屏或进入后台后的连接持续性未获保证；使用日志网页时先保持 App 在前台。

### 与界面同步的调试接口

设置中启用日志网页后，可以直接向已有会话发送命令。接口与聊天页复用应用级 `SessionController`：手动模式仍需“发送→推送”，自动模式仍走防抖；插话、模式切换、播出和落盘也走同一条路径。手机可随时打开目标会话观察，返回首页或打开其他会话不会取消生成/播出。此保证限于进程存活期间，不承诺系统杀进程后自动续播。

本机可通过 `adb forward tcp:8787 tcp:8787` 访问；局域网访问沿用日志网页密码。开发测试只用独立 TEST- 人物及会话，示例不会创建、删除或清空资料：

```powershell
# 查询 id 可用原有 /api/conversations，也可从日志查看；必须明确目标。
pwsh tools/ui-command.ps1 -ConversationId <会话id>
pwsh tools/ui-command.ps1 -ConversationId <会话id> -Action send -Text "测试收到请回复收到" -RequestId test-send-1
pwsh tools/ui-command.ps1 -ConversationId <会话id> -Action push -RequestId test-push-1
# 直接改变会话模式，再发起一次模型开场；相同模式不会重复调用。
pwsh tools/ui-command.ps1 -ConversationId <会话id> -Action mode -Mode scene -RequestId test-mode-1
```

`GET /api/ui/state?id=…` 返回同一控制器的模式、阶段、历史、待推送数、正在播出的正文与错误。`POST /api/ui/command` JSON 字段为 `conversationId`、`requestId`、`action`，附 `text` 或 `mode`；`send` 还可用 `pieces: [{"kind":"say","text":"…"},{"kind":"act","text":"…"}]` 组合面对面输入。响应表示命令已交给控制器，完成情况需再读 state；不会阻塞等待模型和整场播出。同一进程最近 128 个 `(conversationId, requestId)` 重试不重复执行，改动内容须换编号；重启后不保留这份去重记录。导入副本仍须先在手机确认恢复发送。

聊天输入 `/scene`、`/chat`，或 `/system 进入面对面模式` / `/system 切换到聊天模式` 会直接切换并让对方开场。普通 `/system …` 仍只记录事实供下一轮读取，不立即调用模型。测试人物模板在 `tools/TEST-UI-persona.json`；先导入或填入独立人物卡，再选给测试会话，不应用于日常人物。

### 旧执行器测试接口

下述 `/api/send` 直接运行执行器，**不包含 UI 的代发、防抖与真实播出**，仅保留给协议/提示词排查；验证交互请优先使用上面的 `/api/ui/command`，不要把两条写入路径同时用于同一会话。



同一个端口上还有几个接口，可以直接发消息并看待回的**原始输出**。排查"为什么回这个"
时比截图快得多：

```powershell
# 发一条并等这一轮跑完（默认新建干净会话）
curl -X POST "http://127.0.0.1:8787/api/send" -d "在干嘛" `
     -H "Content-Type: text/plain; charset=utf-8"

# 接着上一个会话继续发（?id= 从上面返回的 conversationId 拿）
curl -X POST "http://127.0.0.1:8787/api/send?id=<会话id>" -d "假期要没了"

# 看历史（和界面同一套投影，所以能用来判断"是引擎顺序错还是界面渲染错"）
curl "http://127.0.0.1:8787/api/history?id=<会话id>&limit=30"

# 看**消息表**（装配上下文读的就是它，不是上面那个投影）
curl "http://127.0.0.1:8787/api/messages?id=<会话id>&limit=100"

# 列出会话
curl "http://127.0.0.1:8787/api/conversations"
```

`/api/send` 的返回里同时有：**模型原始输出**、解析出的事件（含顺序与 `gap_hint`）、
实际会发出的气泡、以及这一轮的 token 与成本。这样"输入 X → 输出 Y"在一个响应里就完整了。

> **`/api/history` 与 `/api/messages` 为什么都要有。**
> 前者是"界面上该看到什么"（事件 + 消息的投影），后者是"模型能看到什么"（消息表）。
> 两者会分叉，而且分叉时**前者看起来完全正常** —— 曾经有一个 bug 就是这样：
> 助手说的话在时间轴上一条不少，但消息表里根本没有它们，于是模型看不到自己说过什么，
> 会把自己上一轮答过的内容重新答一遍（用户原话："它又重新回答了一遍我在睡觉"）。
> 排查这类问题只能看 `/api/messages`，以及日志里那行 `历史构成: 对方 N 条 / 我 M 条`
> —— **`我` 是 0 就说明模型这一轮看不到自己的任何发言。**

> 这些接口返回的是对话内容，所以和 `/api/logs` **共用同一道密码**。
> 只监听本机时不需要密码。

### 在真机上抓"某一瞬间屏幕上有什么"

有一类问题**只在几帧里存在**，事后看数据完全正常。例如"气泡是逐条累积还是逐条覆盖"
—— 差别只在两条消息之间那几秒。

这台机器上拍屏幕这件事是**受限**的，两条路都堵：

- `screenrecord` 写不进 `/sdcard` 也写不进 `/data/local/tmp`（SELinux 不让 shell 域写），
  `adb exec-out screenrecord --output-format=h264 -` 流式输出同样拿不到数据；
- `uiautomator dump` 一次要 0.5~2.5 秒，只能看到秒级的粗粒度。

所以退一步：**抓状态，而不是抓像素**。状态是同步写的，比抓屏幕准得多。

> **日志服务开着的时候**（= 在调试状态），**点一下聊天页的标题栏**，
> 就会往日志里打一份"此刻屏幕上有什么"：`items`（已成历史）/ `live`（正在播）/
> `pending`（还没交给模型）各是哪些。判据很直接 ——
> **正在播第 2 条时，`items` 里应当已经有第 1 条**；如果 `items` 是空的、只有 `live`，
> 那就是"逐条覆盖"。

`tools/send-message.ps1` 与 `tools/snapshot-at-playback.ps1` 是配套的脚本。

## 工程结构

```
SoloChat/
  core/                纯 Kotlin JVM 模块，不含任何 Android API
    model/  protocol/  agent/  llm/  playback/  prompt/  persona/  ports/
  app/                 Android 模块
    data/              Room、加密 Key、价格解析、提示词与人设文档加载
    play/              SessionController（防抖/抢占/播放）、ChatProjector
    ui/                Compose 界面
    service/           前台服务（常驻 + 主动消息检查）
    src/main/assets/
      prompts/         提示词分段（改语气不用重新编译代码结构）
      data/            从 QQ-agent 转出的数据资源
  tools/               构建与引导脚本
  docs/                方案、设计决定、变更记录、人物卡文件格式
```

**`core` 刻意不依赖 Android API**，这样协议解析、节奏、防抖、播放状态机都能用普通
JUnit 秒级验证，不需要模拟器。它也是"以后想把核心搬到电脑端"的物理前提。

## 本地备份

设置 → 资料 → 本地备份 → 整理备份，可查看数量与整理时间，再选择位置保存 ZIP。包含归档在内的全部会话与消息、事件、人物卡、记忆、摘要版本及用量；不含 API Key、接口设置、价格表等偏好、日志和头像图片内容。文件未加密，请自行保管。整理后的新消息需重新整理才能包含。

恢复：同页点击“从备份文件恢复”，选择 ZIP，核对来源时间、数量、重复导入和通用记忆提示，再确认导入。会话、人物卡等创建独立副本，不覆盖现有资料；失效摘要保留但停用。导入会话先暂停发送，可只读查看，确认接口与模型配置后在会话中点击“恢复发送”。自动模式下确认会推送旧代发，手动模式仍须按推送。导入历史账目与本机新消费单独显示。

调试包 `app.solochat.debug` 和发布包 `app.solochat` 的资料独立。迁移时保留旧包：先用旧包导出文件，再在发布包恢复；接口、Key、价格表等设置须在发布包重新配置，两边不会自动同步。备份包含通用记忆时，恢复后所有人物都可使用这些通用记忆。

GitHub 版本检查与更新下载已纳入后续计划，尚无在线更新入口。恢复页面与迁移后的完整操作暂未在实机上验证，用户可通过预发布 APK 确认。

## 测试

测试按改动范围选择，以下步骤不要求每次全部执行。`core` 与 `app` 的自动测试均为纯 JVM JUnit，不需要模拟器；它们不能代替真实界面、文件选择或模型行为检查。

| 改动 | 必要检查 |
|---|---|
| 文档、普通文案 | 直接核对内容，不默认构建或测试 |
| 解析、计价、状态流转等逻辑 | 运行相关测试类；修 bug 优先用可复现用例确认修复 |
| Android 代码或界面 | 需要交付 APK 时构建；键盘、滚动、节奏等交互有变化时，真机走一次相关路径 |
| 共享流程改造、跨模块变更 | 根据影响扩大到相关套件；影响难以限定时才全量测试 |
| 修改已有数据的迁移、修复、清理 | 增加原记录保护核对，见 [交接文档 §5](docs/02-handoff.md#5-真机取证这台机器上能做什么不能做什么) |

常用命令（按需选一项）：

```powershell
# 定向测试：把类名换成本次涉及的测试类
pwsh tools/build.ps1 :core:test --tests '*PriceCatalogTest'
pwsh tools/build.ps1 :app:testDebugUnitTest --tests '*PricingRulesTest'

# 需要更广回归时运行两模块的全部 debug JVM 单测
pwsh tools/build.ps1 :core:test :app:testDebugUnitTest

# 需要装机时才出包；构建本身不执行单测
pwsh tools/build.ps1 :app:assembleDebug
```

真机优先正常字体和本次修改路径；改到主题颜色时检查明暗模式，不默认遍历所有页面或大字体。对话测试使用新建的专用会话及独立人物卡，不操作日常会话；用户已检查的项目不重复检查，除非之后的修改影响了该结果。

发布 Release（含预发布）时，GitHub 工作流执行一次 `:core:test :app:testReleaseUnitTest :app:assembleRelease`；普通推送和 PR 不触发构建。测试报告仅在失败时上传，APK 附到对应 Release。

通过后不再追加同类验证；不默认 `clean`、`--rerun-tasks`、重复装机、请求真实模型或收集快照。只有排查缓存问题或明确需要重新执行时才强制重跑。记录本次检查范围、结果及未确认项即可，不维护日常测试总数，也不累计残留 XML；旧结果见 [变更记录](docs/04-changes.md)。

## 已知限制

- **手动上下文压缩已实现**，支持 chat/scene；百轮长会话与连续长场景的压缩质量尚未验证。
- **联网搜索还没做**。现在模型遇到不知道的事会说不知道，不会去查。
- **局域网网页版还没做**（依赖已在版本目录里预留）。
- **主动消息只做了判断**：前台服务会检测"多久没动静"，但只改通知文案，不会自动发消息。
- 只在 Android 上可用（Kotlin + Compose，没有 iOS 目标）。
- **这台开发机上拍不了屏幕**：`screenrecord` 被 SELinux 挡住（`/sdcard` 与
  `/data/local/tmp` 都写不进去），所以"肉眼验证动画"这件事只能由人在手机上做。
  代码侧靠"状态快照 + 纯函数测试"替代，见上面「在真机上抓某一瞬间屏幕上有什么」。
